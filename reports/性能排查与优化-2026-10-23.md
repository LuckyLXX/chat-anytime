# 性能深度排查与优化报告（2026-10-23）

## 1. 结论摘要

本次排查针对真实会话库（684 个 JSONL、约 1.14 GB，p50 0.60 MB、p90 3.4 MB、p99 26.3 MB、最大 45.8 MB）做静态热路径分析 + Node 微基准，定位并修复了 4 个 P0/P1 级问题：

1. **流式期间每 50 ms 通过 IPC 重传整段消息历史与全部工具执行**，并经过 utility→main→renderer 两次结构化克隆。13.56 MB 的会话实测单次克隆 14.1 ms（20 fps 即 283 ms CPU/s、271 MB/s），是长会话卡顿/掉帧的首要根因。
2. **`App` 因 `snapshot.model` 每帧新建对象而以 20 fps 整棵重建**（侧栏、顶栏、预览壳、会话行）。这一条在原有“细粒度订阅”优化中被漏掉。
3. **`getContextUsage()` 每帧重建整条 session projection**：3,037 条 entry 实测 2.0 ms/次，20 fps 下仅这一项就吃掉约 4% 的一个核。
4. **冷会话打开同步解析 JSONL**：45.8 MB 会话 `SessionManager.open` 实测 273–278 ms，且超出 4 个 parked 会话后每次切回都要重读；用户点击后没有任何即时反馈。

已完成优化（含代码）与验证见第 3、4 节。

## 2. 关键证据

### 2.1 流式快照体积

以真实会话 `2026-10-13T01-51-48-009Z_01a132f5…jsonl`（22.1 MB 文件、110 条可见消息）为例，`RuntimeSnapshot.messages` 载荷 **13.56 MB**（13.3 MB 为用户上传图片的 base64）。Node 22 实测：

| 载荷 | `structuredClone` 单次 | 20 fps 等效 CPU | 20 fps 等效带宽 |
|---|---:|---:|---:|
| 13.56 MB / 110 条 | 14.1 ms | 283 ms/s | 271 MB/s |
| 3.65 MB / 1,489 条 | 18.1 ms | 361 ms/s | 73 MB/s |
| 0.94 MB / 212 条 | 3.3 ms | 65 ms/s | 19 MB/s |

链路实际是 utility → main → renderer 两次跨进程序列化，renderer 还要再反序列化一次；上表只算一次克隆，因此真实成本更高。

### 2.2 冷会话打开

| 会话文件 | 大小 | `SessionManager.open`（仅解析） |
|---|---:|---:|
| 2026-08-16… | 45.8 MB / 224 entries | 273–278 ms |
| 2026-10-17… | 36 MB / 429 entries | 213–228 ms |
| 2026-09-15… | 34 MB / 3,037 entries | 265–280 ms |

这还**不包含** `createSession()` 里 ResourceLoader、MCP 注册、todo/memory/团队运行时等装配成本。原 `MAX_PARKED_SESSIONS = 4`，第 5 个最近会话切回就要重走整条冷路径。

### 2.3 热路径中的隐藏扫描

- `AgentSession.getContextUsage()` 内部每次 `buildSessionProjection()` + `getBranch()`；3,037 entries 实测 **2.0 ms/次**，原来在每 50 ms 的 `snapshot()` 中调用。
- `normalizeMessages()` 原来每帧对全部消息做 `filter + map`；`paneSnapshotFrom()` 原来每帧 `[...messages].sort()`（即使没有控制消息）。
- `TurnMinimap` 原来每帧随整格重渲染，turns 数组每帧重建；长会话中数百个缩略块跟着重建。
- `snapshot.model` 每帧新建对象，导致 App 的 `state.snapshot.model` 选择器每帧换引用 → App 整树 20 fps 重渲染。

### 2.4 首屏包体

优化前 renderer 主 chunk 约 **6.0 MB**；其中包含 Vditor（797 KB）、highlight.js 全量 192 种语法、html2canvas（434 KB）、xterm（427 KB）等只在特定场景使用的模块，以及桌面端永远不会执行的 demo mock 数据。

## 3. 已实施的优化

### P0：流式快照改为增量补丁

- 新增 `src/shared/snapshot-patch.ts`：消息补丁（append / replaceFrom / truncateTo / reset）、执行补丁（upsert / remove / reset）、快照合并、差量计算，含 11 个单测。
- `src/main/pi-runtime.ts`：
  - `state` / `session.state` 仅在首帧、会话切换、`state.sync` 时发全量；其余帧发 `state.patch` / `session.state.patch`。
  - 补丁只携带变化的消息尾部（通常就是正在流式增长的最后一条）、变化的执行记录、变化的标量字段；`sessions`/`recentWorkspaces`/`backgroundProcesses` 仅在内容变化时附带。
  - 每帧分配单调递增 `revision`；无实际变化的帧不占用 revision，避免 renderer 误判断档。
  - 新增 `state.sync` 命令：renderer 丢帧/重载时请求一次全量、重置补丁基线。
- `src/renderer/src/store.ts`：应用补丁、按 revision 去重/检测断档；断档时自动请求 `state.sync`。
- `src/main/index.ts`：main 的 `latestSnapshot` 同步合并补丁（bootstrap 不再退回到旧全量帧），重复补丁按 revision 丢弃。
- `src/main/panel-state.ts`：面板状态缓存识别 `state.patch` 的 `sessions`/`sessionId`。

**效果（同一 13.56 MB 会话、60 个流式帧模拟）**：全量 13.56 MB/帧 → 平均 **6.1 KB/帧**，约 **2,200 倍** 下降；1,489 条消息的会话同样为 6.1 KB/帧，差量计算约 **0.11 ms/帧**。

### P0/P1：其它热路径

- `message-normalize.ts`：新增 committed visible 序列缓存（数组引用 + 长度 + 首尾元素校验），无流式变化时复用整段 normalized 数组；流式只重算最后一条。
- `paneSnapshotFrom`：没有 control 消息时不再 `copy + sort`。
- `getContextUsage()` 结果缓存在 `record.contextUsageCache`，只在 message_end / compaction / agent_end / 切模型等稳定边界重算。
- `App.tsx`：折叠工作区默认不挂载会话行（几百条历史会话不再进 DOM）；展开过的分组保留挂载以维持折叠动画。
- `ConversationPane.tsx`：图片 data URL 按 block/attachment 对象身份 WeakMap 缓存（输入框每敲一个字不再复制数 MB 字符串）；消息高度估算按 ChatMessage 缓存；缩略导航 turns 在流式期间节流到 500 ms。
- `TurnMinimap.tsx`：`memo` 化。
- `ArtifactPreview.tsx` / `MemoryPreview.tsx`：Vditor MarkdownEditor、Xterm TerminalPanel、BrowserPreview、SshPanel、DiffView 全部改为 `React.lazy`。
- `RichContent.tsx`：highlight.js 从全量 192 种语法改为 `lib/common`（37 种常用语言）+ 单独注册 PowerShell。
- `share-image.ts`：html2canvas 改为点击分享时动态 import。
- `main.tsx`：demo-api 改为仅浏览器演示模式动态 import。

### P1：会话切换反馈与内存治理

- 冷会话解析前新增 `session.opening` 推送；侧栏目标行立即显示 spinner（15 s 兜底，失败/错误帧清除）。
- parked 会话从固定 4 个改为 **最多 6 个 + 96 MB 历史字节上限**：小会话保留更多以便即时切换，大会话（图片/工具输出多）按体积淘汰，避免 utility 进程无界保留 base64。
- `disposeRecord` 清理 `lastActiveEmit` / `lastPaneEmit` 基线，避免关闭会话后整段消息数组仍被 GC 根持有。
- 子代理 transcript 缓存上限 16 份；错误缓存上限 32 份。
- 关闭预览 tab 时清理 `previewEditorStates` 与 AI 同步执行标记。

## 5. 后续项评估与已开始实施（2026-10-23 追加）

### 5.1 冷会话打开：已实现「最近销毁 manager」复用（已落地）

新增 `src/main/session-manager-cache.ts`：

- `disposeRecord` 时把 `SessionManager` 留在**有界缓存**（最多 2 个 / 96 MB，按文件字节淘汰）；
- 下次 `session.open` / 自动化打开同一路径时，先校验 **agent + workspace + 文件 mtime + size** 全部一致，命中即复用 manager，完全跳过 JSONL 解析；
- 文件被外部修改、删除、换 agent/工作区时缓存自动失效，退回原 `SessionManager.open` 路径；
- 新增 `session-manager-cache.test.ts`（3 个单测）。

这直接覆盖「超出 6 个 parked 会话后切回大会话」的最常见路径。首次打开超大文件仍是 200–300 ms 级，下一步可再做 hover 预取或 worker 解析。

### 5.2 图片体积：已实现超大附件入库降采样（已落地）

- `preparePromptPayload` 对 **base64 长度 ≥ 8 MB** 的图片附件，入库前用现有 `createImageDownsampler` 压到 ≤1.5 MB / 1600 px；
- 普通截图（<8 MB）不做额外等待，避免发送时多等一轮压缩；
- 工具结果图片（`read` 生成的 45 MB base64）仍保留原图，需要后续单独做工具层策略。

### 5.3 壁纸模式 blur：已实现流式期间自动降级（已落地）

`styles.css` 增加：

- `html[data-theme-wallpaper="true"][data-ui-generating] .composer` 关闭 `backdrop-filter`；
- 生成结束后自动恢复，避免消息从 composer 下方滚过时每帧重新模糊。

### 5.4 窗口隐藏：已实现动画/模糊暂停（已落地）

- 主进程推送 `app:window-state`（focus/blur/show/hide/minimize/restore）；
- renderer 在 `html[data-ui-window-hidden]` 时暂停 running dot、spinner、流式光标、SSH 进度动画，并关闭壁纸面板 blur；
- 这是对 `CalculateNativeWinOcclusion` 被禁用（自动化截图需要）的一层实际缓解；被其他应用遮挡但仍 visible 的情况仍需后续评估。

### 5.5 性能观测：已实现 dev longtask 采样（已落地）

新增 `src/renderer/src/lib/perf-telemetry.ts`：开发构建用 `PerformanceObserver` 采样 >80ms 的 `longtask`，只打印警告，不常驻上报；生产构建不加载。

## 6. 仍建议继续评估

1. **首次打开超大历史会话**：继续做 hover 预取 / worker 解析（本次已解决「切回」路径，首次路径仍 200–300 ms）。
2. **工具结果图片**：`read` 等工具生成的 base64 仍会进 JSONL（单会话可达 45 MB）。建议做工具层图片降采样或工作区文件 + URL 引用；这是剩余最大的内存/IO 来源。
3. **被遮挡窗口**：`CalculateNativeWinOcclusion` 仍全局禁用；若挂机 CPU 高，可评估按浏览器自动化活跃状态动态开关（需重启/独立进程）。
4. **性能观测**：后续可在 dev 面板汇总 `state.patch` 字节数、`diffChatMessages` 耗时与 longtask 统计，形成回归基线。
