# 森野假日 Forest Holiday

两张等距视角插画壁纸组成的 PiDesktop 明暗双模式主题。

| 模式 | 壁纸 | 画面 | 取色方向 |
| --- | --- | --- | --- |
| 亮色 | `wallpaper-light.webp` | 夏日西瓜池：池水蓝、叶绿、西瓜红，白熊泡在水里 | 薄荷瓷白玻璃面 + 西瓜红强调色 + 深松绿代码面 |
| 暗色 | `wallpaper-dark.webp` | 夜森营地：松林夜色、溪流、帐篷与篝火 | 深松绿面板 + 篝火暖橙强调色 + 底部营火柔光 |

## 导入

设置 → 外观 →「导入主题目录」，选择本目录（`theme.css` 与两张壁纸在同一层）。
导入后设置里的「气泡透明度 / 面板透明度 / 壁纸透明度」三个滑块照常可用。

## 设计说明

- **全量调色板**：明暗两套各 84 个语义 token，无 `color-mix()`、无内嵌 base64，图片保持相对路径，随目录可移植。
- **按面玻璃**：五个公开面（`--panel-bg-sidebar` / `-topbar` / `-composer` / `-dialog` / `-preview`）分别给底色，
  侧栏 84%、顶栏 80%、输入卡 90%、对话框 96%、预览 94%（亮色；暗色见 CSS），插画透出但压得住文字。
- **气泡透明度默认值**：亮 90% / 暗 88%。插画细节密，80% 时插画明亮处的浅灰元信息会掉到约 4.2:1；
  这里只在 token 层给默认值，用户拖动【外观 → 气泡透明度】滑块后由滑块值接管。

### 结构装饰（全部走契约钩子）

- 输入卡圆润瓷面（16px 圆角 + `--accent-border` 发丝边 + 柔和投影）；
- `send` / `stop` 成对改成胶囊按钮（渐变填充、hover 上浮、`:active` 下沉、`:disabled` 变暗、`:focus-visible` 保留焦点环）；
- 壁纸态下侧栏右缘 / 顶栏下缘补一条发丝分隔线；
- 侧栏行圆角对齐 `--ui-control-radius`，选中行加一圈 `--accent-border` 描边；
- 分屏时失焦格的输入卡收敛成素卡（`[data-ui-split-open] [data-pane="conversation"]:not([data-pane-active])`）。

### 场景感（A 批：纯 CSS、零新素材）

| # | 效果 | 实现 | 位置 |
| --- | --- | --- | --- |
| A1 | 暗色营火会呼吸 | `--pi-overlay-firelight`（大范围暖光，22%，6.8s 明暗 + 微缩放）+ `--pi-overlay-emberlight`（余烬核 34%，3.4s 不规则闪烁）；`--pi-overlay-vignette` 四角暗角保持静态。 | 壁纸之上、菜单之下 |
| A2 | 亮色池面会反光 | `--pi-layer-poolshine`（两道光带 24% / 14%）+ `--pi-layer-poolshine-far`（16%），层比视口宽 16%，15s / 23s 不同方向往返交叉漂流 | 壁纸之上、界面之下 |
| A3 | 气泡长出小角 | 用户气泡收右下角（`14px 14px 4px 14px`）+ 一条"西瓜皮 / 余烬"下缘（`--fh-rind`，分模式）；助手气泡收左上角 | 消息气泡 |
| A4 | 状态有戏 | 生成中：一道溪水光斑沿输入卡底缘滑过（`::after` + 3.4s）+ 停止按钮呼吸环；待用户决策：顶栏底缘琥珀脉搏，提问面板给一圈 accent 光环 | 输入卡 / 顶栏 / 提问面板 |

#### 振幅是实测校准过的（重要）

初版 A1/A2 的振幅小到等于没有：实测（把层渐变按真实参数合成到真壁纸上，量底部 28% 条带的逐像素差）

| 版本 | 呼吸一次在底部条带的 ΔRGB |
| --- | --- |
| 初版 A1（14% × opacity .78→1.0，无余烬层） | 均值 **1.54** / p99 6.2 / 峰值 7.1 —— 看不见 |
| 校准后 A1（22% × .42→1.0 + 余烬 34% × .35→1.0） | 均值 **7.67** / p99 49.5 / 峰值 66.6 —— 一眼可见 |

经验值：**整屏层层上的环境动效，alpha 摆动低于 5 个百分点（ΔRGB 均值 < 3）等于不存在**；
要「看得见但仍是氛围」，目标定在 ΔRGB 均值 6–10 / 峰值 40–70。
对照图：`../forest-holiday-amplitude-check.png`（四格：无装饰层对照 / 反光两相位 / 营火最亮，同屏同尺度）。

两条实现约定：

1. **气泡选择器带 `[data-theme-wallpaper="true"]`**。应用壁纸态的气泡规则是
   `[data-theme-wallpaper="true"] .message-user .message-body`（(0,3,0)）且用了 `background` 简写，
   主题若只用 `[data-role="user"] .message-body`（(0,2,0)），`background-image` 会被清掉。
2. **`.message-body` 不是定位元素**，A3 因此只改 `border-radius` 与 `background-image`（下缘渐变），
   不挂伪元素、不改 `position`，避免改变气泡内绝对定位子项的包含块。

### 动效清单与克制原则

全部动画包在 `@media (prefers-reduced-motion: no-preference)` 内，并额外认应用自己的开关
`html[data-ui-motion="off"]`（应用的「界面动效」开关只对一份**类名白名单**停动画，
主题新增的层/控件动画不在名单里，必须自己认）：两者任一成立即全部静止。

| 触发条件 | 动画 | 代价 |
| --- | --- | --- |
| 暗色常驻 | `fh-firelight` 6.8s + `fh-emberlight` 3.4s：opacity + transform（整屏层） | 合成层，便宜 |
| 亮色常驻 | `fh-poolshine` 15s / 23s：transform 位移（两个整屏层） | 合成层，便宜 |
| `data-ui-generating` 且焦点格 | `fh-stream`：2px 伪元素 `background-position`；`fh-stop-pulse`：停止按钮 box-shadow | 小区域重绘 |
| `data-ui-permission-pending` | `fh-alert`：顶栏底缘颜色脉搏 | 全宽 1px 边框重绘，状态短暂 |

生成中不再叠加“输入卡呼吸光晕”（旧版有），改为稳定暖光 + 一处流动信号，避免整屏同时“抖”。

- **界面微调**：默认把 `--ui-container-radius` 设为 12px、`--ui-control-radius` 设为 8px；
  用户在【外观 → 界面微调】选档位时，应用的运行时覆盖层优先级更高，会正常接管。

## 核验

创作期在独立预览台（模拟外壳 + 真实 `theme.css`，切模式改 `<html data-theme-effective>`）里逐项核对；
明暗 / 生成态截图与振幅对照图留在创作工作区，未随本目录分发。

已核验的取用事实（`getComputedStyle` 实测）：A1/A2 层各自只在对应模式启动动画、互不串台；
A3 用户气泡 `14px / 4px` + 分模式下缘色生效；A4 生成态下 `::after` 动画为 `fh-stream`、
停止按钮为 `fh-stop-pulse`、顶栏为 `fh-alert`；`data-ui-motion="off"` 时上述全部归零，
且溪水光斑 `display: none`。

> 踩坑记录：`data-ui-generating` / `data-ui-permission-pending` 挂在 `<html>` **自己**身上，
> 不能写成后代（`html[...] [data-ui-generating] …` 永不匹配）；`[data-ui-generating] …` 只有在
> 不带 `html` 前缀时才靠 html 自身命中。

`pidesktop-theme-creator/scripts/check_theme.py`：每种模式 84 个变量，覆盖度 / 对比度 / 钩子名 / 可移植性全部通过。

对比度补充核验（检查器清单外、但应用里确实当正文用的组合）：

| 组合 | 亮色 | 暗色 |
| --- | --- | --- |
| `--success` on `--success-soft` | 5.03 | 6.94 |
| `--warning` on `--warning-soft` | 5.20 | 8.13 |
| `--danger` on `--danger-soft` | 5.31 | 6.81 |
| `--text-muted` on `--surface-muted` | 5.35 | 6.5 |
| `--text-sidebar-active` on `--surface-sidebar-active` | 5.65 | 9.41 |

（亮色的 `--success` / `--warning` 在 soft 底色上原本只有 3.7:1，已压深到 5:1 以上。）

## 壁纸与清晰度

原图 1665×945 / 1663×946（PNG，2.0–2.2 MB）。应用用 `background-size: cover` 铺满窗口，
在 1920×1040 的窗口下需要 **1.153× 放大**——这一步由浏览器的双线性插值完成，
是“看起来比原图糊”的主因（边缘能量只剩原图的 75%）。

因此发货资产改成：**1.5× LANCZOS 预放大 + 轻度 USM（radius 1.1 / 55% / 阈值 2）→ 无损 WebP**
（2498×1418 / 2494×1419，3.47 MB / 2.97 MB，主题合计 6.47 MB）。
这样一来浏览器做的是 **缩图** 而不是拉图，上屏后的边缘能量从 6.06 / 7.19 提到 **7.67 / 8.94**
（理想 LANCZOS 上屏为 8.09 / 9.12）。1.5× 也是往大屏留的余量：视口宽 ≤2498 px 时都不会再放大。

> 诚实说明：预放大里的“细节”是插值出来的，不是真细节。真正的清晰度只能靠更高分辨率的原图；
> 这一手只是把“浏览器的一次差重采样”换成“一次好重采样 + 轻度锐化”。

### 看起来模糊的三层原因（实测）

| 层 | 实测 | 处理 |
| --- | --- | --- |
| ① 上屏放大 1.153×（浏览器双线性） | 边缘能量降到 **74.9% / 78.8%** | 已用 1.5× 预锐化资产抵消大部分（→ 94.8% / 98.0%） |
| ② 资产转码 | q92 WebP 边缘能量 91.7% / 96.4% | 已改 **无损**（100%） |
| ③ 装饰层的灰雾（抬黑场=降通透度） | 营火 22% 时底部抬 +23；宽泛光覆盖 29% 屏幕 | 已改：暖光 16% 且纵幅 62%→46%；反光从“宽而淡”（24%×16% 宽、覆盖 29%）改成“**窄而亮**”（40%×5% 宽、覆盖 9.5%） |

副产物：亮色反光改动后，全屏平均抬升 3.87 → **1.96**（更通透），亮处 P95 抬升 43 → **70**（更像反光），
暗色营火呼吸峰值仍有 ΔRGB 57（肉眼依旧明显），抬黑场代价 +23 → **+16**。

另外：面板下的毛玻璃虚化（`backdrop-filter: blur(16px)`）是应用的壁纸态设计，不属于“壁纸变糊”；
它只影响面板覆盖的区域。
