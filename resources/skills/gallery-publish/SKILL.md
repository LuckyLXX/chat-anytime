# 作品发布：形态选择与跨域边界

> 本目录随应用分发（安装目录 `resources/skills/gallery-publish/`），是**内置资产**：所有工作区可见，随应用升级。

发布前最重要的决策是作品的**运行环境**——它决定跨域待遇、生命周期与可用能力。选错形态的典型代价：为不需要代理的作品写了一整个本地代理（真实发生过：一个调外部生图 API 的单文件作品，因为在内置浏览器里实测被 CORS 拦而自建了代理；其实发成 panel 就能直连）。

## 一、三种形态（file / server / panel）

| kind | 运行在哪 | 适合 | 生命周期 |
| --- | --- | --- | --- |
| `file` | 主界面内置浏览器 | 单文件网页（原型、导出物），可离线、可拷给别人 | 随主界面 |
| `server` | 内置浏览器（需先起服务） | 完整项目（dev server / 本地服务） | 随主界面 |
| `panel` | **独立小窗口** | 常驻小工具、监控面板；主界面关了它还在 | 独立存活 |

`kind=panel` 有三种窗口形态（`panel.mode`，缺省 `"window"`）：

| mode | 窗口 | 页面要做的 | 典型作品 |
| --- | --- | --- | --- |
| `window` | 系统边框，可缩放 | 普通网页 | 监控面板、常驻小工具 |
| `pet` | 透明无边框，尺寸可在运行期调大调小（缺省置顶） | `body` 背景透明自绘形状；拖窗口用一块 `-webkit-app-region: drag` 的底层（**拖动区收不到鼠标事件**，所以点击 / 右键菜单必须放在 no-drag 元素上）；自带关闭钮 POST `{"action":"close"}`；大小 POST `{"action":"grow"}` / `"shrink"` / `"reset-size"`，再监听 `resize` 重排精灵缩放 | 桌宠、桌面挂件 |
| `drawer` | 贴屏幕边缘（`panel.edge`：left/right/top/bottom，缺省 right），窄把手 ↔ 完整面板两态切换，不可拖不可缩放 | 监听 `resize` 按窗口尺寸渲染两态（窄时把手、宽时面板）；点把手 POST `{"action":"toggle"}`；自带关闭钮 POST `{"action":"close"}`；透明背景 + 圆角由页面自己画 | 快速启动器、贴边监控条 |

三种形态的数据接口与跨域待遇完全一致（同一静态服务 + 端点）；`width`/`height`/`alwaysOnTop` 通用（桌宠缺省置顶，其余缺省不置顶）。桌宠的尺寸在运行期可由页面调（`grow`/`shrink`/`reset-size`）：Windows 透明窗口不能由用户拖边框缩放，所以改尺寸要走这条动作——主进程按**底部中心锚点** `setBounds`（猫变大不会浮起来）并把结果写进位置尺寸记忆，下一次「运行」还是调好的大小。

## 二、跨域边界（最容易踩的坑）

平台只在**面板窗口（panel）**里放宽跨域：主进程替响应补上整套 `Access-Control-Allow-*`（反映来源），预检 OPTIONS 被服务端拒掉（405 等）也会改写成 200。

- **panel**：可以直接 `fetch` 任何 http(s) API，**包括一个 CORS 头都不发的服务**——很多自建 / 中转的模型推理接口与图床（如 GCS 图片链接）都属此类。**不要为面板作品写本地代理。**
- **内置浏览器**（`file` / `server` 的运行地，也是 `browser_*` 工具的验证地）：「正常浏览器」语义，服务端不发 CORS 头就 `Failed to fetch`。这是刻意的安全设计（在预览里放宽等于让任意网站的脚本读跨域数据），不是 bug。
- panel 也救不了两种情况：服务端对预检直接重置连接（拿不到任何响应头，无从改写）；面板页里由 service worker 发起的请求。

**形态选择规则（按序判断）：**

1. 作品要直连无 CORS 的外部 API → **首选 panel**（零代理直连）。
2. 服务端自带 CORS 头（xjbh.lol、rolldek.com、GitHub API 等多数开放接口）→ 任意形态皆可。
3. 必须是 `file`（单文件离线分发）且要调无 CORS 接口 → 才写本地代理：只监听 `127.0.0.1`、代理统一补 `Access-Control-Allow-Origin: *`、模型返回的图片链接一并透传（形如 `/__proxy?url=<encoded>`，避免上游链接过期后裂图）。

## 三、验证口径（别被自己的测试环境骗了）

在**内置浏览器**里实测外部接口被 CORS 拦，**不等于**作品运行时被拦：`file` / `server` 形态真的会被拦，`panel` 形态不会。因此：

- 用 `browser_*` 验证页面逻辑时，跨域失败只说明「该接口服务端无 CORS 头」——先确认作品形态，再决定是「改发 panel」还是「确实需要代理」，不要直接断定必须写代理。
- 验证 panel 的跨域能力：发布成 panel 并打开面板窗口，在面板里看请求的实际结果（可请用户点开面板确认）。内置浏览器里的结果是另一个环境的，不能当定论。

## 四、panel 开发要点

面板的数据接口（相对自己 `fetch("./__pidesktop_state.json")` 读会话状态、POST 唤回主界面 / 关窗 / 抽屉切换，`panel {width,height,alwaysOnTop,mode,edge}` 声明窗口）在作品墙「继续开发」按钮的注入文本里有完整契约，**以它为准**，此处不重复。写 pet / drawer 之前先看同仓库 `examples/panel-pet/`、`examples/panel-drawer/` 两个零依赖示例。

**面板的持久化直接存 `localStorage` / `IndexedDB`，不要自建保险库（2026-10-10 起）**：面板页跑在由作品 id 决定的固定 origin（`pidesktop-file://w-<作品>`，没有端口）上，所以这两种存储跨启动保留、按作品隔离。之前流传的「隐藏 iframe 走自定义协议做保险库 / 自己起本地服务存盘 / 把数据塞 sessionStorage 兜底」都是旧「随机端口 origin 每次换锁」时代的弥补手段——现在只会多一层会坏的中间层（而且保险库那条路本来就跑不通：平台协议 `pidesktop-file://preview` 只服务 PDF 与图片，HTML 会 415）。用户可在作品墙卡片的「数据…」看用量并清空。注意：**在内置浏览器里预览同一个面板是另一个 origin**（http + 随机端口）——那里的存储是开发用的另一份，别把「面板里没数据」当成 bug 的证据；要验持久化就把面板真正跑起来（可请用户关闭再重开一次）。

## 五、封面（每个作品都要有）

**2026-10-28 起，作品墙的每张卡片都必须有封面**；发布时平台按下面的顺序取图，第一个成功的胜出：

1. **显式 `cover`**：`gallery_publish` 的 `cover`（或人工对话框的「封面图片」）指定工作区内的一张图片（png / jpg / jpeg / webp / gif / svg，≤8 MB）。
2. **入口本身就是图片**：`kind=file` 的入口是 png / jpg / webp 时直接用它。
3. **自动截图**：
   - `file` / `panel`：离屏加载入口网页截图（不需要真的打开窗口）；
   - `server`：只有登记的服务地址**此刻可达**才截服务页（平台不会为截图自动起服务——所以调试完、服务还跑着时发布，封面效果最好）。
4. **占位封面**：以上都不行时，平台生成一张渐变底 + 作品名 + 类型徽标的封面，保证卡片不裸图标。

要点：

- **规格**：建议 16:10（如 1440×900）、主体放在画面上半部；卡片会把封面裁到 112px 高（`object-fit: cover`），底部细节可能被裁掉。
- **要好看就自己给图**：用 `browser_screenshot_full` 截真实页面（存到工作区 `.pidesktop/screenshots/`），或用生图能力（`rolldek-image` / `xjbh-image`）生成一张放进工作区，然后把路径写进 `cover`。
- **panel 特别注意**：离屏截图拿不到 `./__pidesktop_state.json`（会截到页面骨架/降级态）。想要真实画面，就在面板窗口开着时截图，再用 `cover` 指定。
- **发布后自检**：回执里会写封面来源（自定义封面 / 入口图片 / 服务页截图 / 占位封面）。出现「占位封面」说明还没拿到真实画面——补一张 `cover` 后**用同一入口重新发布**即可更新（不会新增作品）。

## 六、发布卫生（gallery_publish）

- 只发布**真做完、能运行**的成果；临时脚本、中间产物不发布（作品墙会被噪声塞满）。
- 入口必须位于当前工作区内；同「工作区 + 类型 + 入口」重复发布是**更新**而非新增（改了标题 / 命令再发一次即可）。
- 发布后告诉用户在哪看：顶栏「作品」下拉或空会话的作品墙；panel 型说明「运行」会开成独立小窗（桌宠 / 贴边抽屉会以对应形态出现在桌面上），数据存在作品自己的固定 origin 里，作品墙卡片上的「数据…」可以看用量与清空。
- 每个作品都要有封面（见上一节）；没给 `cover` 时确认回执不是「占位封面」，是的话补一张图再发布一次。
