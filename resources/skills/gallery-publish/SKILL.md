# 作品发布：形态选择、入口与服务所有权

> 本目录随应用分发（安装目录 `resources/skills/gallery-publish/`），是**内置资产**：所有工作区可见，随应用升级。

发布前最重要的决策是作品的**运行环境**——它决定跨域待遇、生命周期与可用能力。选错形态的典型代价：为不需要代理的作品写了一整个本地代理（真实发生过：一个调外部生图 API 的单文件作品，因为在内置浏览器里实测被 CORS 拦而自建了代理；其实发成 panel 就能直连）。

## 一、三种形态（file / server / panel）

| kind | 运行在哪 | 适合 | 生命周期 |
| --- | --- | --- | --- |
| `file` | 主界面内置浏览器 | 单文件网页（原型、导出物），可离线、可拷给别人 | 随主界面 |
| `server` | 进程在**后台**，页面在内置浏览器 | 完整项目（dev server / 本地服务），或纯服务进程（反代 / API） | 后台进程，随应用退出而停 |
| `panel` | **独立小窗口**（本地服务同 `server` 走后台） | 常驻小工具、监控面板；主界面关了它还在 | 独立存活（平台为它启动的本地服务随窗口关闭而停） |

### 服务型作品：进程在后台，看板管它

`kind=server` 的启动命令由平台当作**后台进程**执行（2026-11-12 起）：

- **不占标签页**，关掉浏览器页面也不会停——所以启动命令必须能**非交互地长期运行**（不能等回车、不能依赖 TTY、不要在末尾加 `&` 之类的手工 daemon 化）；
- 命令**自己**必须是要长期活着的那个服务进程：不要用 `start`、`pythonw`、`cmd /c start` 这类把服务甩到别的进程树里的启动器。平台按「这条命令的进程树」判定所有权与回收，启动器会立刻退出，平台既不知道服务有没有起来，也停不掉真正的进程；就绪前退出会直接被判为**启动失败**（回执会说「启动命令提前结束，不能建立可回收的服务所有权」），就绪后退出则计为服务停止；
- 进程的可见/可停入口是**作品墙顶部的「运行中的服务」看板**（每行：状态、PID、运行时长、命令、日志尾部；动作：打开页面 / 日志 / 重启 / 停止）。顶栏「作品」下拉有运行中计数；
- 应用退出时全部停掉（不留孤儿进程），下次启动是干净状态；
- 「运行」遇到**地址已经可达**时不另起进程（那是用户手工起的或上一次留下的），也不会杀掉它——这类外部服务平台不接管。

服务型还有 `runMode` 两种，决定「就绪之后要不要顺手开页面」：

| runMode | 就绪后 | 适合 |
| --- | --- | --- |
| `page`（缺省） | 打开内置浏览器标签页 | 前端 dev server、有界面要看的本地服务 |
| `background` | 什么都不开，只在看板上出现 | 反代、API、桥、给别的程序提供数据的进程（地址打不开任何给人看的页面） |

**判断方法**：把 `url` 在浏览器里打开，是给人看的页面吗？不是 → 写 `runMode: "background"`。写错的代价很直接：一个纯服务作品每次「运行」都多弹一个 404/空白页。

`kind=panel` 有三种窗口形态（`panel.mode`，缺省 `"window"`）：

| mode | 窗口 | 页面要做的 | 典型作品 |
| --- | --- | --- | --- |
| `window` | 系统边框，可缩放 | 普通网页 | 监控面板、常驻小工具 |
| `pet` | 透明无边框，尺寸可在运行期调大调小（缺省置顶） | `body` 背景透明自绘形状；拖窗口用一块 `-webkit-app-region: drag` 的底层（**拖动区收不到鼠标事件**，所以点击 / 右键菜单必须放在 no-drag 元素上）；自带关闭钮 POST `{"action":"close"}`；大小 POST `{"action":"grow"}` / `"shrink"` / `"reset-size"`，再监听 `resize` 重排精灵缩放 | 桌宠、桌面挂件 |
| `drawer` | 贴屏幕边缘（`panel.edge`：left/right/top/bottom，缺省 right），窄把手 ↔ 完整面板两态切换，不可拖不可缩放 | 监听 `resize` 按窗口尺寸渲染两态（窄时把手、宽时面板）；点把手 POST `{"action":"toggle"}`；自带关闭钮 POST `{"action":"close"}`；透明背景 + 圆角由页面自己画 | 快速启动器、贴边监控条 |

三种形态的数据接口与跨域待遇完全一致（同一静态服务 + 端点）；`width`/`height`/`alwaysOnTop` 通用（桌宠缺省置顶，其余缺省不置顶）。桌宠的尺寸在运行期可由页面调（`grow`/`shrink`/`reset-size`）：Windows 透明窗口不能由用户拖边框缩放，所以改尺寸要走这条动作——主进程按**底部中心锚点** `setBounds`（猫变大不会浮起来）并把结果写进位置尺寸记忆，下一次「运行」还是调好的大小。

## 二、`path` 与 `entry`：最终入口只有一条

发布参数里有两个路径字段，分工固定（工具、登记对话框、本文件用同一套术语）：

- **`path`**：发布源，也是**工作区边界的检查字段**（权限门只认它，所以永远要写成工作区内的相对路径）。
  - `file` / `panel`：工作区内的文件**或目录**；
  - `server`：必须是项目目录，`entry` 不适用——给 server 传 `entry` 会直接报错，不会静默忽略。
- **`entry`**：只在 `file` / `panel` 有意义，且只用于「`path` 是目录」的情形——最终入口 = `path/entry`。`path` 本身就是入口文件时不要传 `entry`。

清单里只存**最终入口**这一条相对路径（作品墙卡片上显示的那条），不存二义的两段。下面两种写法等价：

```json
{ "title": "状态面板", "kind": "panel", "path": "panels/status", "entry": "index.html" }
```

```json
{ "title": "状态面板", "kind": "panel", "path": "panels/status/index.html" }
```

后者是旧写法（只传 `path`），行为不变——旧作品不需要迁移。重复发布按**最终入口**判定：同工作区 + 同 kind + 同最终入口 = 更新那张卡，作品 id 与面板的固定 origin 都不变。

## 三、面板的本地服务：`command` 与 `url` 必须成对

面板页没有 preload 也跑不了外部命令，需要本地数据源（跑 git / 读数据库 / 访问本机文件）时用**成对**的 `command` + `url` 声明一个本地服务。为什么必须成对：平台靠 `command` 起进程、靠 `url` 探活，缺一个就无法判断「服务到底起没起来」。

- 只填 `command`：平台不知道该等哪个地址就绪——发布就报错，不会静默开窗；
- 只填 `url`：平台没法替你起进程——同样报错；
- 两个都留空 = 面板不依赖平台托管的本地服务（面板页自己去 fetch 它需要的东西）。

成对只意味着「平台**可以**托管」：能不能真托管得看运行时的探活结果（见下面第 1 步）。清单里残留的不成对旧记录（只有 command 或只有 url）：发布阶段与运行阶段都直接报配置错误、运行被阻止——平台不猜你想怎么跑，也不会「地址可达就开窗」蒙混过去；补齐后重新发布即可。

`url` 是**探活地址**（如 `http://127.0.0.1:8791/api/health`），**不是面板页面地址**：平台只对它做 TCP 探活判断就绪，页面内容仍来自 `path`/`entry` 指向的入口文件；它不会被当作页面打开，也不该填成面板自己的入口。

运行与关窗的语义：

1. 点「运行」**先探活**：地址已经可达就是外部服务（或上一次留下的进程）——平台不启动、不接管，关窗时也不会停它；
2. 不可达才在**入口所在目录**起 `command`（后台进程），探活通过后才开窗；
3. 关闭面板窗口：平台**异步**停掉自己为**这个面板**启动的那个服务（按 `ownerPanelId` 归属），不是「停掉这个地址上的所有服务」；
4. 命令要求同 server：前台、非交互、长期运行，不用 `start` / `pythonw` / `cmd /c start` 这类启动器。

## 四、跨域边界（最容易踩的坑）

平台只在**面板窗口（panel）**里放宽跨域：主进程替响应补上整套 `Access-Control-Allow-*`（反映来源），预检 OPTIONS 被服务端拒掉（405 等）也会改写成 200。

- **panel**：可以直接 `fetch` 任何 http(s) API，**包括一个 CORS 头都不发的服务**——很多自建 / 中转的模型推理接口与图床（如 GCS 图片链接）都属此类。**不要为面板作品写本地代理。**
- **内置浏览器**（`file` / `server` 的运行地，也是 `browser_*` 工具的验证地）：「正常浏览器」语义，服务端不发 CORS 头就 `Failed to fetch`。这是刻意的安全设计（在预览里放宽等于让任意网站的脚本读跨域数据），不是 bug。
- panel 也救不了两种情况：服务端对预检直接重置连接（拿不到任何响应头，无从改写）；面板页里由 service worker 发起的请求。

**形态选择规则（按序判断）：**

1. 作品要直连无 CORS 的外部 API → **首选 panel**（零代理直连）。
2. 服务端自带 CORS 头（xjbh.lol、rolldek.com、GitHub API 等多数开放接口）→ 任意形态皆可。
3. 必须是 `file`（单文件离线分发）且要调无 CORS 接口 → 才写本地代理：只监听 `127.0.0.1`、代理统一补 `Access-Control-Allow-Origin: *`、模型返回的图片链接一并透传（形如 `/__proxy?url=<encoded>`，避免上游链接过期后裂图）。

## 五、验证口径（别被自己的测试环境骗了）

在**内置浏览器**里实测外部接口被 CORS 拦，**不等于**作品运行时被拦：`file` / `server` 形态真的会被拦，`panel` 形态不会。因此：

- 用 `browser_*` 验证页面逻辑时，跨域失败只说明「该接口服务端无 CORS 头」——先确认作品形态，再决定是「改发 panel」还是「确实需要代理」，不要直接断定必须写代理。
- 验证 panel 的跨域能力：发布成 panel 并打开面板窗口，在面板里看请求的实际结果（可请用户点开面板确认）。内置浏览器里的结果是另一个环境的，不能当定论。

## 六、panel 开发要点

面板的数据接口（相对自己 `fetch("./__pidesktop_state.json")` 读会话状态、POST 唤回主界面 / 关窗 / 抽屉切换，`panel {width,height,alwaysOnTop,mode,edge}` 声明窗口）在作品墙「继续开发」按钮的注入文本里有完整契约，**以它为准**，此处不重复。写 pet / drawer 之前先看同仓库 `examples/panel-pet/`、`examples/panel-drawer/` 两个零依赖示例。

**每次「运行」都会重新加载入口页**（关闭再开是重载，窗口已经开着也会 reload 后前置）：所以改完代码再点「运行」看到的一定是最新版本，不必让用户手动关窗；反过来，页面**内存**状态会被重置，需要留住的东西（设置、缓存、草稿）写 `localStorage` / `IndexedDB`。

**面板的持久化直接存 `localStorage` / `IndexedDB`，不要自建保险库（2026-10-10 起）**：面板页跑在由作品 id 决定的固定 origin（`pidesktop-file://w-<作品>`，没有端口）上，所以这两种存储跨启动保留、按作品隔离。之前流传的「隐藏 iframe 走自定义协议做保险库 / 自己起本地服务存盘 / 把数据塞 sessionStorage 兜底」都是旧「随机端口 origin 每次换锁」时代的弥补手段——现在只会多一层会坏的中间层（而且保险库那条路本来就跑不通：平台协议 `pidesktop-file://preview` 只服务 PDF 与图片，HTML 会 415）。用户可在作品墙卡片的「数据…」看用量并清空。注意：**在内置浏览器里预览同一个面板是另一个 origin**（http + 随机端口）——那里的存储是开发用的另一份，别把「面板里没数据」当成 bug 的证据；要验持久化就把面板真正跑起来（可请用户关闭再重开一次）。

**安全边界**：面板页的代码等同**受信任的本地代码**——平台为它放宽跨域、它能读本机会话状态端点。因此面板入口只能是你自己（或用户审查过的）本地文件，不要把远程页面、第三方脚本、来路不明的 HTML 当面板入口发布。

## 七、封面（每个作品都要有）

**2026-10-28 起，作品墙的每张卡片都必须有封面**；发布时平台按下面的顺序取图，第一个成功的胜出：

1. **显式 `cover`**：`gallery_publish` 的 `cover`（或人工对话框的「封面图片」）指定工作区内的一张图片（png / jpg / jpeg / webp / gif / svg，≤8 MB）。
2. **入口本身就是图片**：`kind=file` 的入口是 png / jpg / webp 时直接用它。
3. **自动截图**：
   - `file` / `panel`：离屏加载入口网页截图（不需要真的打开窗口）；
   - `server`：只有登记的服务地址**此刻可达**才截服务页（平台不会为截图自动起服务——所以调试完、服务还跑着时发布，封面效果最好）。
4. **占位封面**：以上都不行时，平台生成一张渐变底 + 作品名 + 类型徽标的封面，保证卡片不裸图标。

要点：

- **规格**：建议 16:10（如 1440×900）、主体放在画面上半部；卡片会把封面裁到 112px 高（`object-fit: cover`），底部细节可能被裁掉。
- **要好看就自己给图**：用 `browser_screenshot_full` 截真实页面（存到工作区 `.pidesktop/screenshots/`），或用生图能力（`rolldek-image` / `xjbh-image`）生成一张放进工作区，然后把路径写进 `cover`。
- **panel 特别注意**：离屏截图拿不到 `./__pidesktop_state.json`（会截到页面骨架/降级态）。想要真实画面，就在面板窗口开着时截图，再用 `cover` 指定。
- **发布后自检**：回执里会写封面来源（自定义封面 / 入口图片 / 服务页截图 / 占位封面）。出现「占位封面」说明还没拿到真实画面——补一张 `cover` 后用同一入口重新发布即可更新（不会新增作品）。

## 八、发布卫生与「继续开发」回发布

- 只发布**真做完、能运行**的成果；临时脚本、中间产物不发布（作品墙会被噪声塞满）。
- 入口必须位于当前工作区内；按最终入口重复发布是**更新**而非新增（改了标题 / 命令 / 封面再发一次即可）。
- 发布后告诉用户在哪看：顶栏「作品」下拉或空会话的作品墙；panel 型说明「运行」会开成独立小窗（桌宠 / 贴边抽屉会以对应形态出现在桌面上），数据存在作品自己的固定 origin 里，作品墙卡片上的「数据…」可以看用量与清空；server 型说明进程跑在**后台**（不占标签页），要停/看日志就去作品墙顶部的「运行中的服务」。
- 发布纯后台服务（反代 / API）时必须带 `runMode: "background"`，否则用户点「运行」会被弹一个没有意义的页面。
- **继续开发必须闭合「改 → 验 → 重新发布」**：用户从作品墙点「继续开发」进来后，改完并验证通过就要再次调用 `gallery_publish`，并且用**同一作品身份**：
  - 优先用注入文本里给出的作品 id（`appId`），它决定更新哪张卡；
  - 没有 id 时用「同工作区 + 同 kind + 同最终入口」，也是更新；
  - 除非用户明确要一个新作品，不要改 `kind` 或最终入口。panel 的 origin 由作品 id 决定：更换 id 会让 `localStorage` / `IndexedDB` 数据分裂；只改入口但保留 appId 时数据仍在同一 origin；
  - 回执显示「更新」而不是「新增」之后再告诉用户做完了。

## 九、发布前检查清单

1. **最终入口对**：回执里的入口就是你想要的那个文件（目录 + `entry` 的写法别漏 `entry`）。
2. **服务所有权对**：panel / server 的回执要能分清三种状态——「已由平台启动并托管」/「地址已可达，复用外部服务，平台不接管」/「没有配置本地服务」。回执说外部复用而你本来指望平台托管：先看看那个地址是不是你自己之前起的服务（平台不会停它，也不会重复起）；如果它不应该占着这个端口，停掉它再运行，平台才会自己起。什么情况下都拿不到平台托管的记录，就是命令写成了启动器或提前退出了。
3. **页面是新代码**：改完代码重新发布后点「运行」，panel 会 reload 到最新入口；画面还是旧的，先核对发布的是同一个最终入口 / 同一个作品 id。
4. **封面不是占位**：回执里的封面来源应当是你给的图 / 入口图片 / 服务页截图。
5. **命令能长期运行**：前台、非交互，没有 `start` / `pythonw` / `cmd /c start` 这类甩进程的启动器。
6. **纯后台服务带了 `runMode: "background"`**，不会平白弹一个空白页面。
