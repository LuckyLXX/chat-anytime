# 记忆整理

> 本目录随应用分发（安装目录 `resources/skills/memory-organize/`），所有工作区、所有角色可见，随应用升级。
> 要自定义就把本目录复制到全局技能目录 `~/.pi/agent/pidesktop-skills/memory-organize/`（同名覆盖内置）
> 或项目技能目录 `<工作区>/.pidesktop-skills/memory-organize/`。
>
> **本文件是整理口径的唯一事实源**：定时任务的提示词只写「读本 skill 执行」，不要再把规则复制过去，
> 两处规则必然漂移。若库里另有「长期记忆组织约定」一类治理主题，先读它；与用户最新口径冲突时以用户为准。

## 0. 一句话判据

**代码是最终事实源。** 一条记忆删掉后，未来会话会不会因此做错事？**会 → 留（压到最短）；不会 → 删。**

记忆只存「读代码看不出来」的东西，按价值排序：

1. **关键决策点**——选了什么、否决了哪些备选、为什么否决（用户原话与日期、实测依据）。
2. **关键实测点**——具体数值 / 阈值 / 耗时 / 限额，以及怎么测出来的（探针路径、可复现命令）。
3. **用户口径**——明确选定 / 否决的做法，尤其产品形态与交互。
4. **会坏的坑**——跨会话仍生效、一句话能说清后果（附测试或文件锚点）。
5. **外部硬事实**——平台 / 协议 / 系统限制（CORS、TLS、OSC633、win32 语义这类不可推导的约束）。
6. **流程关键步骤**——发布、打包、冒烟这类不可试错的动作。

## 1. 调用即授权

用户调用本 skill（或用户自己配置的定时任务读本 skill 执行）= 授权本轮**直接删改**，不必逐条确认——删主题、整篇重写都算。工具描述里「删除前需取得用户确认」在这里已被这次调用满足。

只有两种例外：

- 用户明说「先给方案 / 只出报告不要改」→ 只盘点、只出报告，零写入。
- 目标是**别的助手**的助手库 → 一律不碰。

即便如此，每个删改都要在报告里写依据；删除项还要写「这条事实现在还能在哪查到」。

## 2. 允许动的两处

| 库 | 路径 | 范围 |
|---|---|---|
| 项目库（项目知识 / 踩坑 / 架构事实，任意助手共享） | `<工作区>/.pidesktop/memory/` | 可整理 |
| 助手库（用户偏好 / 协作纪律，跟人走） | `<agentDir>/pidesktop-memory/<本 agentId>/` | **只整理自己这一份** |

- 以 `memory_list` 的结果为整理范围：它列出的就是「本助手库 + 全局 + 当前工作区绑定」的可见主题。
- **只用 `memory_*` 工具改记忆**。不要用文件系统直接增删改主题文件——库归属、索引派生、工作区绑定都由工具维护，绕过它会漂移。
- 其他 agent 的目录、`AGENTS.md`、源码、`docs/`、git：全部不碰。

## 3. 流程

### 3.0 备份（第一件事，fail closed）

Windows（PowerShell）：

```powershell
$ts = Get-Date -Format 'yyyyMMdd-HHmmss'
$root = Join-Path $env:USERPROFILE '.pidesktop-memory-backup'
$backup = Join-Path $root $ts
New-Item -ItemType Directory -Force -Path $backup | Out-Null
$project = Join-Path '<工作区绝对路径>' '.pidesktop\memory'
if (Test-Path -LiteralPath $project) { Copy-Item -LiteralPath $project -Destination (Join-Path $backup 'project') -Recurse -Force }
Copy-Item -LiteralPath (Join-Path $env:USERPROFILE '.pi\agent\pidesktop-memory') -Destination (Join-Path $backup 'agent') -Recurse -Force
```

macOS / Linux：

```bash
ts=$(date +%Y%m%d-%H%M%S); backup="$HOME/.pidesktop-memory-backup/$ts"
mkdir -p "$backup"
[ -d "<工作区>/.pidesktop/memory" ] && cp -R "<工作区>/.pidesktop/memory" "$backup/project"
cp -R "$HOME/.pi/agent/pidesktop-memory" "$backup/agent"
```

复制完**核对非空**（`Get-ChildItem -Recurse -LiteralPath $backup` 有文件），备份路径记进报告。**备份失败 → 本轮只出报告，不写任何记忆。**

只保留最近 5 份。清理旧备份必须**先列清单、再逐个显式路径删**：

```powershell
Get-ChildItem -LiteralPath $root -Directory | Sort-Object Name -Descending | Select-Object -Skip 5
# 对上面列出的每一项，单独一条，路径写死字面量：
# Remove-Item -LiteralPath "C:\Users\<你>\.pidesktop-memory-backup\20260101-120000" -Recurse -Force
```

禁止 `Get-ChildItem ... | Remove-Item -Recurse -Force` 这类管道式递归删除：目标不显式时一次意外就是整库误删。路径里带变量（`$d.FullName`）同样不合格。

### 3.1 盘点

一次 `memory_list({ limit: 200 })` 拿到：主题数、各主题字数、层、库归属、更新日期。算出缺口，不要逐个 read：

- 主题数（项目库目标 ≤18；助手库 ≤6）
- 正文合计字数（项目库目标 ≤120k）
- 单主题 >8k 名单（>12k 必须本轮处理）
- core 数量（≤3）
- 重复 / 副本 / 纯指针主题
- 索引预算：项目库 1400 字 + 助手库 600 字（总 2000 字），description ≤45 字

### 3.2 选目标（按优先级）

超 12k 主题 → 超 8k 主题 → 重复 / 副本 → 含过期状态的段（已修项、旧版本号、旧测试计数）→ 纯指针 / 只剩流水 → 其余。一轮挑 **4–10 个**。

### 3.3 逐个处理

**先 `memory_read(topic, section="*")` 读全文再决定**（封顶 12000 字；更大的主题先看目录再按节读）。同一会话已读过会回一行提示，确需重看传 `refresh: true`。

| 情况 | 动作 |
|---|---|
| 只剩流水 / 纯指针 / 已被新方案取代 | `memory_delete` |
| 有价值但臃肿 | `memory_write` 整主题重写（见下） |
| 两个主题同义 | 合并重写成一个，另一个删（保留被 `AGENTS.md` 点名的那个标题） |
| 考古才用的取证细节 | `memory_layer` 改 `archive`，正文压成一句结论 + 锚点 |
| 分错了层 | `memory_layer` 调整，不重写正文 |
| 只是缺要点 | `memory_write` 整篇替换补 summary（见坑 4） |

压缩重写（`memory_write`）的硬要求：

- 逐条保住保留清单里的每一条事实：**数字、阈值、报错原文、用户原话一个字都不许改**。不要写成「大概偏高」这类模糊总结。
- `description` ≤45 字，只做索引；`summary` 3–8 行 / ≤400 字（超了**静默截断末尾**，结论别放最后）；`triggers` ≤3 个、每个 ≤12 字，只放反直觉词。
- 层：`core` 只放每会话都该在场的偏好 / 纪律 / 会变状态（要点 ≤120 字）；`standard` 放项目知识；`archive` 不进索引。
- 改写前必须已读全文；改写后不得新增编造内容。

### 3.4 自检

1. 再调一次 `memory_list`：主题数 / 总字数 / 最大主题**是否真的下降**。
   > 会话开头注入的索引是会话创建时冻结的快照，**不能当现状**；一切以工具回执为准。
2. 索引：项目 1400 + 助手 600 字内，description ≤45 字；超预算就先降 description、合并或归档。
3. 一致性：frontmatter 齐全、单文件只有一个一级标题、没有指向已删标题的悬挂引用。
4. **无损校验靠指纹比对**：从备份抽出 ① `npm test` 这类验证结论数字 ② commit 短哈希 ③ 反引号标识符集合，与新主题集比对；**验证结论类数字丢了必须补回**。
5. 行尾统一 LF（记忆库文件）。

### 3.5 出报告

见 §6。

## 4. 目标态

| 对象 | 目标 | 超限处理 |
|---|---|---|
| 项目库主题数 | ≤18 | 合并同义 / 删过程流水 |
| 项目库正文合计 | ≤120k 字 | 删 + 压缩 |
| 单主题正文 | ≤8k 字 | >12k 必须本轮处理 |
| core 主题 | ≤3 个 | 其余降 standard |
| 助手库（自己那份） | ≤6 主题 | 同上 |
| 索引 `MEMORY.md` | 派生，不手写 | 只改 description / summary / 层 |

## 5. 额度与硬禁止

额度：

- 一轮处理 4–10 个主题；删除 ≤8 个；压缩重写 ≤4 个（其余顺延并写明）。
- 必须产出净减少：总字数 −20k 或主题数 −2（已达标除外）。
- 不确定时按「能少留就少留」处理，在报告里写「依据 + 万一删错的后果」，**不要因为不确定就整轮不动**。

硬禁止：

- 不改 `AGENTS.md`、不改源码、不做任何 git 写操作、不跑构建、不 push。
- 不动其他助手的助手库；不把记忆写进仓库文件（含 `docs/`）；**不手写 `MEMORY.md`**（索引由 store 派生）。
- 不把事实写成模糊总结；不编造数字、路径、结论。
- 被 `AGENTS.md`「细节去哪找」点名的主题**不许删**（可压缩；合并时保留该标题，否则索引表出现悬挂引用）。

## 6. 报告格式

一个 `assistant_html` div 气泡，≤600 字，气泡外不写正文：

- **标题**：`记忆整理 · <日期> · 净减 X 字 / −Y 主题`；已收敛写「【已收敛】」。
- **动作表**：主题 | 删 / 压 / 合 / 归档 | 体积变化 | 一句依据。
- **删除清单**：主题 +「这条事实现在还能在哪查到」（git、代码、归档主题、备份路径）。
- **目标进度**：主题 a→b / 18；总字数 c→d / 120k；最大主题 e→f / 8k。
- **保护清单核对**：`AGENTS.md` 点名主题 0 项被动（有则写理由）。
- **下轮优先处理**：1–3 个。
- 备份路径与「已达标就建议把定时任务改成每周一次」。

## 7. 常见坑（都是实测踩过的）

1. **标题手打会 miss**：主题标题里含易混域名 / 长英文词时，`memory_delete` / `memory_read` 连续几次都找不到。从 `memory_list` 整行复制标题，别凭印象手打；实在对不上就用码点比对重建标题。
2. **`X · 片段 N` 不是小节**：目录里的片段编号是读取器把 >4000 字的节切片的结果。按节拼回时片段之间是连续文本，不要当成并列小节。
3. **合并要改边界声明**：目标主题常写「XXX 不要写到这里」这类边界句，并入新内容后必须同步改掉，否则自相矛盾。
4. **补 summary 只能整篇替换**：先 `memory_read(section="*")` 取全文、原样写回并补 summary，写后核对 header「正文 N 字」不变。超过 12000 字的主题必须按节读，不能整篇替换。
5. **工具返回「已停用」**：记忆功能被关掉了，报告一句结束，不要改文件绕过。
