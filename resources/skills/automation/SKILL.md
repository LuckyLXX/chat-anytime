# 创建与管理自动化定时任务

> 本目录随应用分发（安装目录 `resources/skills/automation/`），是**内置资产**：所有工作区、所有角色可见，
> 随应用升级。要自定义就把本目录复制到全局技能目录 `~/.pi/agent/pidesktop-skills/automation/`（同名覆盖内置）
> 或项目技能目录 `<工作区>/.pidesktop-skills/automation/`。

PiDesktop 的「自动化任务」让用户配置「在什么时间、让 Agent 用什么提示词跑一次」。你负责把用户的自然语言定时需求，转换成一条**合法、可读、能落库**的定时任务。

## 什么时候用

- 用户说「每天 9 点巡检一下仓库」「每小时生成一次报告」「每周一上午提醒我开会」。
- 用户说「5 分钟后检查一下刚才那个后台任务有没有跑完」「半小时后提醒我」。
- 用户说「创建一个定时任务 / 自动化任务」。
- 用户想列出、暂停、删除、修改或立即试跑已有任务。

## 核心概念

一条定时任务由以下字段组成（对应 `automation_create` 的参数）：

| 字段 | 说明 |
|---|---|
| `name` | 任务名，一句话可读（如「每日项目巡检」「5 分钟后检查后台任务」）。 |
| `prompt` | **必填**。触发后让 Agent 做什么，要写清目标与期望产出。 |
| `cron` | 周期任务：5 字段 `分 时 日 月 周`。与 `after_seconds`/`at` **三选一**。 |
| `after_seconds` | 一次性延时任务：相对当前时刻的秒数（5 分钟 = 300）。与 `cron`/`at` 三选一。 |
| `at` | 一次性绝对时间：ISO 8601（推荐带时区偏移，如 `2026-10-21T15:30:00+08:00`）。与 `cron`/`after_seconds` 三选一。 |
| `target` | `session`（默认）或 `background`。`session` = 到期把提醒作为普通用户消息投递回**当前会话**，保留上下文；`background` = 到期新建后台会话独立执行（旧行为）。 |
| `timezone` | 可选。仅 cron 使用，IANA 时区名（如 `Asia/Shanghai`）；不传则跟随系统。 |
| `model` | 可选。执行时用哪个模型；**不传则用该 Agent 默认模型**。 |
| `workspace` | 可选。后台任务的「空间」元数据；会话绑定任务使用目标会话自己的工作区。 |
| `accessMode` | 可选。`read-only` / `ask` / `workspace` / `full`；**后台无人值守任务建议 `full`**。会话绑定任务沿用原会话权限。 |
| `skillName` / `subagentName` | 可选。绑定技能/子智能体，v1 仅存为元数据。 |

## 一次性任务与会话绑定（重点）

当用户说「**几分钟后检查刚才那个后台任务**」时，**不要**用 cron，也不要把任务建成一个无上下文的新会话：

1. 用 `after_seconds` 表达延时（例如 5 分钟 → `300`）；
2. 保持默认 `target: "session"`，任务会绑定当前会话；
3. `prompt` 可以直接引用「刚才」「上面」的后台任务，因为到期提醒会作为普通用户消息进入同一个对话，Agent 能看到原上下文；
4. 到点后任务自动完成，不会重复触发；要再检查一次，需要新建任务或 `automation_update` 改期。

示例：

```text
用户：「5 分钟后检查刚才启动的 Ghidra 分析有没有跑完」

→ automation_create {
  name: "5 分钟后检查后台任务",
  after_seconds: 300,
  target: "session",
  prompt: "检查刚才启动的后台分析任务是否完成：查看进程是否还在、CPU/内存是否正常、日志与产物是否生成。完成就汇报结果；未完成说明当前进度和预计时间；失败则给出错误原因和下一步建议。",
  accessMode: "full"
}
```

如果用户明确要一个**独立后台任务**（例如每天生成日报、巡检仓库，不希望占用当前对话），用 `target: "background"`；这时 prompt 必须自洽，不能依赖「刚才」这类只有当前对话才有的上下文。

## 自然语言 → cron 的换算

cron 5 字段顺序：`分 时 日 月 周`（周：0 和 7 都是周日，1=周一 … 6=周六）。

| 用户需求 | cron |
|---|---|
| 每天 18:00 | `0 18 * * *` |
| 工作日每天 09:00（周一至周五） | `0 9 * * 1-5` |
| 每周一 09:00 | `0 9 * * 1` |
| 每 15 分钟 | `*/15 * * * *` |
| 每小时整点 | `0 * * * *` |
| 每月 1 号 08:00 | `0 8 1 * *` |
| 每天凌晨 00:30 | `30 0 * * *` |

换算要求：
- 5 字段一定写全，用空格分隔。
- `分` 0-59、`时` 0-23、`日` 1-31、`月` 1-12、`周` 0-7。
- 用户没说精确时间就问一下；能推断就给出最合理的默认并明确告知。
- 用户的「每周」通常指「某星期几」用 `周` 字段；「每个月 X 号」用 `日` 字段；不要同时填死 `日` 和 `周`。

## 落库步骤

1. 向用户确认（或依据已知信息直接定）：任务名、触发方式（cron / 延时 / 指定时间）、提示词、目标（会话/后台）、模型（必要时）、权限。
2. 组合出完整字段，调用 **`automation_create`** 一次性创建。调度参数（`cron` / `after_seconds` / `at`）必须且只能传一个。
3. 创建成功后简短告知用户：任务名、触发方式、是否绑定当前会话、几点跑、用哪个模型、当前共几条任务。

## 管理已有任务

- 查列表：**`automation_list`**（含名称/调度/一次性或周期/绑定会话/启用状态/近一次运行）。
- 修改：**`automation_update {id, ...}`**（可改名称、提示词、调度、target、启停；不传的字段保持原值）。
- 立即试跑：**`automation_run {id}`**（不等 cron；会话绑定任务会直接投递到关联会话）。
- 启停：**`automation_toggle {id, enabled}`**（暂停后不再自动触发；已完成的一次性任务要改期才会重新启用）。
- 删除：**`automation_delete {id}`**。

## 注意事项

- **权限**：后台任务无人值守运行，不会有人来点确认；`accessMode` 建议 `full`（完全访问），否则遇到写文件/执行命令的权限确认会**挂起**。会话绑定任务沿用原会话权限。
- **模型**：用户没提模型就别硬塞，用该 Agent 默认模型；用户提到了才传 `model`，并保证 `provider/id` 是已配置的模型。
- **提示词要自洽**：`target: "background"` 时任务触发时没有原对话上下文，prompt 要写清「做什么、产出什么格式」；`target: "session"` 时可以利用上文，但仍要写清检查/执行的具体目标。
- **一次性任务**：`after_seconds` / `at` 到点投递后自动变为「已完成」，不会重复触发；要重复检查请用 cron 或重新创建。
- **关联会话**：任务绑定的是**创建时所在的会话**；如果该会话被删除或尚未落盘，投递会失败并在运行记录里留下错误。不要假设任务会自动改投到别的会话。
- **重复创建**：如果用户想改一条已有任务，用 `automation_list` 找到 id 后调用 `automation_update`，不要再 create 一条新的。
