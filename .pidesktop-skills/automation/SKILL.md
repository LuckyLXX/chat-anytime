# 创建与管理自动化定时任务

PiDesktop 的「自动化任务」让用户配置「在什么时间、让 Agent 用什么提示词跑一次」。你负责把用户的自然语言定时需求，转换成一条**合法、可读、能落库**的定时任务。

## 什么时候用

- 用户说「每天 9 点巡检一下仓库」「每小时生成一次报告」「每周一上午提醒我开会」。
- 用户说「创建一个定时任务 / 自动化任务」。
- 用户想列出、暂停、删除或立即试跑已有任务。

## 核心概念

一条定时任务由以下字段组成（对应 `automation.create` 的参数）：

| 字段 | 说明 |
|---|---|
| `name` | 任务名，一句话可读（如「每日项目巡检」）。 |
| `cron` | **必填**。5 字段调度：`分 时 日 月 周`。 |
| `prompt` | **必填**。触发后让 Agent 做什么，要写清目标与期望产出。 |
| `model` | 可选。执行时用哪个模型；**不传则用该 Agent 默认模型**。用户明确点了某个模型时传 `{provider, id}`。 |
| `timezone` | 可选。IANA 时区名（如 `Asia/Shanghai`）；不传则跟随系统。 |
| `workspace` | 可选。参照「空间」；v1 仅存为元数据，执行用当前工作区。 |
| `accessMode` | 可选。`read-only` / `ask` / `workspace` / `full`；**无人值守建议 `full`**。 |
| `skillName` / `subagentName` | 可选。绑定技能/子智能体，v1 仅存为元数据。 |

## 自然语言 → cron 的换算

cron 5 字段顺序：`分 时 日 月 周`（周：0 和 7 都是周日，1=周一 … 6=周六）。

| 用户需求 | cron |
|---|---|
| 每天 18:00 | `0 18 * * *` |
| 工作日每天 09:00（周一至周五） | `0 9 * * 1-5` |
| 每周一 09:00 | `0 9 * * 1` |
| 每 15 分钟 | `*/15 * * * *` |
| 每小时整点 | `0 * * * *` |
| 每月 1 号 08:00 | `0 8 1 * *` |
| 每天凌晨 00:30 | `30 0 * * *` |

换算要求：
- 5 字段一定写全，用空格分隔。
- `分` 0-59、`时` 0-23、`日` 1-31、`月` 1-12、`周` 0-7。
- 用户没说精确时间就问一下；能推断就给出最合理的默认并明确告知。
- 用户的「每周」通常指「某星期几」用 `周` 字段；「每个月 X 号」用 `日` 字段；不要同时填死 `日` 和 `周`（会按「与」匹配，多数用户不理解）。

## 落库步骤

1. 向用户确认（或依据已知信息直接定）：任务名、触发时间、提示词、模型（必要时）、权限。
2. 组合出完整字段，调用 **`automation.create`** 一次性创建。不要把字段拆成多步，也不要自己在对话里复述 JSON。
3. 创建成功后简短告知用户：任务名、cron、几点跑、用哪个模型、当前共几条任务。

```text
举例：用户说「每天下班前 18 点用 chatanytime 的中转模型巡检一次仓库并生成日报」
→ automation.create {
  name: "每日 18 点仓库巡检",
  cron: "0 18 * * *",
  prompt: "巡检当前项目的代码仓库：检查未提交改动、运行测试，并生成一份简短的日报（含当日改动要点、测试结果、风险与建议）。",
  model: { provider: "chatanytime-openai-compatible", id: "gpt-4o-mini" },
  accessMode: "full"
}
```

## 管理已有任务

- 查列表：**`automation.list`**（含名称/cron/启用状态/近一次运行）。
- 立即试跑：**`automation.run {id}`**（不等 cron，立刻在后台跑一次，验证提示词与模型）。
- 启停：**`automation.toggle {id, enabled}`**（暂停后不再按 cron 自动触发）。
- 删除：**`automation.delete {id}`**。

## 注意事项

- **权限**：无人值守下任务在后台运行，不会有人来点确认；`accessMode` 建议 `full`（完全访问），否则遇到写文件/执行命令的权限确认会**挂起**。若用户指定了受限权限，要提醒这一点并建议改为完全访问。
- **模型**：用户没提模型就别硬塞，用该 Agent 默认模型；用户提到了才传 `model`，并保证 `provider/id` 是已配置的模型。
- **提示词要自洽**：任务触发时没有用户上下文，prompt 要写清「做什么、产出什么格式」，让 Agent 能独立完成。
- **重复创建**：如果用户想改一条已有任务，用 `automation.list` 找到 id 后**不要**再 create 一条新的；优先编辑（修改后再 create 同 id 覆盖）或直接删除重建。
