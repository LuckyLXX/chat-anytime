## 2026-08-16 工具管道优化（refactor/tool-pipeline）

借鉴 deepseek-harness 架构思路的三阶段落地（此前分析结论：dsh 的"跟随系统主题"建议不成立——本应用已有且为默认；插件注册表收益低，真正的痛点是 customTools 固定于会话创建）：

1. **工具审计 + MCP 调用超时**（`tool-audit.ts` / `mcp-client.ts`）
   - 新增 app-owned 内联扩展：`tool_execution_start/end` 事件 → 追加写 `chatanytime-sessions/<agentId>/tool-audit.jsonl`（时长/错误标记/参数摘要 2KB 截断，best-effort 串行写入）
   - MCP `callTool` 由此前完全无超时 → `AbortSignal.any` 合并外部取消与 120s 超时，超时报「MCP 工具调用超时」
2. **MCP 工具热重载**（`tool-delta.ts` + `applyMcpToolChanges`）
   - 关键机制（已用真实 AgentSession 集成测试钉死）：Pi 以引用保存 customTools 数组且刷新时重读；`pi.registerTool()` 可在活会话上触发注册表重建
   - 新增/替换服务器：原地换数组 + registerTool + setActiveToolsByName，消息流不中断
   - 删除/停用（无移除 API）：回退到原有会话重建路径（保 SessionManager，历史不丢）
3. **pi-runtime.ts 拆分**（1528 → 1416 行）
   - 五个能力簇搬至 `runtime-todo-tools / runtime-skills / runtime-vision / runtime-permissions / runtime-mcp`，纯构建器 + 显式入参，无共享可变状态对象
   - 死代码清理：`builtinToolNames`、恒空的 `resourceDiagnostics`

验证：vitest 232 全过（新增 14：审计 5、信号 2、delta 3、热重载真实会话集成 2、原 mcp 用例 2）；`npm run build` 过。无打包行为变化。
