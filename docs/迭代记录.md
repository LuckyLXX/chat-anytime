## 2026-08-16 多会话并行 + 会话状态点（feat/multi-session）

痛点：`createSession` 切换即 `dispose()` 旧会话——一个会话执行中无法新建/切换到另一个会话并行执行；侧边栏也看不出哪些会话在跑、跑完是成是败。

1. **会话运行时记录化**（`pi-runtime.ts`）
   - 原全局单例状态（session/busy/status/executions/controlMessages/turnTiming/pendingVision/todoStore/extensionApi/sessionCustomTools/权限门 deps）全部收进 `SessionRuntimeRecord`，`liveSessions: Map<sessionId, record>` + `activeRuntime` 激活指针
   - 切换/新建会话 = park 旧记录（后台继续流式写入自己的 JSONL），不 dispose；快照始终取激活记录
   - 每记录独立的 customTools 数组（MCP 热重载只作用于激活会话）、独立权限门（workspace/agent/session 按记录捕获）、独立 session-scoped todo store
2. **并行执行语义**
   - `session.new` / `session.open` / `workspace.open` / `agent.select` 忙时不再阻塞或杀运行中的会话；`session.open` 与 continueRecent 命中活记录时原位 reactivate（不重建，执行中的回合完整保留）
   - 同一会话内仍串行：prompt/regenerate/compact 增加 record.busy 守卫
   - 空闲驻留记录 LRU 上限 4 个（运行中永不驱逐）；`workspace.remove` 连带销毁该工作区的活记录；createSession 双重 generation 复查防止并发切换时旧管线抢回激活位
   - 后台记录只上报生命周期变化（省 IPC），流式事件直接丢弃
3. **会话状态点**（协议 + 渲染层）
   - `SessionSummary.runStatus?: "running" | "completed" | "failed"`，由 agent_start/agent_end（末条 assistant errorMessage 或 abortRequested 判失败）/prompt 拒绝/compaction 结果驱动，`refreshSessions` 叠加活记录状态
   - 侧边栏话题项加小圆点：黄=执行中（呼吸动画，实时状态）、绿=执行完成、红=执行失败（中止也算失败），复用主题 `--warning/--success/--danger`，深浅色自适应
   - 终态圆点（绿/红）语义是"未读结果提醒"：只在后台会话上挂，点进该会话即清除（结果已可见于对话）；正在查看的会话自己跑完不挂终态圆点（`setTerminalRunStatus` / `activate` 统一收口）
   - 会话完成/失败后 500ms 去抖刷新列表（标题/排序跟上）
4. **其他**：agent 切换/资源重载期间的 busy 反馈改走 `transitionStatus` 覆盖层（重建中记录被替换不再闪断）；助手切换按钮解除 busy 禁用；demo-api 模拟 running→completed 生命周期

验证：vitest 232 全过；`tsc` node/web 双工程通过；`npm run build` 过。
