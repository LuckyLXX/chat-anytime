# 主题创作能力分析报告（以 maid-atelier 复刻为样本）

> 样本：`themes/maid-atelier/`（从 dsh-deep-whale 复刻，纯 CSS + 资产目录）。
> 结论先行：**架构不需要重构，需要的是"语义钩子下沉 + 确定性验证闭环 + 修 3 个真坑"。**

### 1.1 被证明成立的能力（不要动）

### 1.2 被证明是"洞"（按责任方归类）

| # | 现象 | 责任方 | 本质 |
|---|---|---|---|
| 1 | 设置页与侧栏 `.agent-list` 类名撞车，设置页规则带 `background: var(--surface-muted)`，深蓝侧栏下整块泛白（`styles.css:826`） | **应用 bug** | 类名无作用域；基础主题下两色相近被掩盖，深色主题一用就爆 |
| 2 | 应用壁纸规则 `html[data-theme-wallpaper="true"] .sidebar`（0,2,1）压过主题 `[data-theme-wallpaper] [data-pane="sidebar"]`（0,2,0），侧栏渐变/顶栏织带**静默失效**（表现为纯色兜底） | **契约缺口** | 覆盖规则需要"特异性暗知识"，AI 默认写错且无报错 |
| 3 | `[data-pane] > * { position: relative; z-index }` 覆盖附件托盘/斜杠菜单的 `position: absolute`，浮层变网格隐式行、压到工具栏上 | **套路陷阱** | 主题没有"安全抬层"的语义方式，只能靠排除类名解决 |
| 4 | 输入框强给 `min-height: 208px` → `minmax(32px, 1fr)` 的 `1fr` 行吃满富余 → textarea 与工具栏间大空白 | **套路陷阱** | 网格 `1fr` 在"确定高度容器"下的语义未文档化 |
| 5 | 侧栏 260px 硬编码进主题（立绘偏移 `calc(... + 260px)`、蝴蝶结 `50% + 130px`） | **契约缺口** | 布局尺寸不是 token，主题无法引用响应式 |
| 6 | 立绘暗色变体、角饰镜像变体需 Pillow 预处理，AI 创作时不可行 | **表达力缺口** | 层是纯 `background` 简写：无 filter / transform / opacity 单层控制 |
| 7 | 行级/节点级只能命中区域内类名（`.session-list button.active`、`.empty-workspace`、`.action-timeline-*`） | **语义缺口** | 钩子只有区域级；AI 精细收益受限，且类名升级即碎 |

## 二、应用侧优化项

### P0（改完立刻解除 3 个真坑，小改动）

**P0-1 修复 `.agent-list` 撞名**
- 改法：设置页类名改为 `settings-agent-list`（`styles.css:826-831` + 对应 JSX）。
- 收益：消除一整类"主题一刷深色就白块"的隐性 bug；侧栏助手列表不再需要主题侧回收规则。

**P0-2 壁纸规则去掉 `html` 前缀 + 文档化特异性阶梯**
- 改法：`html[data-theme-wallpaper="true"] .sidebar/.topbar/...` → `[data-theme-wallpaper="true"] .sidebar/...`（`styles.css:1309-1351`），并说明"主题用等特异性属性选择器 + 后注入即可覆盖"。
- 收益：主题不再需要 `html` 前缀暗知识；`theme.css` 可删掉 4 处 `html` 前缀规则。

**P0-3 布局尺寸 token 化**
- 改法：`:root { --layout-sidebar-width: 260px }`，`grid-template-columns: var(--layout-sidebar-width) …`（`styles.css:145`）。
- 收益：主题用 `calc(... + var(--layout-sidebar-width))` 替代硬编码；日后侧栏可拖宽时不碎。

**P0-4 `data-theme-layer` / `data-layer-kind` 升为契约**
- 改法：装饰层 div 已渲染这两个属性（`App.tsx:2431`），写进 `docs/theme-guide.md`、skill `variables.md`、checker 白名单。
- 收益：主题可写 `[data-theme-layer="maid-left"] { filter: brightness(0.84) drop-shadow(...); transition: ... }` ——
  - 解除 #6 的暗色立绘：不需要 Pillow 预调暗；
  - 角饰镜像可用 `--pi-overlay-corner` 层 + `transform: scaleX(-1)`（overlay 是 `pointer-events:none`，压在 UI 上层正合位置）；
  - 图层可动（位移/淡入）→ 着陆-对话切换动画成为可能。
- 这是**对 AI 创作能力影响最大的一笔**。

### P1（语义钩子下沉，AI 主题表达上限，独立且稳定）

| 项 | 建议 | 挂载点（现有 DOM，成本≈0） |
|---|---|---|
| 行级钩子 | `data-row-kind="workspace|session|agent"`、`data-row-active`、`data-row-expanded` | `App.tsx` 侧栏各行/组头按钮 |
| 节点级钩子 | `data-node-kind="tool|think|context|files|image"`、`data-node-running` | 时间线 `.action-timeline-*`、思考块（解锁"思考中金色扫光"类状态动画） |
| 输入框分区 | `data-composer-zone="queue\|attachments\|input\|footer\|popup"` | 排队列表/附件托盘/text 行/工具栏/浮层菜单（同时给 #3 一个"不得改 position"的语义约定） |
| 空态 | `data-pane="landing"`（新增取值） | `.empty-workspace` 容器 |
| 面板 token 分解 | `--panel-bg-sidebar/topbar/composer/dialog/preview`（原 `--panel-bg` 作别名） | `styles.css` 壁纸模式规则引用 |
| 状态扩充 | `data-ui-sidebar-view="topics\|files\|agents"`、`data-ui-attachments` | App 已有对应 state，`dataset` 一行 |

### P2（暂缓）

## 三、skill / 检查器优化项

### S1 新增"陷阱清单"章节（首选）
内容：特异性阶梯怎么算；已知撞名类（`.agent-list` 修复前）；`> *` 位置覆盖的危险；输入框 `min-height`/`1fr` 语义；`--panel-bg` 共享 token 的区域覆写模式；壁纸/气泡/面板三滑块的运行时覆盖路径。**本次所有排除法时间都能省在这。**

### S2 checker 升级为"静态断言 + 轻量真解析"
- 警告类：`[data-pane="x"] > *` 中出现 `position`/`z-index`；`[data-pane="composer"]` 上 `min-height` > 阈值（如 160px）；`html` 前缀提示。
- 真解析（引入 `tinycss2`）：现在为正则解析，`border-image-slice` 与素材尺寸不匹配、`background` 简写分层错乱、`calc()` 语法错误等"AI 最易写错、Chromium 静默失败"的问题查不出。真解析后：slice 数值 ≤ 素材尺寸、`--pi-layer-*` 值过 CSS 语法树、`@media` 嵌套合法。

### S3 recipes.md 收录本次实战技法
九宫格镂空画框 + `fill`、多背景四角画框（预镜像素材 vs overlay 层 transform 两条路线）、`mask-image` 列表渐隐、`order` 纵列重排、暗色立绘双文件方案——都有真实样张背书。

### S4 素材预处理模板
技能内提供一键脚本模板（Pillow/Sharp 镜像、调暗、切片导出），写入"素材无法变形时用脚本生成变体随目录导入"的官方路径（与 P0-4 双轨：有脚本 → 资产变体；无脚本 → 层属性 filter/transform）。

## 五、明确"不要改"

- token 体系与双模式选择器（`data-theme-effective`）——已验证稳定
- `--pi-layer-*` 声明层机制本身（值走 CSS 级联、可状态/模式切换）——只扩属性，不换机制
- 主题 = 纯 CSS + 资产目录的边界（禁止 JS/DOM 注入）——这是与 DSH 皮肤的本质差异，也是可移植性所在
- 检查器的 structural 放宽模式与对比度/钩子名校验
