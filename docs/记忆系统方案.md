# PiDesktop 记忆系统实施方案（v2，对齐 dsh 缓存哲学）

> 状态：已实现（2026-08-19，分支 feat/memory-system；npm test 320 用例全绿、npm run build 通过；打包冒烟待手动验证）。
> 背景：分析过 GenericAgent（四层金字塔记忆 + 存在性索引）与 Proma（知识路由 + 提示词治理）两个开源项目的记忆模块后定稿。
> 落地偏差一处：面板入口采用会话区右上方浮球（与 task-panel 同族，`data-control="memory-toggle"`），未放顶栏 runtime-controls——与任务面板形态一致、App.tsx 改动最小。

## 核心原则（延续 todo 重写的方向）

**动态状态不进系统提示词；一切变化通过工具调用参数/结果出现在对话尾部（纯追加，不破坏前缀 KV cache）。** 系统提示词只含字节冻结的会话级常量。

记忆索引的特殊性：它是**跨会话的加载态**而非会话内的变化态（变化稀疏——只在记忆写入时变）。因此：

- **会话创建时一次性快照注入索引**：在 `createSession` 里取 `indexMarkdown(workspace)` 存入闭包变量，`systemPromptOverride` 拼入。整个会话字节不变 → **会话内缓存零扰动**；跨会话只有索引真变了才不同（新会话本来就是新前缀）。与 skillsBlock（`pi-runtime.ts` 的 systemPromptOverride 组装处）同类：会话级常量。
- **会话内新鲜度走工具输出**：`memory_write` 的结果回显该主题的最新索引行（不回整个索引，照 todo "结果只回计数" 的克制）；需要全量时 `memory_list`。工具结果在历史尾部，追加不破坏前缀。
- **没有 `before_agent_start` 每轮注入**，不建 context extension。
- 面板手改记忆（IPC 直改 store，不经过模型上下文）后，本会话快照不更新、下个会话生效——接受，工具输出始终权威。

## 存储布局

```
<agentDir>/pidesktop-memory/<agentId>/     # 每助手一份，跨会话
├── MEMORY.md                              # 派生索引（store 自动再生成，供人浏览）
└── topics/<id>.md                         # frontmatter: title/description/workspace?/createdAt/updatedAt + markdown 正文
```

- 主题文件为记忆单元（用户偏好 / 协作纠错 / 项目约定 / 决策理由）
- 索引由 store 派生，模型不维护（无 GA 式同步漂移）；注入用索引 = 全局主题 + 匹配当前工作区的主题，40 行安全截断
- 治理规则（静态字节，进系统提示词）：只记验证过的稳定信息；禁存易变状态/可推理常识/单次行为推断/凭证；写前先 `memory_read`、整主题替换不得丢既有要点；删除或大段改写先在对话中向用户确认，普通写入直接做、事后一句话告知；时间敏感内容标注日期；主题超过 ~15 个主动合并

## 工具（utility process customTools，不过权限门，tool-audit 自动覆盖）

- `memory_write(topic, description, content, workspace_scoped?)` —— dsh 式整主题替换（按 topic 匹配 upsert），参数即状态、在对话尾部；结果只回「已保存主题 X + 该主题索引行 + 主题总数」
- `memory_read(topic)` / `memory_list()` / `memory_search(query)`（标题命中优先，前 5 条带片段）/ `memory_delete(topic)`
- 每个 execute 先查 `settings.memory.enabled`，停用时返回提示文本（工具保持注册，开关即时生效不重建会话）

## v3 重构（2026-10-18）

**触发**：真实记忆库 22 个主题 / 16.0 万字符；会话记录里 memory_read 363 次共 299 万字符、memory_write 203 次参数共 179 万字符（67 次重写「踩坑记录」花 93 万字符），而 memory_search 只有 14 次。结论：索引快照不是主要成本，**整篇读/整篇写**才是；存储格式不必推翻，重构索引、检索、读写三层。

**用户对齐的 5 项**：全套重构；大主题 read 默认回目录；新增 memory_append；面板摘要化 + 正文按需读；本地词法检索（中文 bigram + BM25 风格，零依赖）。

### 数据与缓存
- 存储布局不变：`pidesktop-memory/<agentId>/topics/<id>.md` + 派生 `MEMORY.md`；旧文件零迁移。
- store 按文件 mtime+size 增量缓存解析结果；写后更新缓存并 bump revision；搜索索引按 revision+workspace 缓存。
- 摘要 `MemoryTopicSummary` 不携带正文，增加 `contentChars` 与 FNV-1a `contentRevision`；`MemoryTopic` = 摘要 + 正文。
- 写操作（save/append/remove）经 `<dir>/.write.lock` 串行化：token 校验释放、rename 清理陈旧锁（避免误删新锁）；append 在锁内重新读文件。

### 分节与读取
- `memory-sections.ts` 解析行首 H2/H3（跳过围栏代码），H2 的 end 覆盖其 H3 子节；前言生成「概述」；无标题主题按段落切 `片段 N`（4000 字）；无子节的大节也切片段。
- `memory_read`：`section="*"` 读全文；小主题（≤6000 字）默认全文；大主题默认目录（节标题、字数、首行预览），按编号/标题片段读单节。
- `memory_append`：命中节 → 插到节末尾；未命中且非纯数字 → 文末新建 `## section`；缺省 → 文末。父节被切片段时，按父标题追加落到最后一段之后。

### 检索
- 中文连续段生成 bigram，ASCII 按 `[a-z0-9]+`；查询/文档共用分词。
- 分节 BM25（k1=1.2, b=0.75）+ 标题 ×3 / 描述 ×2 / 短语加成；每主题最多 2 个分节命中，有分节命中则不再返回主题级命中。
- 长查询要求至少 1/3 词命中（≥2 个）且 IDF 覆盖率 ≥50%，避免「绝对不存在的关键词」被常见 bigram 蒙中；短查询允许单词命中。
- 片段在原文下标上定位（只用小写化，不做 NFKC 偏移），避免变长归一化切错位置。

### 预算索引
- `snapshotMarkdown(workspace, 2000)`：组内按 updatedAt 降序；每条依次尝试 48 字描述、24 字描述、仅标题；放不下就省略并写「另有 M 个未列出，用 memory_search…」脚注。
- `buildMemorySnapshotBlock` 不再按 40 行二次截断；磁盘 `MEMORY.md` 仍写全量索引。
- 快照仍在会话创建时冻结，保持前缀缓存纪律。

### 面板与 IPC
- `resources.memory` / `memory` 推送只带摘要（此前 `resources` 在 todo/skill/MCP 等变更时也会携带全部正文，16 万字符/次）。
- 新增 `memory.read` 命令与 `memory.topic`/`memory.topic-error` 消息；预览打开时按需拉正文，`memoryContents` 按 revision 失效。
- 面板新增本地筛选、总字数、单主题体积与「偏大」（>12000 字）徽标。

### 验证
- 真实库副本探针：快照 1435 字符（预算 2000）；搜索热路径 2.1ms、冷路径 30ms（首次建索引）；最大主题 18.8k 字 → 6 段目录 459 字符、单段 2.5k 字；假查询 0 命中。
- 新增 `memory-sections.test.ts`、`memory-store.v3.test.ts`、`runtime-memory-tools.v3.test.ts`、`MemoryPanel.test.tsx`、`MemoryPreview.test.tsx`；`npm test` 2662 项 / 227 文件 + `npm run build` 全绿。
- 独立审查发现并修复 P1：预览 tab 切换时组件复用会把上一主题正文写进当前主题（`ArtifactPreview` 加 `key={topicId}` + 预览兜底校验 id）。

### 边界
- 只做本地词法检索，不做 embedding/语义；几 MB 级记忆库适合，几十 MB 需另评估磁盘索引。
- 无数据迁移；新工具/命令需重启应用注册。
- 同大小且同 mtime 的外部原位改写不可见（原子写会刷新 mtime），为既定取舍。

## v4 分层（2026-11-05）

**触发**：v3 已把「整篇读写」拆成「目录 / 分节 / append」，但实测仍有三个问题——
① 单次 read p50 2,002 字、p90 5,887 字、max 24,063 字，18 次 `section="*"` 单次 1.1–2.4 万字；
② 读取成本 61% 集中在 3 个主题（业务知识 41%、会变的状态 11%、纪律 9%），它们和其余 24 个主题
用同一种读取方式；
③ 索引 1,905/2,000 字已顶预算，所有主题等权，再加主题就开始丢条目。

结论：**分层的对象不是文件，而是信息的寿命与使用频率**。v4 只解决三件事：召回准确率、
召回体积、重复召回；不引入向量 / 后台蒸馏 / 每轮自动召回。

### 3+1 层结构

| 层 | 内容 | 预算 |
| --- | --- | --- |
| 索引（每会话一次） | core：标题 + 要点；standard：标题 + ≤24 字描述或触发词；archive：只留计数 | 2,000 字 |
| 要点（summary） | 3–8 行结论，≤400 字；缺省时由「概述首段 + 首句」规则派生 | 400 字 |
| 正文（分节） | H2/H3，单节 ≤4,000 字；`section="*"` 封顶 12,000 字并显式截断 | 4,000 / 12,000 |
| 归档（layer） | 不进索引，`memory_search` 可达，read 标「已归档」 | — |

### 数据模型（向后兼容）

frontmatter 新增三个可选字段，缺省按 standard / 无要点 / 无触发词处理，老文件零迁移：

- `layer: core | standard | archive`
- `summary`: 单行要点（多行按 ` · ` 连接）
- `triggers`: 反直觉触发词（≤3 个，每个 ≤12 字）

### 读取与检索

- `memory_read` 默认：正文 ≤1,200 字给全文；否则「要点 + 目录」≤1,300 字；单节 ≤4,000 字；
  `section="*"` ≤12,000 字（超出截断并给续读路径）。所有截断都写明原因。
- `memory_search`：单条 ≤260 字、单次 ≤1,200 字；标题/触发词 ×3、描述 ×2、节标题 ×1.5；
  30 天半衰、7 天内更新的主题免疫（只排序，不删数据）；已读节标 `[已读]` 且不再给片段。
- 会话内已读表：键 = 主题 id + 节；容量 40、TTL 20 分钟；重复读回一行提示，`refresh=true` 强制重看。
  不承担正确性（压缩/编辑后内容可能已不在上下文），所以有 TTL 与逃生口。

### 写入纪律

治理块补「无行动不记忆」：只写成功工具调用或用户明确陈述；core 只放每会话都在场的偏好/纪律/会变状态；
一主题一件事；正文 >8,000 字提示拆分、>12,000 字索引自动降级为标题；summary 3–8 行、triggers 只放反直觉词。

### 面板

- 记忆页改为卡片列表（层徽标 + 要点预览 + 字数/日期/作用域 + 归档/删除），可按层筛选。
- 新增记忆中心（`MemoryCenter.tsx`）：卡片墙 + 搜索/分层/排序；右侧详情可改层、索引描述、要点、触发词；
  「模型索引」tab 用 `memory.indexPreview` 展示新会话会注入的索引与预算占用（与会话注入同一函数）。

### 验证与边界

- `npm test` 3,474 项 / 309 文件 + build 全绿；新增 store/tools v4 14 例、中心 5 例、接线 4 例。
- 真实库（27 主题 / 20.6 万字）索引从 1,905 字降到约 1.4–1.6k（core 要点 + standard 24 字 + 归档计数），
  可支撑 35–40 个主题。
- 顺带修 `parseFrontmatter` 键名小写导致 `createdAt/updatedAt` 永远读不到的旧 bug（重启后日期重置、排序失效）。
- 不做：向量 / embedding、LLM 蒸馏、每轮自动召回、跨会话已注入持久化；当前会话索引仍在创建时冻结。
