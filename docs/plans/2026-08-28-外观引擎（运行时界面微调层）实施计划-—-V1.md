# 外观引擎（运行时界面微调层）实施计划 — V1

## 背景与目标
PiDesktop 用户现在只能换整套主题 + 壁纸/气泡/面板透明度滑杆，不能微调界面本身。本步参考 VCPChat 的 `appearance-engine.js`，引入一个「**主题之上、运行时可调**」的微调层：**不改主题**也能调**界面密度**与**圆角**。原则与现有主题体系并存——默认值 = 当前视觉现状，主题可覆盖 token，向后兼容。

## V1 范围（推荐：密度 + 圆角）
只做两个感知最强、变量化可控的维度：
- **density（密度）**：`compact / comfortable / relaxed` → 侧栏列表行高、主控件（按钮/输入/图标钮）高度。
- **radius（圆角）**：`square / small / medium / round` → 控件圆角（`--ui-control-radius`，默认 6px）+ 容器圆角（`--ui-container-radius`，默认 10px）。

**不做（留待后续）**：fontScale、contentWidth（消息宽度）、每区域独立圆角、surfaceEffect/材质光学（opacity/blur/亮度）、typography。

### 为什么不全做
VCPChat 完整引擎（材质光学、每区域圆角、classic/next 预设）对 PiDesktop 是一次大重构：styles.css 数百处尺寸/圆角硬编码要变量化，且与「每主题一套变量」的主题体系叠加、回归风险高。V1 只拿感知最强、改动可控的两项，先验证「运行时微调层」这个模式成立，再逐步扩展其余维度（每次一个小步、可回退）。

## 实施步骤

### 1. 协议（`src/shared/protocol.ts`）
`AppearanceSettings` 新增可选 `tune?: InterfaceTuning`：
```ts
interface InterfaceTuning {
  density?: "compact" | "comfortable" | "relaxed";
  radius?: "square" | "small" | "medium" | "round";
}
```
默认 `undefined`（跟随主题/默认，旧数据无此字段不受影响）。

### 2. 设置规范化（`src/main/settings.ts`）
- `defaultAppearance()` 不带 `tune`。
- `migrateSettings()` 校验 `tune`：density/radius 取各自合法集合，非法值丢弃；`showThinking` 等既有逻辑不动。
- `src/main/settings.test.ts` 补：合法集合 / 非法丢弃 / 缺失默认。

### 3. 渲染端投影 + 设置面板（`src/renderer/src/App.tsx`）
- 在现有「project UI state onto document root」effect 里，复用 `data-ui-sidebar-view` 的带值状态模式，新增：
  `["data-ui-density", tune?.density]`、`["data-ui-radius", tune?.radius]`（仅当有设置值才写 `<html>` 属性）。
- 设置对话框「外观」区块新增「界面」小节：密度下拉（紧凑/舒适/宽松）+ 圆角下拉（方角/小圆/中圆/圆润），保存走现有 `appearance.save`。

### 4. 样式 token（`src/renderer/src/styles.css`）
- `:root` 定义（默认值 = 当前视觉现状）：
  - `--ui-control-radius: 6px;` / `--ui-container-radius: 10px;`
  - `--ui-list-row: 48px;`（侧栏列表行高基准）/ `--ui-control-height: 32px;`（主控件高度基准）
- `data-ui-density` / `data-ui-radius` 覆写：
  - compact → `--ui-list-row:40px; --ui-control-height:28px;`
  - relaxed → `--ui-list-row:56px; --ui-control-height:36px;`
  - square → `--ui-control-radius:0; --ui-container-radius:0;`
  - round → `--ui-control-radius:999px; --ui-container-radius:14px;`
- 把**代表性密度敏感项**的尺寸改引用 token：侧栏 `.session-list button`/`.agent-list button`/`.sidebar-tabs button`/`.sidebar-footer button`/`.workspace-tree-row`、`.icon-button`。
- 把**主要控件/容器**的 `border-radius` 改引用 token：按钮、输入框、chip、context-menu、composer、气泡、菜单弹层。
- **保持默认视觉不变**：默认下 `--ui-list-row:48px`、`--ui-control-radius:6px` 等 = 现值；未加 data 属性时主题/默认完全不受影响。

### 5. 主题契约（`AGENTS.md` + `docs/theme-guide.md`）
theme-guide「UI 状态」段与 AGENTS.md 主题 bullet 新增 `data-ui-density`/`data-ui-radius`（带值状态；主题可忽略、可覆盖 `--ui-*-radius`/`--ui-list-row`）。

### 6. demo-api.ts
默认 appearance 同步（不带 tune 或默认值），演示一致。

### 7. 测试
- `settings.test.ts` 补 `migrate` 对 tune 的校验用例。
- 现有 theme-presets / 渲染测试不受影响。

## 验证
- `npm test` 全绿。
- `npm run build` 全绿。

## 风险与假设
- 变量化**不改变默认视觉**（默认值 = 现值），现有主题与默认不受影响。
- 新增 token / 属性是公开 API；旧主题不引用即忽略，兼容。
- radius 替换是纯 CSS 机械替换、易走样——用「默认=现值」+「只改有代表性的控件/容器」控制风险；某处若走样可单独回退该处。
- **分阶段**：确认 V1 模式可行后再扩展其余维度（每个维度一个小步）。

## 产出交付
协议字段、设置规范化+测试、App 投影+设置面板、styles.css token+引用、主题契约、demo 同步；`npm test`+`build` 全绿后更新迭代记录并提交。
