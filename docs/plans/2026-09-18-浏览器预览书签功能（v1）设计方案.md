# 浏览器预览书签功能（v1）设计方案

> 状态：**已实施**（2026-09-18，v1）。实现与验证摘要见 `docs/迭代记录/2026-09.md` 的 2026-09-18 条目。
> 日期：2026-09-18

## 1. 背景与目标

PiDesktop 右侧面板的浏览器预览（`src/renderer/src/components/BrowserPreview.tsx`）目前只有 地址栏 + 后退/前进/刷新/设备视口/元素选择/外部打开，没有书签。用户常访问的网址（内网系统、localhost 调试页、文档站点）每次都要重新输入。

目标：用户可把当前页收藏为书签，之后从书签面板一键打开。

## 2. 现状调研结论（已核实）

- **工具栏布局**：`BrowserPreview.tsx` 的 toolbar 为 grid，列定义为 `29px 29px 29px auto minmax(0,1fr) 29px 29px`（styles.css:1534 附近）：后退、前进、刷新 | 设备菜单(auto) | 地址栏(1fr) | 选元素、外开。
- **现成下拉菜单模式**：`PreviewDeviceMenu.tsx` —— rootRef + open state、外部 pointerdown 关闭、Escape 关闭（capture）、`onMenuOpenChange` 向上抛。
- **关键约束（native 视图遮挡）**：浏览器预览的 native WebContentsView 悬浮在所有 DOM 之上，任何下拉面板打开时必须临时隐藏 native 视图。BrowserPreview 已有机制：`useEffect` 里 `visible: !suspended && !deviceMenuOpen`，书签菜单的开关必须同样纳入这个 effect。
- **持久化既有模式**：`src/renderer/src/lib/browser-address.ts` —— 渲染端 localStorage + 可单测的纯读写层 + happy-dom 单测（`browser-address.test.ts`），storage 不可用时静默降级不抛错。
- **页面状态来源**：当前页 `url` / `title` 由主进程经 `BrowserPreviewState` 推送（`onBrowserPreviewState`），收藏当前页时直接取 `state.url` + `state.title`，无需新协议。
- **导航路径**：表单提交走 `send({ type: "navigate", url })`，成功后 `setAddress(next.url)` + `saveBrowserAddress(tabId, next.url)` 同步地址栏。书签打开复用同一逻辑。

## 3. 设计决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 实现位置 | **纯渲染端**，不动主进程 / IPC 协议 | 书签只是 UI 快捷方式，无后端参与必要，改动面最小 |
| 存储介质 | 主窗口 localStorage，key `pidesktop.browser-bookmarks` | 沿用 browser-address 既有模式；主窗口 partition 持久化，跨工作区共享 |
| 书签作用域 | 全局共享，**不按浏览器标签 tabId 隔分** | 符合书签语义（浏览器书签也是全局的），多个浏览器标签都能用同一份 |
| 图标 | 首字母色块（域名首字母 + 域名 hash → hue） | 不依赖 favicon 在线服务；内网站点 / 离线场景均可用 |
| 触发交互 | 星标按钮固定在地址栏右侧第一位；点击**永远弹面板**，面板首项为「收藏/取消收藏当前页」 | 交互统一、防误触取消（参考 Chrome：点星标是弹卡片而非直接取消）；已收藏时星标实心高亮 |
| 删除交互 | 行 hover 出现 X，直接删，不弹确认 | 书签丢失成本低，重新收藏即可 |
| v1 不做 | 标题编辑、拖拽排序、文件夹/分组、地址栏内联建议、AI 管理书签的协议扩展 | 保持 MVP 精简，交互成本低；后续有需要再迭代 v2 |

## 4. 数据模型

```ts
export interface BrowserBookmark {
  id: string;        // crypto.randomUUID()，不可用时降级 Date.now()+random
  title: string;     // 页面 title；无 title 时用域名
  url: string;
  addedAt: number;   // 新书签插列表最前
}
```

localStorage 存 JSON 数组（key 见上）。同 URL 去重策略：**完整 URL 字符串比较**（不做规范化——可预测、实现简单）；收藏已存在的 URL → 更新标题并置顶，不新增条目。

## 5. 实施步骤

### 5.1 新增 `src/renderer/src/lib/browser-bookmarks.ts`（纯读写层）

- `storedBrowserBookmarks(): BrowserBookmark[]` —— 读 localStorage；JSON 解析失败 / 数据非数组 → 返回 `[]`；storage 本身不可用（getter 抛错）→ 静默返回 `[]`（与 browser-address 同款防御）。
- `addBrowserBookmark(url: string, title?: string): BrowserBookmark | undefined` —— trim 后空 URL 返回 undefined；同 URL 已存在则更新标题 + 置顶；否则新建并插最前；返回该书签。
- `removeBrowserBookmark(id: string): void` —— 按 id 删；写失败静默。
- `bookmarkGlyph(url: string): { letter: string; hue: number }` —— 域名首字母（大写）+ 域名字符串 hash 映射 0–360 hue；纯函数。
- 单测 `browser-bookmarks.test.ts`（`// @vitest-environment happy-dom`，参考 browser-address.test.ts）：
  - 增删查 round-trip
  - 同 URL 去重：不新增、标题刷新、置顶
  - 空 URL / 空白 URL 拒绝
  - 坏数据容错：localStorage 里塞非法 JSON / 非数组结构 → `[]` 不抛
  - storage 不可用降级：`Object.defineProperty(window, "localStorage", { get(){ throw } })` 下读写均不抛
  - glyph：同一 URL 结果稳定；不同域名 hue 分布在 0–360

### 5.2 新增 `src/renderer/src/components/BrowserBookmarksMenu.tsx`

骨架参考 `PreviewDeviceMenu.tsx`（rootRef + open + pointerdown/Escape 关闭 + onMenuOpenChange）：

- Props：
  ```ts
  {
    currentUrl: string;      // 来自 BrowserPreviewState，空串表示未导航
    currentTitle: string;
    onNavigate(url: string): void;
    onMenuOpenChange?(open: boolean): void;
  }
  ```
- 面板内容（自上而下）：
  1. 首项「收藏当前页」/「取消收藏此页」（Star 图标 + 文案随收藏态切换；`currentUrl` 为空时禁用并提示「先打开一个页面」）
  2. 分隔线（复用 `.preview-device-sep` 样式思路）
  3. 书签列表：行 = 首字母色块 + title（ellipsis）+ 域名小字（secondary）；点击 → `onNavigate(url)` + 关闭面板；行 hover 右侧出现删除 X（点击删除且不关闭面板，便于连续清理）
  4. 空状态：「还没有书签，先收藏一个页面吧」
- 书签列表本地 `useState`（挂载 / 打开时从 `storedBrowserBookmarks()` 读取；增删后重读同步）。
- 列表区 `max-height` + `overflow-y: auto`（书签多时可滚动）。

### 5.3 修改 `src/renderer/src/components/BrowserPreview.tsx`

- 新增 state `bookmarksMenuOpen`。
- **visible effect 改为**：`visible: !suspended && !deviceMenuOpen && !bookmarksMenuOpen`（native 视图遮挡防护，必须改）。
- 工具栏地址栏右侧、元素选择按钮左侧插入 `<BrowserBookmarksMenu>`，传 `currentUrl={state.url}`、`currentTitle={state.title}`。
- `onNavigate`：调 `send({ type: "navigate", url })`，成功后 `setAddress(next.url)` + `saveBrowserAddress(tabId, next.url)`（与现有表单导航完全一致）；导航后关闭面板（面板内部已处理关闭，这里只管导航）。

### 5.4 修改 `src/renderer/src/styles.css`

- `.browser-preview-toolbar` 的 `grid-template-columns` 加一列：`29px 29px 29px auto minmax(0, 1fr) 29px 29px 29px`（星标插在地址栏后第一个 29px）。
- `.browser-bookmarks-pop`：参考 `.preview-device-pop`（absolute、z-30、`top: calc(100% + 6px)`、圆角 10px、`var(--shadow-lg)`、语义变量配色）；**右对齐 `right: 0`**（按钮位于工具栏右端，左对齐会超出面板）；宽约 280px。
- 书签行样式（flex、hover 背景、色块 `hsl(hue 45% 45%)` 圆角方块白字、title ellipsis、域名 `--text-muted` 10px、删除 X 默认透明 hover 显现）。
- 空状态（居中、`--text-muted`、11px）。
- 已收藏态星标：`.browser-bookmarks-menu > button.active`（实心填充色，参考 `.preview-device-menu > button.active` 的 accent 处理，可用 warning/accent 语义变量）。

## 6. 验证方式

1. `npx vitest run src/renderer/src/lib/browser-bookmarks.test.ts` —— 数据层单测全绿。
2. `npm run build`（tsc 双 project noEmit + electron-vite build）—— 类型与构建通过。
3. 手动验证（`npm run dev`）：
   - 打开页面 → 收藏当前页 → 星标实心高亮；**重启应用书签仍在**（localStorage 持久化）。
   - 点击书签 → 正确导航，地址栏同步显示目标 URL。
   - 同 URL 再收藏 → 列表不重复，标题刷新为最新。
   - 面板打开时 native 页面临时隐藏、面板可读可点；关闭后页面恢复（遮挡防护生效）。
   - Escape / 点击面板外部关闭；书签为空时展示空状态。
   - hover 行 → X 出现 → 点击删除成功，面板不关。
   - 明暗两种主题下面板可读（全用语义变量，理论上自动适配，肉眼过一遍）。

## 7. 风险与假设

- localStorage 属主窗口 partition → 书签**跨工作区共享**：这是预期行为（书签语义），如未来要按工作区隔离再迭代。
- 书签仅存 url/title，无 favicon、无网络依赖，内网环境安全。
- 书签功能与 AI 的 `browser_navigate` 完全解耦，互不影响；未来若要 AI 读写书签（如「帮我把这页加书签」），需扩展 `BrowserPreviewCommand` 协议 + 主进程桥接 localStorage——超出 v1 范围，设计上不阻塞。
- 组件级测试不写（项目内 PreviewDeviceMenu 等同类下拉组件也无常驻组件测试），核心逻辑全部收敛在 lib 纯函数层保证覆盖。
