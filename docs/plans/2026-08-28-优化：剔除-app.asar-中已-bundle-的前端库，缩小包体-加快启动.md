# 优化：剔除 app.asar 中已 bundle 的前端库，缩小包体 / 加快启动

## 背景与目标
- 现状：`dist/win-unpacked` 共 689MB，其中 `resources/app.asar` 高达 **295MB**。巨大冗余来自——mermaid/katex/highlight/react/remark-rehype/vditor/zustand/lucide 等**前端库及其整棵依赖树**（如 mermaid→@iconify/utils→@antfu/install-pkg、cytoscape 等）被 electron-builder 打进 asar；但这些库早已被 vite **烧进 `out/renderer` 的 JS chunk**（能看到 `mermaid.core.js`、`katex-*.js`、5.4MB 主入口）。
- 目标：让这些「仅 renderer 使用、已被 bundle」的库**不再被 electron-builder 打进 app.asar**，从而大幅缩小包体；便携版每次解压的体积也随之下滑（启动更快），并**顺带消除**此前 `@antfu/install-pkg`（mermaid 传递依赖）引发的 portable 打包 `ENOENT` bug。
- 注意边界：此优化**不改变** renderer 主 bundle 体积（那部分已烧死在 chunk 里），所以**对「目录版」启动提速有限**；最大收益是**便携版解压提速 + 分发体积大幅缩小 + 冷启动略快**。诚实说明，避免预期过高。

## 调研结论（已用 grep 实证）
- `src/main`（含 Pi 运行时入口 pi-runtime.ts）、`src/preload`、`src/shared` 对下述前端库**零引用**。
- 前端库仅在 `src/renderer` 被引用，且已被 vite 打进 `out/renderer` bundle；运行时用的是 bundle 里的代码，不需要 node_modules 副本。

### 依赖归类（改 package.json）
**保留 `dependencies`（运行时被主进程/preload/Pi 运行时 require，绝不能动）**
- `@earendil-works/pi-agent-core`、`@earendil-works/pi-ai`、`@earendil-works/pi-coding-agent`（utility 运行时，externalized）
- `@modelcontextprotocol/sdk`（MCP 客户端）
- `node-pty`（主进程终端，native）
- `strip-json-comments`（hooks-config / mcp-config 的 JSONC 解析）
- `typebox`（runtime-* 工具 schema / MCP / subagent）

**移入 `devDependencies`（纯 renderer bundle 用）**
- `@xterm/xterm`、`@xterm/addon-fit`（终端渲染，TerminalPanel.tsx）
- `highlight.js`、`katex`、`lucide-react`、`mermaid`、`react`、`react-dom`
- `react-markdown`、`rehype-katex`、`rehype-raw`、`rehype-sanitize`、`remark-gfm`、`remark-math`
- `vditor`、`zustand`

## 实施步骤
1. 新建分支 `feat/slim-asar`（功能/优化类的分支纪律；不在 main 上直接改）。
2. 改 `package.json`：把上述 17 个包从 `dependencies` 移到 `devDependencies`；`overrides`、`build` 配置、`engines` 保持不变。
3. `npm install --package-lock-only`（仅更新 lock 的归类，不重装 node_modules、不触发网络重装）。
4. `npm test` 全绿。
5. `npm run build` 全绿（含 tsc 双校验 + vite build + copyVditorAssets——开发机 node_modules 完整，vditor 资源仍能从 `node_modules/vditor/dist` 拷入 `out`）。
6. 重打 dir 包 `npm run package:win`，**确认三点**：① `app.asar` 体积大幅下降（预期从 295MB 降到几十 MB）；② 不再出现 `@antfu/install-pkg` 打包报错；③ `out` 下 `lib/vditor/dist` 仍进产物。
7. 交给用户做内网冒烟（终端/剪贴板/图表 mermaid/KaTeX/Markdown 渲染），确认功能无损。
8. 更新 `docs/迭代记录.md`（加一条实现摘要，含日期），并按仓库规范 commit（`feat(build): 剔除已bundle前端库缩小asar`）。**仅 add** `package.json`、`package-lock.json`、`docs/迭代记录.md`。

## 验证方式
- `npm test`、`npm run build` 全绿；重打包无 `@antfu/install-pkg` 报错；`app.asar` 体积明显缩小。
- 用户侧冒烟：终端、剪贴板、mermaid 图表、KaTeX、Markdown、VDitor 渲染，确认功能完整。

## 风险与假设
- 假设：这些库只在 renderer 用、已被 vite bundle（已 grep 实证，风险低）。
- 风险1：万一某库被 main/preload 运行时 require（grep 已排除，概率极低）→ build 会报「找不到模块」，我会停下来如实上报，不硬闯。
- 风险2：`npm install --package-lock-only` 可能因环境/网络失败 → 若失败，退为手动修正 lock 或如实上报。
- 提交纪律：本次只动 `package.json` / `package-lock.json` / `docs/迭代记录.md`；工作区既有的 `AGENTS.md / src/main/pi-runtime.ts / src/main/session-scope.*` 是**他人的未提交改动**，一律不 add、不卷入。
- 范围边界：不做 renderer bundle 进一步的代码分割/懒加载（那是另一个更大的任务，且会动大量组件，超出本次范围）；不删 wall paper 资源（涉及功能/美观取舍）。

## 交付物
缩小后的 `dist/win-unpacked`（体积明显下降）与**对应的这次优化说明**；如需可再出一版缩小后的 portable 单文件。
