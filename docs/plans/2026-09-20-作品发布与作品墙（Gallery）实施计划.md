# 作品发布与作品墙（Gallery）实施计划

## 一、背景与目标

**需求来源**：用户图示需求——顶栏新增一个下拉按钮，主区域空态展示"我们用 AI 开发的小程序（小网页、小 demo 等）"，点击可**运行**，也可**持续优化**。

**要解决的问题**：目前用 AI 做出来的成果全是散落文件（`designs/exports/*.html`、根目录 `*.html`、`outputs/…`、`npm run dev` 起的服务），做完就沉底：既看不到，也回不去。"作品墙"把成品变成**一等公民**——可反复运行、可一键回到开发流程。

**已与用户对齐的决策（5 项，均已确认）**：

| # | 决策 | 结论 |
|---|---|---|
| 1 | 什么算作品 | **显式发布动作**：AI 工具封装发布 + 实体按钮，发布即登记。不做自动扫描（作品墙只收用户认可的成品，不会脏） |
| 2 | 入口位置 | **顶栏下拉为主入口 + 空态作品墙**（空态只在「有工作区+无消息+非生成中」出现，聊过一句就消失，所以顶栏必须是常驻主入口） |
| 3 | 运行路线 | **一律走内置浏览器 + 本地静态服务**（能力最全：console/网络/多文件/localStorage/fetch 全可用；沙箱预览只跑得了单文件且有 origin 限制） |
| 4 | 清单作用域 | **全局跨工作区**（一个池子，换工作区也在） |
| 5 | 登记数据形态 | **统一记「入口」**：工作区 + 入口路径（文件或目录）+ 可选启动命令/URL |
| 6 | AI 工具激活 | **永远激活**（1 个轻量工具，约 200 tokens/请求） |
| 7 | 缩略图存放 | **全局作品目录** `<agentDir>/pidesktop-gallery/thumbs/`（跨工作区不失效、不受现有 20 张截图保留策略影响） |
| 8 | 继续开发 | 注入当前会话 composer 当作 `@` 引用（复用现成链路） |

**用户特别纠正的一点**（重要）：**作品不一定单文件**——可能是一整个目录、甚至一个服务型项目。因此登记模型以「入口」为中心同时容纳三种形态，实体发布按钮也**不限于文件**（文件树右键、目录右键、交付产物行、预览工具栏、顶栏下拉「登记新作品」都要有）。

### 硬约束与坑（必须绕开）

1. **沙箱 iframe 不能当运行通道** —— `artifactSandbox`（`lib/content.ts:293-295`）**永不同时给** `allow-scripts` 与 `allow-same-origin`（安全不变量，`content.test.ts:39-48` 钉住）。已按用户决策走内置浏览器，规避此约束。
2. **`.pidesktop/screenshots/` 只有 20 张保留上限**（`browser-screenshot.ts:24-25`），且是工作区相对路径 → 换工作区失效。已按用户决策改用全局目录。
3. **`migrateSettings` 漏字段 = 静默删除**（`settings.ts:433-437` 血泪注释）→ 清单**绝不放进 `settings.json`**。
4. **新 `RuntimeCommand` 必须同步 `demo-api.ts:599-1082` 的 switch**，否则 `npm run demo` 静默无反应（有对应测试 `demo-api.test.ts`）。
5. **`pathLeavesWorkspace` 只看 `args.path`/`file_path`/`filePath`**（`permissions.ts:4-10`）→ 新工具写盘字段必须叫 `path` 才能被越界检查覆盖。
6. **`createNewSession` 后立即注入必然静默失败**（`App.tsx:1738-1741` 注释 + 三重时序缺口）→ 本期**不做新开话题注入**（见 §3.8）。
7. **`.empty-conversation` 在两处动画关停列表里**（`styles.css:180-186`、`:191-204`），新增动画要同步。
8. **`data-control`/`data-pane` 是公开主题 API，共 5 处镜像**：`AGENTS.md`、`docs/theme-guide.md`、`pidesktop-theme-creator/SKILL.md`、`check_theme.py` 的 `KNOWN_CONTROLS`/`KNOWN_PANES`、以及源码。**`check_theme.py:76-84` 的 `KNOWN_CONTROLS` 目前根本没有 `design-toggle`/`computer-toggle`/设计工具那批** —— 说明它已落后于 AGENTS.md，本次只补新增钩子，不做全量补齐（超出范围）。
9. **`getAgentDir()` 只在 utility 进程可用**（`pi-runtime.ts` 独有，52 处）。主进程（如缩略图落盘、静态服务）只能自己拼：照 `index.ts:96-97` 用 `join(homedir(), ".pi", "agent")`（`runtime-skills.ts:28` / `runtime-computer.ts:84` 已有 `homedir()` 先例）。
10. **`launch 服务 → 轮询就绪`不可靠**：`BrowserStaticServer` 与内置浏览器只服务**静态文件**，不能拉起 dev server 并等端口就绪。本期**不自动拉起进程**，改为「运行」时打开终端 tab 并预填命令（用户回车）。

## 三、实施步骤

### 3.1 shared 层：数据模型与纯函数（新增 `src/shared/gallery.ts` + `gallery.test.ts`）

**作品条目**（`GalleryApp`）：

```ts
export type GalleryKind = "file" | "server";

export interface GalleryApp {
  id: string;              // 稳定 id（randomUUID，发布时生成）
  title: string;
  description?: string;
  kind: GalleryKind;
  workspace: string;       // 绝对路径（运行、继续开发、打开文件都靠它）
  /** 入口：kind=file 时是工作区相对路径（.html 等）；kind=server 时是目录相对路径（"." 表示工作区根）。 */
  entry: string;
  /** kind=server：启动命令（可选，用户在终端里手动回车执行）。 */
  command?: string;
  /** kind=server：服务就绪后的地址（可选，优先于 command 直接打开）。 */
  url?: string;
  thumb?: string;          // 缩略图文件名（全局 thumbs 目录内）
  tags?: string[];
  createdAt: number;
  updatedAt: number;
  lastRunAt?: number;
  order?: number;          // 手动排序（缺省按 updatedAt 倒序）
}
```

**纯函数**（全部无 IO，可单测）：

- `normalizeGalleryApp(value: unknown): GalleryApp | undefined` —— 逐字段校验（比照 `automation-store.ts:26-88`：非法即丢弃、`id` 缺省补 `randomUUID`、`kind` 非法即丢弃、`workspace` 必须非空绝对路径、`updatedAt` 非数即丢弃）。
- `upsertGalleryApp(list, draft): { list: GalleryApp[]; app: GalleryApp }` —— 按 `id` 或 `(workspace, entry, kind)` 去重（**同一入口重复发布 = 更新而非新增**，避免作品墙出重复卡片）。
- `removeGalleryApp(list, id)`、`sortGalleryApps(list, mode)`（`"recent" | "manual"`）。
- `galleryRunTarget(app): { kind: "file"; absolutePath: string } | { kind: "server"; url?: string; directory: string; command?: string }` —— **运行分流判定的唯一来源**，渲染端与主进程共用（避免两处各判一套）。
- `composeGalleryDevMessage(app): string` —— 「继续开发」注入文本块（照 `lib/browser-pick.ts:18-37` 的 `composePickMessage` 形状：`【作品】\n标题：…\n类型：…\n入口：…\n工作区：…` + 提示语）。
- `galleryPreviewUrl(workspace, entry): string` —— 生成静态服务 URL（见 3.3）。

**测试**（`src/shared/gallery.test.ts`，纯 node 环境）：归一化丢弃非法项 / 同入口 upsert 覆盖 / 排序 / 运行分流三种形态 / 注入文本块形状。

### 3.3 主进程：作品运行通道（改 `src/main/browser-preview.ts` + `index.ts`）

**核心改动：给浏览器标签页加「初始地址」能力**（作品「运行」要落到浏览器 tab 上）。

- `BrowserPreviewCommand` 新增 `| { type: "tab-meta"; tabId?: string; initialUrl?: string; galleryId?: string }`（`protocol.ts:675-690`）。
- `BrowserPreviewController` 存 `tabMeta: Map<tabId, {initialUrl?, galleryId?}>`，新增 `tabMeta(tabId)` 读取方法（供主进程拼接运行 URL）。
- **`BrowserPreview` 组件**（`components/BrowserPreview.tsx`）：在 `[tabId]` 重置 effect（`:109-114`）之后新增一个 effect —— 若 sessionStorage 无 `gallery-started-<tabId>` 标记且 `tabMeta.initialUrl` 存在，则 `navigateTo(initialUrl)` 并写标记，保证**同一 tab 切换回来不重复导航**。为此需要一个 `getTabMeta` IPC（直接走已有 `browserPreview:command` 的 `tab-meta` 命令读回即可，无需新通道）。

**「运行」的执行路径**（App.tsx 新增 `runGalleryApp(app)`）：

1. `resetGalleryTab(app)`：找到 `preview.tabs` 中 `target.type === "browser" && target.galleryId === app.id` 的 tab；
   - 存在 → `send({ type: "browser-preview:close" })` 后再新建（丢弃旧 tab → 双保险 reset）；
   - 不存在 → 什么都不做。
2. `id = \`gallery-${app.id}\``，`openPreviewTarget({ type: "browser", id: \`browser-${randomUUID()}\`, title: app.title, initialUrl, galleryId: app.id }, id)`。
   - `PreviewTarget` 的 browser 分支新增可选 `initialUrl?: string; galleryId?: string; title?: string`（`ArtifactPreview.tsx:21`）。
3. `openPreviewTarget` 里对 browser target 且带 `initialUrl` 的：在 `setPreview` 之后 `void window.piDesktop.browserPreview({ type: "tab-meta", tabId, initialUrl, galleryId })`，并把 `saveBrowserAddress(tabId, initialUrl)` 写上（地址栏立即可见，不用等页面加载）。
4. `App` 的 `closePreviewTab`（`:2119-2140`）里，若关闭的 tab 带 `galleryId`，额外发 `{ type: "tab-meta", tabId, initialUrl: undefined }` 清理（防 tabId 复用串味）。

**`initialUrl` 的生成**（按 `galleryRunTarget` 分流）：

- `kind === "file"`：需要**静态服务 URL**。新增 `RuntimeCommand | { type: "gallery.previewUrl"; requestId: string; workspace: string; entry: string }`，utility 侧走 `BrowserAutomationController.resolveNavigationTarget(绝对路径, workspace)`（`browser-automation.ts:1321-1330` 已是 `private`，需要加一个 public 薄封装 `localFileUrl(filePath, workspace)`），结果经 `RuntimeMessage | { type: "gallery.previewUrl.result"; requestId; url?: string; error?: string }` 回传（**照 `design-snapshot.request/result` 的 bypass 早退语义**，`pi-runtime.ts:4589-4592` 附近）。
  - 为什么绕 utility：`BrowserStaticServer` 实例归 `BrowserAutomationController` 所有，只在 utility 进程；主进程拿不到服务端口。**这是本方案唯一一处跨进程新增 RPC**，务必照搬 bypass 早退位置，否则会卡在串行命令队列后面。
- `kind === "server"`：`app.url` 存在则直接用；否则**不做静态服务**，走 3.4 的终端预填路径。

### 3.4 主进程：服务型作品的「运行」降级（不自动拉起进程）

用户选了"一律走内置浏览器"，但**没有任何现成能力能可靠地拉起 dev server 并等就绪**。本期方案（诚实、不假装）：

- `kind === "server"` 且**有 `url`** → 直接开浏览器 tab。
- `kind === "server"` 且**只有 `command`** → 「运行」时：① 打开一个终端 tab（`openPreviewTarget({type:"terminal"}, \`terminal-${randomUUID()}\`)`）；② **把命令填进作品卡片下方展示 + 复制到剪贴板**，卡片上提示「命令已复制，在终端里回车执行」（**不自动敲键**——用户终端是人工输入通道，绕过权限门，见 AGENTS.md `terminal-pty` 段）。执行后命令跑起来，用户点第二次「运行」（或 `url` 已登记）即进浏览器。

**这是本期明确的边界**，写进迭代记录与卡片文案，不留下"以为会自动跑"的错觉。自动拉起进程留作 T-next 待办。

### 3.5 主进程：缩略图（复用离屏渲染链路，改 `design-snapshot.ts` 为通用）

把 `DesignSnapshotController` **通用化**（最小改动，保留既有 `design_export` 行为不变）：

- `DesignSnapshotRequest`（`protocol.ts:827-835`）新增可选字段：`thumbPrefix?: "design" | "gallery"`、`thumbDir?: string`（**缺省行为与现在完全一致**，零破坏）、`loadTimeoutMs?: number`。
- `design-snapshot.ts`：`capture` 里把写死的 `"design"` 与 `LOAD_TIMEOUT_MS` 改为读请求字段；新增分支——`thumbDir` 存在时写 `<thumbDir>/gallery-<时间戳>.png`（自建目录，不调 `saveBrowserScreenshot`，从而**不受 20 张保留策略约束**），并返回 `savedPath` 为**绝对路径**（`DesignSnapshotResult.savedPath` 语义从"工作区相对"扩为"按请求而定"，需在类型注释里写明；旧调用方 `runtime-design.ts:450-460` 不受影响）。
- `loadURL` **保持 `file://`**（作品 HTML 多数自包含；且缩略图只需静态快照，不需要运行语义）。

**触发时机**：作品发布成功时（3.6 的工具/按钮路径）**异步**发起一次缩略图（`await`，超时 12s 降级为无缩略图）。因为「发布」是用户显式动作，等一两秒可接受。

**渲染端读取缩略图**：缩略图在 agentDir（工作区外），`pidesktop-file://` 协议只允许工作区内文件（`index.ts:120-123`），`workspace-asset.ts` 也只映射工作区相对路径 → **新增一个只读 IPC** `desktop:gallery-thumb`（`app.getPath` 不需要，直接读 `galleryThumbsDirFor`，返回 data URL 或 `file://`？）。取最稳妥的：**返回 `data:image/png;base64,...`**（缩略图已缩到 1024 宽，单张约 100–300 KB，作品墙一屏最多 12 张 = 可接受）。渲染端 `GalleryWall` 用 `useEffect` 按需拉取并缓存（同 id 不重复拉）。

## 四、风险与假设

| 风险 | 应对 |
|---|---|
| **服务型作品无法自动就绪**（无能力拉起 dev server 并等端口） | 本期明确降级为「终端 + 复制命令」，不假装自动；写进卡片文案与迭代记录，另立待办 |
| **跨进程新增 RPC（`gallery.previewUrl`）** 若未走 bypass 早退会卡命令队列 | 严格照 `design-snapshot.request/result` 的位置（`pi-runtime.ts:4589-4592`），并加测试 |
| 缩略图 base64 经 IPC 传输的体积（12 张 ≈ 2–4 MB） | 按需拉取（可视区域优先）+ 同 id 缓存；单张 1024 宽已压过 |
| `BrowserPreview` 新增 initialUrl effect 可能重复导航 | 用 sessionStorage 标记 + tab-meta 清理；冒烟验证"切走再切回不重新导航" |
| 作品 HTML 是本地文件，浏览器 tab 用 http（静态服务）→ 与 `file://` 直开行为有差异 | 这正是选静态服务的目的（真实 origin）；若相对资源跨目录会 403（服务根 = workspace），发布时校验入口在工作区内 |
| AI 可能滥用 `gallery_publish` 把临时文件都发布 | 工具 `description` 明确"仅发布已完成、可运行、值得保留的成果"；权限走 write（ask 模式需确认） |
| 新增公开主题钩子（5 处镜像） | 逐处同步 + 组件契约测试钉住 |

**假设**：`pidesktop-gallery/` 作为 agentDir 下新目录，与 `pidesktop-automation/` 同级，不与其他模块冲突（已确认 agentDir 现有目录清单无同名）。
