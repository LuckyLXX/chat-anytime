# T21 修复长会话压缩后历史轮次消失

## 背景与目标

隔离复现中，12 轮会话在压缩后只显示后 6 轮，重开结果相同，而磁盘 JSONL 仍保留 12 轮。本工作区最近 20 份会话里也发现一例。`src/main/pi-runtime.ts` 的 `paneSnapshotFrom` 与分屏早水合均从 `session.state.messages` 取显示消息。Pi SDK 1.5.2 把这个列表用于模型请求，压缩成功后只保留摘要和近期消息。SDK 的 `SessionManager.getBranch()` 仍包含当前分支的历史原文。

验收目标是手动或自动压缩前后，用户均可翻阅同一分支完整的历史提问、AI 回复、附件和对应工具记录。切换回来、重开会话、打开分屏时同样可见。模型继续用压缩后的上下文，继续生成和重新生成沿用现有行为。存量会话使用已有 JSONL 即可恢复显示。

## 实施步骤

1. **在 `src/main/session-display.ts` 新增会话历史构建器。** 每个运行会话绑定同一 SDK `SessionManager`。从 `getBranch()` 按当前 leaf 路径读取 `message` 和 `custom_message`，用公开的 `sessionEntryToContextMessages` 转换，再复用 `normalizeMessages` 生成界面消息。压缩条目不参与界面消息计算。沿用当前分支内显式 `context_edit` 的语义，按目标条目取最后一次编辑，保留 Pi 对已废弃的自动重试响应和工具结果的省略，避免重试后重复显示失败气泡。复用 `session-history.ts` 的控制消息解析，让 `/compact` 指令与结局仍按时间落在原位置，旧分支的控制消息随分支切换退出。
2. **给历史构建器加会话内缓存。** 用 leaf 与条目计数判断是否需要重新遍历，缓存由条目及其编辑产生的消息引用和已完成消息列表。只有分支或条目改变才重新计算历史。压缩等元数据新增若未改变显示内容，复用原消息数组与气泡标识。流式帧继续由 `normalizeMessages` 投影活动尾部，保留从首个 token 到定稿的 UUID，已提交历史及控制消息的合并结果可复用。沿用现有窗口化渲染和快照增量协议。
3. **在 `src/main/pi-runtime.ts` 接入常规快照和分屏早水合。** `paneSnapshotFrom` 与创建会话时的分屏早水合使用同一个历史构建器。人工压缩控制信息仍写入原自定义条目，由会话历史构建器读取。`restoreToolExecutions` 读取同一分支中呈现给用户的消息与工具结果，使压缩前的工具卡在重开后仍可展开，沿用现有输出截断和产物回填上限。上下文用量、模型请求及回合结算继续消费 `session.state.messages`。
4. **处理完成事件与落盘的顺序。** Pi 先发 `message_end`，再在公共同步监听器返回后追加对应条目。保留事件内统计和调度，只把该事件的聊天快照推送放到同一事件循环的微任务，推送前校验 `liveSessions` 仍持有同一记录，再走现有 active 或 watched pane 即时推送。这样完成帧直接读到新叶子，既不会短暂漏掉消息，也不需要维护第二份待写入历史。`agent_settled` 仍是回合唯一结束边界。
5. **补充约定和迭代记录。** 在 `AGENTS.md` 会话约定里加一行说明时间线从当前会话分支构建，`state.messages` 服务于模型上下文。验证通过后把 T21 从 `docs/迭代记录.md` 待办移入同月归档，提交本次源码及测试。宿主应用的重启由用户执行。

## 验证

- `src/main/session-display.test.ts` 用 SDK 内存会话验证压缩前后历史顺序、控制消息位置、消息引用和 UUID、流式到定稿时无重复。覆盖历史附件、可见与隐藏的自定义消息、上下文编辑、回到更早的分支、同一条目数下 leaf 改变，以及新分支不会串入废弃消息。用临时 JSONL 验证重开后的历史正文和旧工具输出。
- `src/main/session-display-pi-mechanics.test.ts` 用真实 `AgentSession`、本地 faux provider 和临时会话，分别驱动手动压缩与自动阈值压缩，断言模型消息缩短、聊天历史稳定，追加下一轮仍正常。钉住 `message_end` 微任务能看到已提交的 user 与 assistant 条目。测试全程零网络。
- 在 `src/main/session-display-wiring.test.ts` 验证常规快照、分屏早水合、工具历史恢复和 `message_end` 刷新边界均接入。同一分支的长会话夹具验证固定历史的连续流式帧无需重复遍历分支，压缩不会触发历史消息全量重置。
- 指定回归测试通过后做独立代码审查并跑 `npm test` 与 `npm run build`。构建输出使用独立目录，保留运行中宿主的文件。检查现有增量帧、分屏切换及回合结算测试结果。

## 风险与假设

- 恢复历史原文和用户附图会增加冷开首帧载荷。当前界面继续按需挂载时间线，工具输出继续截断，稳定会话的增量帧继续复用消息引用。用长会话夹具检查并记录这一开销。
- SDK 的 `message_end` 早于追加条目，微任务顺序依赖这一版本的同步提交路径。真实 SDK 回归测试用于尽早捕捉升级后的时序变化。
- 重新生成会主动选择另一条分支。界面随当前 leaf 更新，压缩仍保留同一分支内的旧轮次。数据文件格式及会话写入路径沿用现状。
