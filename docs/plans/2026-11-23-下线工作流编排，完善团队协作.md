# 下线工作流编排，完善团队协作

## 背景与目标

11 月 23 日的「SSH 终端交互修复」中，工作流完成了规划与开发，但只读审查节点调用 bash 被拒，运行终止，交付由主会话另派审查、验证后完成。用户决定下线独立工作流编排，并一并删除既有工作流数据。团队保留「停止全部」，主会话 AI 可按任务或成员停止，聊天区「停止」继续中止当前聊天回合。首批团队改动以成员回传、查看权限卡点、改派和停止为验收目标。

## 1. 完整拆除工作流编排

- 删除 `src/shared/workflow*.ts`、`src/main/workflow-*.ts`、`src/main/runtime-workflow*.ts`，以及 `src/renderer/src/WorkflowCenter*`、工作流组件、`lib/workflow-*`、`workflow.css` 和其专属测试。移除 `resources/skills/workflow/`。
- 在 `src/shared/protocol.ts`、`src/main/pi-runtime.ts`、`src/main/index.ts`、`src/main/resource-catalog.ts`、`src/main/settings.ts` 清除工作流资源目录、命令、快照、工具开关、审批范围、运行生命周期、会话删除钩子和旧角色覆盖键。更新测试及 demo fixtures。保留共享权限 broker、待决权限镜像、权限上限取严机制和 `delegations` 的会话扫描排除。
- 在 `src/renderer/src/App.tsx`、`AgentSettings.tsx`、`ConversationPane.tsx`、`store.ts`、`components/RuntimeDialogs.tsx`、`styles.css` 和 `demo-api.ts` 移除工作流入口、角色扩展开关及状态 UI。移除工作流离开守卫后验证设置、预览和其他中心互斥，保留计划/团队共用状态容器。核对普通会话、子代理、IM、定时任务、设计与 GitHub Actions 的独立接线。
- 同步 `AGENTS.md`、`docs/theme-guide.md`、主题创作技能的 `SKILL.md`、`references/variables.md` 和 `scripts/check_theme.py` 五处主题契约、钩子计数及共享 wiring tests。迁移说明列出退役钩子，旧用户 CSS 继续加载，校验器可将已知退役钩子提示为需要移除的无效选择器，继续严格检查真正未知的钩子。保留历史计划与版本记录作为历史资料。

## 2. 让 Lead 可靠接收成员结果

- 扩展 `src/main/team-runtime.ts`、`team-contract.ts`、`runtime-team.ts`。基于成员 `agent_settled` 生成每成员每回合一条有界结算记录，包含回合结果、最后的短结论、已知任务 ID、明确提供的产物引用和卡点。已经主动向 Lead 汇报的正文去重，仍提供回合结果。失败/中止与正常结算分开，成员回合结束和任务验收继续分别判定。全文沿用成员会话转写。
- 结算放入 Lead 会话的既有持久化路径，并在 `team_list` 或 `team_wait` 给出轻量结果。Lead 在等时能取得结算、待审批或拒绝事件，成员活动帧继续只刷新看板。Lead 空闲时记录消息，等下一轮消费。上线前验证成员在 Lead 开始等待前就结束的时序，避免漏报或反复返回同一旧事件。
- `src/shared/protocol.ts`、`src/renderer/src/store.ts`、`TeamBoard.tsx`、`TeamBoardParts.tsx`、`TeamStrip.tsx` 消费需要展示的字段，覆盖主会话与分屏快照。旧团队会话按缺省字段读取，无需迁移历史。通过现有团队工具描述与回执说明用法，维持工具注入开关、静态 schema 与上下文预算。

## 3. 完成可控的权限、停止和改派链路

- 在 `pi-runtime.ts`、`runtime-permissions.ts`、`permission-broker.ts`、`pending-permissions.ts`、`protocol.ts` 和 `RuntimeDialogs.tsx` 为团队权限附加 Lead 会话和不可复用的成员 ID，审批卡显示成员名。现有审批路由继续按 owner 会话定位，成员的长期授权按该成员隔离。取消时按成员取消待决请求，Lead 停止继续收尾自身和同步子代理的请求，团队权限仍由成员或团队停止控制。团队的显式拒绝、权限模式拦截、超时分别反馈给 Lead，取消请求归为中止。沿用权限门，不自动提权。团队成员可用可选权限上限，旧成员继承原会话访问策略；保留上限与 Lead 模式逐次取严。复用现有 10 分钟团队权限等待兜底所需的超时机制，并以较短假定时钟验证。
- 在 `team-runtime.ts`、`team-contract.ts`、`runtime-team.ts`、`team-tasks.ts` 及对应接线实现按成员/任务停止。扩展现有 Lead 中断工具接收成员名或任务 ID（二选一）。在需要按任务精确追踪的分派上，用可选 `task_id` 把现有任务板 ID 与 Lead 发起的成员回合显式关联，复用归属与 CAS 校验；每个成员同一时间只绑定一个执行任务。旧的未绑定工作仍可按成员或全队停止。任务已完成、未绑定或无活跃执行时返回明确状态，不能误停其他工作。用户在聊天中「立即发送」时唤醒等待中的 Lead，让新指令能及时进入模型；团队工具事件仍不叫醒等待者。
- 既有看板的单成员中断和「停止全部」走共享收尾路径。确认受理后状态为「正在停止」，收到 `agent_settled` 或确认资源已回收后才报告「已停止」，清除目标此次执行的排队指令与待审批，防止取消后又收到旧任务。覆盖创建中、等待审批、正在运行、冷恢复、重复停止和迟到回调。停止动作保留任务记录、完成的依赖和共享工作区产物，任务可以由 Lead 通过现有 CAS 改派。任务遇到审查权限卡点时，Lead 可以换审查员并传递现有产物，或把确需命令验证的动作交给有授权的会话处理。
- 本轮范围聚焦对话调度。团队任务依赖仍由现有任务板约束，验收结论由 Lead 根据可见证据作出。

## 风险与假设

- 移除功能横跨共享协议、App 导航和权限，分离两批 diff 与针对性回归便于定位问题。既有主题的退役选择器需要迁移提示。历史会话工具调用按通用消息展示，持久化聊天通过旧日志测试验证。
- 成员中断有异步收场，权限取消和成员结算要共享同一个运行身份，避免旧回合覆盖新任务。任务 ID 按显式绑定解释，写入范围依旧只是告警，并行任务避免编辑同一文件。
- 下线后固定模板、自动推进与机器判定返工不再作为独立产品能力提供。验收以上述用户真实场景为准。
