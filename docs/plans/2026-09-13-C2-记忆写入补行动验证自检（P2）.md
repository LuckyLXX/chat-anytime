# C2 记忆写入补「行动验证」自检（P2）

> 来源：`docs/GenericAgent借鉴分析.md` 第六节 C2；本条已登记在 `docs/迭代记录.md` 待办区。
> 优先级 P2（提升记忆库信噪比）。规模 **XS**（改 6 行文案 + 1 例测试）。

## 背景与目标

GA 的记忆 SOP（`memory/memory_management_sop.md`）有四条核心公理，其中第一条是
**行动验证原则**，口号是 *No Execution, No Memory.*：

> 任何写入 L1/L2/L3 的信息，必须源自**成功的工具调用结果**（如 shell 执行成功、
> file_read 确认内容存在、代码运行通过）。
> **禁止**：严禁将模型的「固有知识」、「推理猜测」、「未执行的计划」或「未验证的假设」作为事实写入。

**现状核对（已核实，避免重复造轮子）**：
`runtime-memory-tools.ts:16-24` 的 `buildMemorySystemPromptBlock` 已覆盖五条：

| 现有行 | 内容 |
|---|---|
| 何时记 | 用户明确说"记住"；重复出现的稳定偏好；明确纠错；影响未来判断的决策理由；**本项目中已验证过的协作约定** |
| 何时不记 | 随时间变化的临时状态；模型可自行推理的常识；**从单次行为的推断**；密钥等敏感凭证 |
| 怎么写 | 先读后写、整体替换、description 一句话、时间敏感标日期 |
| 确认边界 | 普通写入直接做；删除/大段改写先确认 |
| 索引预算 | 主题 >15 时合并 |

**所以缺口是精确的、有限的**：「何时不记」里的「从单次行为的推断」覆盖的是
**由观察推断**（inference from one observation），而**没有覆盖**：
- 「把推理猜测 / 未验证的假设**当作事实**写入」——这是 GA 明确禁止且后果最严重的（错误事实会长期污染记忆库）；
- 「**必须来自成功的工具调用结果**」这条**来源要求**——现有文案没有正向规定来源。

**目标**：补一条「写入前自检」，把来源要求讲清楚。

## 设计决策

1. **写进 `buildMemorySystemPromptBlock`（系统提示词块），不写进工具 description。**
   理由：该块是**会话创建时冻结一次**的静态字节（见文件头注释的缓存哲学），
   属于稳定前缀——首请求后走 KV cache，**不破坏缓存**。
   而工具 description 是**每请求前缀成本**（`AGENTS.md` 的 prompt-diet 纪律），
   且这条约束是全局行为准则、不是某个工具的参数说明。

2. **只加一行**（不是一段）。要求：一句话、含可执行的自检问句、含反例枚举。
   预计 ~70 字符 ≈ 35 tokens，冻结前缀，可接受。

3. **不与现有行重复**。实现时若发现与「从单次行为的推断」语义重叠，
   **优先改写那一行**而非新增（保持块的精简）。

## 实施步骤

### 步骤 1：文案（`src/main/runtime-memory-tools.ts:16-24`）

在「何时不记」之后、「怎么写」之前插入一行：

```ts
"写入前自检：这条信息是否来自**成功的工具调用结果或用户明确陈述**？推理猜测、未验证的假设、未执行的计划一律不写——无行动不记忆。",
```

**建议的最终块**（实施时按此落地，逐字）：

```ts
export function buildMemorySystemPromptBlock(): string {
  return [
    "【长期记忆（memory_* 工具）】",
    "何时记：用户明确说“记住/以后都这样”；重复出现的稳定偏好；明确纠错；影响未来判断的决策理由；本项目中已验证过的协作约定。",
    "何时不记：随时间变化的临时状态（任务进度用 todo_write）；模型可自行推理的常识；从单次行为的推断；密钥等敏感凭证。",
    "写入前自检：这条信息是否来自成功的工具调用结果或用户明确陈述？推理猜测、未验证的假设、未执行的计划一律不写——无行动不记忆。",
    "怎么写：写前先 memory_read 既有主题；同主题用 memory_write 整体替换且不得丢失既有要点；description 保持一句话；时间敏感的内容在正文标注日期（至少到日）。",
    "确认边界：普通写入直接做、完成后一句话告知；删除主题或大段改写先向用户说明并取得确认。",
    "索引预算：主题总数超过约 15 个时，主动把相近主题合并重写为一个。"
  ].join("\n");
}
```

### 步骤 2：测试（`src/main/runtime-memory-tools.test.ts:115-123`）

现有用例断言块含「何时记/何时不记/todo_write/确认边界/memory_read」。
**新增断言**（扩展现有用例即可，不必新建）：

```ts
expect(block).toContain("成功的工具调用结果");
expect(block).toContain("无行动不记忆");
```

**并补一条「来源要求」的独立用例**（防后来者删掉这行的意图而不自知）：

```ts
it("governance block requires an action-verified source for new memories", () => {
  const block = buildMemorySystemPromptBlock();
  // 来源要求：必须来自成功工具调用或用户陈述
  expect(block).toMatch(/成功的工具调用结果|用户明确陈述/);
  // 反例枚举：三类禁止写入的内容
  expect(block).toContain("推理猜测");
  expect(block).toMatch(/未验证的假设|未执行的计划/);
});
```

## 验证方式

1. `npm test` 全绿（`runtime-memory-tools.test.ts` 新增/扩展用例）。
2. `npm run build` 全绿。
3. 体积核对：记录块长度（对照改动前）。
4. 行为验证（**弱验证，如实标注**）：这是**提示词文案改动**，
   「模型是否因此少写垃圾记忆」**无法用单测断言**。
   建议：改完后**观察一段时间**（用户主观判断），
   若发现记忆库仍频繁出现「推测性事实」，再考虑更强的手段
   （例如 `memory_write` 增加可选的 `source` 字段强制填写）——**本轮不做**。

## 风险与假设

| 风险 | 对策 |
|---|---|
| 与现有「从单次行为的推断」重复 | 实施时对照；重复则改写该行而非新增 |
| 提示词膨胀 | 只加一行；量化记录；属冻结前缀 |
| 「成功的工具调用结果」被过度解读为「必须执行工具才能记用户偏好」 | 文案已用**「或用户明确陈述」**并列——用户说「记住 X」正是最典型的合法来源，不冲突 |
| 该块进系统提示词会破坏缓存 | **不会**：它在 `createSession` 时取一次后整个会话字节冻结（现有注释已说明），改的是一次性的前缀内容，不是每轮注入 |
| 测试断言脆弱 | 断言用 `toMatch` 容忍措辞微调，只钉住**语义要点**（来源要求 + 三类反例），不断言整句 |
