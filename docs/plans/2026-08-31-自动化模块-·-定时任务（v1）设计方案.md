# 自动化模块 · 定时任务（v1）设计方案

## 一、背景与目标

PiDesktop 目前只有「浏览器自动化」（browser_* 工具），没有面向 Agent 的**定时任务**。本次为自动化模块的第一个能力：**定时任务**——让用户配置「在什么时间、让 Agent 用什么提示词跑一次」，触发后自动在后台运行，结果可回看。参考图（另一软件）的「创建本地定时任务」弹窗：任务名称 / 时区 / 调度方式（工作日+时刻）/ 任务提示词 / 空间 / 技能 / 专家 / 权限，以及「创建定时任务 → 去会话中创建」入口。

用户明确的两条路径都要做：
1. **窗口化创建/管理**：一个管理界面（列表 + 创建表单）。
2. **对话式创建**：通过一个专用 skill 指导 Agent「怎么创建一个定时任务」，Agent 据此调用工具落库。

> 用户已补充确认：定时任务表单要有**模型选择**，且执行时要**真正使用所选模型**（不是仅存元数据）。

## 二、关键决策（可调整）

| 维度 | 决策（v1 默认） | 备注 |
|---|---|---|
| 触发后在哪执行 | 当前 Agent + 当前工作区，后台（不抢焦点）专用新会话跑任务提示词，运行记录落该会话 JSONL，侧边栏可见、可打开回看 | 执行**套用任务所选模型**（见下）；跨工作区/跨 Agent 仍列为 v2 |
| 模型选择 | 任务记录 `model?: {provider,id}`，创建/编辑表单可选（默认 = 该 Agent 默认模型或全局默认），**执行时该后台会话用此模型** | 不再只是元数据——createSession 增加 `modelOverride`，运行会话以任务模型解析 |
| 调度方式 | 完整 cron 5 字段（`分 时 日 月 周`）+ 时区「跟随系统/自定义」 | 不引第三方依赖，自研纯函数 cron 匹配器（`*` `,` `-` `/`）+ 每分tick；参考图「工作日 09:00」=`0 9 * * 1-5` |
| 触发机制 | utility 进程每 1 分钟 tick 一次，命中 cron 且本分钟未触发过即执行 | 无需「下一次触发」推算，匹配+防重即可；准时度误差≤1 分钟 |
| 存储 | 按 Agent 划分：`<agentDir>/pidesktop-automation/<agentId>.json`（原子写，同 todo/plan 风格） | 每个任务携带 `agentId/workspace?/model?/accessMode` |
| UI | ① 新增设置页 tab「自动化任务」：列表（全部/进行中/已暂停）+ 搜索 + 「创建定时任务」按钮弹出创建表单弹窗；② 顶栏加「创建定时任务」按钮，下拉含「去会话中创建」 | 「去会话中创建」是独立流程，与会话内 skill 复用同一条链路 |
| 对话式创建 | 专用 skill `SKILL.md`（项目级 `.pidesktop-skills/automation/`）+ 每会话注册 `automation.*` 自定义工具 | skill 教模型 DSL（含模型可选项）并引导调用 `automation.create` |
| 权限 | 任务 `accessMode` 字段；v1 执行默认「完全访问」以避免无人值守被权限门卡住 | 受限模式会触发权限确认而挂起，skill 提示用完全访问 |
| 无人值守并发 | 调度器串行执行（一次只跑一个任务），同任务同分钟防重 | 避免与活跃会话竞态、避免全局状态被并发改写 |

## 三、数据模型（`src/shared/protocol.ts`）

```ts
/** cron 5 字段调度；timezone 缺省=跟随系统（留空）。 */
export interface AutomationSchedule {
  cron: string;              // "0 9 * * 1-5"
  timezone?: string;         // IANA 名或留空
}

export type AutomationStatus = "idle" | "running" | "failed";  // 展示用
export interface AutomationRunInfo {
  sessionId: string;         // 运行会话（回看入口）
  startedAt: number;
  status: "ok" | "error";
  preview?: string;          // 结果摘要（最后一段助手文本）
  error?: string;
}

export interface AutomationTask {
  id: string;
  name: string;
  schedule: AutomationSchedule;
  prompt: string;            // 触发后让 Agent 做什么
  agentId: string;           // 归属 Agent
  workspace?: string;        // 参照「空间」（v1 供展示/DSL）
  model?: { provider: string; id: string };   // 执行时所用模型（v1 生效）
  accessMode: AccessMode;    // 权限
  skillName?: string;        // 可选绑定技能（v1 展示，v2 生效）
  subagentName?: string;     // 可选绑定子智能体（v1 展示，v2 生效）
  enabled: boolean;
  createdAt: number;
  lastRun?: AutomationRunInfo;
}
```

`ResourceCatalog` 新增 `automation: AutomationTask[]`（当前 Agent 任务）。
`RuntimeCommand` 新增：`automation.save { task }`、`automation.delete { id }`、`automation.toggle { id, enabled }`、`automation.run { id }`。
`RuntimeMessage` 新增：`automation { tasks }`、`automation-run { id; status; message? }`。

## 四、实施步骤（涉及文件）

### 1. 存储层 `src/main/automation-store.ts`（新建，纯构建器 + 原子写）
- `normalizeAutomation(raw)`：字段校验/净化（name 非空、cron 合法、prompt 非空、accessMode 枚举、model 形状校验）、非法 id 重建、缺省 enabled=true。
- `readAutomation(filePath)` / `writeAutomation(filePath, tasks)`（tmp+rename）。
- `upsertAutomation` / `deleteAutomation` / `toggleAutomation`，返回最新列表供广播。
- 路径 `automationPathFor(agentDir, agentId)`。
- 测试 `automation-store.test.ts`（净化/往返/增删改/非法字段回退/model 校验）。

### 2. cron 匹配器 `src/main/automation-cron.ts`（新建，纯函数）
- `parseCron(expr)` → 5 字段数值集合；支持 `*` `,` `-` `/`；minute 0-59 / hour 0-23 / dom 1-31 / month 1-12 / dow 0-7（0 与 7 均周日）；非法抛错。
- `cronMatches(expr, date, timezone?)` → boolean。
- 测试 `automation-cron.test.ts`（星/列表/区间/步长/月日跨界/周日双值/边界非法/时区）。

### 3. 调度器 `src/main/automation-scheduler.ts`（新建）
- `createAutomationScheduler({ getAgentDir, getCurrentAgent, runTask, log })`：读取当前 Agent 任务，注册每分 `setInterval`（防重叠——上次未完成跳过本 tick），`cronMatches` 命中的启用任务、且本分钟未触发过（`taskId:localMinute` 防重键）即执行。
- `runTask(task)`：经回调交 pi-runtime 执行；串行队列保证一次只跑一个。
- `refresh()`：Agent 切换 / 任务增删改后重读 store、重排 ticker。
- 生命周期：`initialize` 创建、随 utility 进程结束清理。

### 4. 任务执行 `src/main/pi-runtime.ts`
- **`createSession` 增加可选 `modelOverride?: {provider,id}`**：在模型解析链顶部让 `requested = modelOverride`（`applyModelOverrides` 后进入会话），仅用于运行时按任务模型创建后台会话；不影响常规 `session.new`/`session.open` 路径。
- 新增 `runAutomationTask(task)`：以当前 Agent 上下文、`任务.model` 作为 modelOverride，创建**后台**（skipActivate 语义、不激活、不抢焦点）新会话，`session.prompt(任务.prompt)`；完成后把 `sessionId`+状态+摘要写回 store 的 `lastRun`，`post` 一条 `automation.run`。失败记录 error。
- 无人值守权限：运行会话 accessMode = 任务 accessMode（v1 默认 full）。
- **模型校验**：任务 model 若已停用/未配置，回退到该 Agent 默认模型并记日志（沿用 `providerConfigured`/`isModelEnabled` 口径）。

### 5. 自定义工具 `src/main/automation-tools.ts`（新建）→ 每会话注册
- `buildAutomationTools({ store(filePath), runNow, listModels })` → `ToolDefinition[]`（自建工具，加入 `recordCustomTools`）。
- `automation.create { name, cron, prompt, model?, workspace?, accessMode? }`：校验后落库（model 需在目录中命中，否则回退），返回任务摘要。
- `automation.list`：返回当前 Agent 任务。
- `automation.delete { id }` / `automation.toggle { id, enabled }` / `automation.run { id }`。
- 测试 `automation-tools.test.ts`（参数校验/创建/删除/开关/run 转发/model 回退）。

### 6. 渲染端
- `store.ts`：新增 `automation` / `automationLoading` / `requestAutomation()` / `automation` 消息分支；`automation-run` 分支（toast + 列表刷新）。
- `App.tsx`：`tab` 联合类型加 `"automation"`；设置 nav 加「自动化任务」按钮；`<AutomationSettings />`；顶栏加「创建定时任务」按钮（下拉：创建 / 去会话中创建，后者 `session.new` + 预填 skill 引导提示词）。
- 新组件 `AutomationSettings.tsx`：列表（全部/进行中/已暂停过滤 + 搜索）+ 行（名称/调度摘要/模型/启用开关/编辑/删除/运行一次）+ 创建/编辑表单**弹窗**，字段：任务名称 / 时区 / cron+预览 / **模型下拉（按供应商 <optgroup> 分组，默认该 Agent 默认模型，选中项存任务）** / 任务提示词 / 空间 / 权限 / 绑定技能·子智能体(v1 仅存)。
- `demo-api.ts`：补 `automation.*` mock + 静态任务夹具；`lib/model-list.ts` 复用 `groupModelsByProvider` 给表单模型下拉分组。
- 主题钩子：新增 `data-pane="automation-settings"`、`data-control="automation-create"/"automation-run"/"automation-toggle"` 等，同步 AGENTS.md / theme-guide / theme-creator skill 清单。

### 7. skill（对话式创建）
- 新建 `.pidesktop-skills/automation/SKILL.md`（项目级；文档注明可复制到全局 `<agentDir>/pidesktop-skills/`）。
- frontmatter：`name: 自动化任务`、`description: 当用户想创建/管理定时任务（自动化）时使用……`。
- 正文：教任务 DSL（名称 / cron 示例 / 提示词要点 / **可选 model**（不指定则用该 Agent 默认）/ 空间与权限 / 默认完全访问原因）、引导调用 `automation.create`、示例（「每天 18:00 用某模型巡检仓库」→ `0 18 * * *` + model）、提醒受限权限会无人值守挂起。

### 8. 记录与验证
- 更新 `docs/迭代记录.md`；补 theme-creator 钩子清单。

- 单测：cron 匹配、store 净化往返、工具校验与 CRUD（含 model 回退）、协议类型、demo-api fixture、createSession modelOverride 解析链。

## 七、风险与假设

1. **执行模型**：v1 在「当前 Agent + 当前工作区」后台跑，**任务所选模型已生效**；跨工作区/跨 Agent 仍只存元数据（若要达到完整「空间绑定 + 跨 Agent」，需给 createSession 加显式 agent/workspace 参数，属更大改动）。
2. **无人值守权限**：受限 accessMode 会触发权限确认而挂起；v1 默认「完全访问」，skill 会提示。
3. **每分 tick 准时度**：命中 cron 最多延迟 1 分钟触发；「秒级」任务不在 v1。
4. **会话累积**：每次触发新建会话；v1 接受（可回看），后续可加「每任务复用会话/运行记录清理」。
5. **不重启不重载**：调度器随 utility 启动从 store 装载；运行中改任务走 `refresh()`；应用关闭期间任务不触发。

## 八、后续（不在 v1）

- 完整执行模型：任务绑定任意 Agent/工作区 + 串行执行队列 + 后台会话不抢焦点。
- 受限权限自动放行策略、任务运行记录清理、每任务复用会话。
- 事件驱动触发（Hooks 事件 → 执行任务）与「专家/技能」在运行中生效。
