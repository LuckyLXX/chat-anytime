# 方案 B（增强版）：工作区助手级 + 默认工作区兜底

## 背景与目标

用户反馈指向同一心智模型——**工作区是每个助手自己的**：

1. 新建助手切到话题栏，不应出现全局历史工作区（fc004f7 已修：空分组仅显示当前激活工作区）。
2. 助手 A 移除工作区 X 应只影响 A（e42c139 因 bug 已回退，根因：workspace 是全局单值且双载体——utility 运行时变量 + 持久化 `settings.workspace`——清全局波及所有助手、`settings.workspace` 不清导致重启回潮）。
3. **新增（用户本次补充）**：引入「默认工作区」概念——没有选择工作区时，所有会话落在默认工作区中。补全「无工作区态」断层：新助手/移除工作区后不再面对 landing 页，开箱即可对话。

## 核心设计

### 1. 每助手工作区记忆：`DesktopSettings.agentWorkspaces?: Record<string, string>`

agentId → resolve 后的绝对路径。**刻意不放 `AgentProfile`**（agent.save 整对象覆盖，表单快照可能过期冲掉运行时字段）；与 `pinnedSessionPaths` 同级，设置页不渲染，渲染端类型零负担。

### 2. 默认工作区：`DesktopSettings.defaultWorkspace?: string` + 内置目录

- 用户可在设置页「通用」tab 自定义（选择文件夹）；未自定义时使用内置目录 `<agentDir>/workspace-default`（agentDir 即 Pi SDK `getAgentDir()`，已有 chatanytime-sessions 等同级目录），落位时 `mkdirSync(recursive)` 幂等创建。
- 兜底链（所有「没有工作区」的场合）：`agentWorkspaces[agentId] → 默认工作区`。会话仍按 `chatanytime-sessions/<agentId>/<hash>/` 助手隔离。

### 3. `settings.workspace` 停写、保留为一次性迁移兜底

updateSettings 三个写入分支改写 `agentWorkspaces` 后不再写它（否则兜底值漂移成「任意助手最后开的工作区」）。`initialize` 时仅当前活跃助手（currentAgentId，即老配置里全局工作区的真实归属）消费一次：`agentWorkspaces[currentAgentId] ?? settings.workspace ?? 默认工作区`；此后冻结。

### 4. 双写对称模式（沿用 `currentAgentId` 先例）

命令经 `runtime:send` → main `updateSettings`（settingsCache + persistSettings 落盘）→ 转发 utility `handleCommand`（settings 内存镜像）。两侧共用同一组纯函数（settings.ts），保证逻辑一致。

## 实施步骤

### 1. `src/shared/protocol.ts`

- `DesktopSettings` 加 `agentWorkspaces?: Record<string, string>` 与 `defaultWorkspace?: string`（含语义注释）。
- `settings.save` 载荷 `Pick<...>` 加 `"defaultWorkspace"`。

### 2. `src/main/settings.ts`（纯函数，双侧共用）

- normalize：`agentWorkspaces`（string→非空 string 条目保留，缺省 undefined）、`defaultWorkspace`（string/undefined）。
- `resolveDefaultWorkspace(agentDir, custom?)`：custom 优先（resolve），否则 `join(agentDir, "workspace-default")`。
- `resolveInitialWorkspace(agentWorkspaces, agentId, legacyWorkspace?, defaultWorkspace)`：命中 → resolve 路径；未命中 → legacy → 默认。
- `recordAgentWorkspace(map, agentId, path)`：resolve 规范化 + 覆盖写入。
- `forgetAgentWorkspace(map, agentId, removedPath)`：resolve+lowercase 匹配才删；不匹配不动。

### 3. `src/main/index.ts`（updateSettings）

- `workspace.open` / `session.new`(带 workspace) / `session.open`(带 workspace)：`settings.agentWorkspaces = recordAgentWorkspace(settings.agentWorkspaces, settings.currentAgentId, path)`，删除原 `settings.workspace = ...`。
- 新增 `workspace.remove` case：`forgetAgentWorkspace(settings.agentWorkspaces, settings.currentAgentId, command.workspace)`。
- `settings.save` case：透传 `defaultWorkspace`。

### 4. `src/main/pi-runtime.ts`（utility）

- helper `rememberWorkspace()`：recordAgentWorkspace 更新内存 map + `touchRecentWorkspace(workspace)`（进全局 recents，空分组才能显示）。
- `initialize`：`workspace = resolveInitialWorkspace(settings.agentWorkspaces, settings.currentAgentId, settings.workspace ? resolve(settings.workspace) : undefined, resolveDefaultWorkspace(getAgentDir(), settings.defaultWorkspace))`；首次落位默认工作区时确保目录存在（mkdirSync best-effort）。
- `agent.select`：`workspace = agentWorkspaces[目标 agentId]（resolve） ?? 默认工作区`（切到从未用过的助手 → 默认工作区，直接可聊）；**失败回滚**加 previousWorkspace 快照。
- 四个 workspace 赋值点接 `rememberWorkspace()`：`workspace.open` / `session.new` / `session.open` / `activate()`（分屏聚焦其他工作区格子 = 该助手最后使用的工作区，记入合理）。
- `workspace.remove`：助手级——不动全局 recents；删当前助手会话文件（现状）；移除目标 = 运行时 workspace 时 **workspace 回落默认工作区**（不再回 landing），并 touch；内存 map `forgetAgentWorkspace` 删当前助手键。
- `settings.save` case：同步内存 `settings.defaultWorkspace`；若当前 workspace 恰为旧默认工作区（resolveDefaultWorkspace(旧值) 等价）→ 即时切到新默认（否则用户改完默认工作区要等下次切换才生效）。

### 5. `src/renderer/src/App.tsx`

- 设置页「通用」tab 新增「默认工作区」行：显示自定义路径或「未自定义（使用内置目录）」+ 选择文件夹按钮（复用 `desktop:choose-workspace` IPC）+ 恢复默认按钮（清自定义）；随「保存通用设置」提交。
- 话题栏右键「移除工作区」：目标为默认工作区（resolveDefaultWorkspace 等价比较，渲染端用 store 中的 settings.defaultWorkspace + 固定 agentDir 路径？——渲染端不知道 agentDir，改为**仅当分组无会话且非当前激活时不显示**？不，更简单可靠：utility 在 snapshot 中已有 workspace 值，右键菜单比较 `workspaceKey(group.workspace) === workspaceKey(snapshot.workspace ?? "")` 不够（默认工作区可能是非激活的历史分组）。
  **落地方案**：协议不加字段；右键菜单的「移除工作区」项仅在 `group.sessions.length > 0 || group.workspace === snapshot.workspace` 时提供不可靠，改为——默认工作区分组必然会被 touch 进 recents 且作为兜底永远回潮，**允许移除会话但移除后它仍作为空分组回来**观感差；因此最终采用：**移除入口保留**，移除默认工作区 = 清当前助手在默认工作区的会话 + 回落默认工作区（workspace 不变，它本来就是默认）——utility 侧 workspace.remove 移除默认工作区时跳过「清 workspace」步骤即可（workspace 已是默认），确认文案统一「仅当前助手」。**UI 不做特殊分支，逻辑侧自然正确**。
- 移除确认对话框文案：「将永久删除当前助手在该工作区下的 N 个会话，其他助手不受影响，此操作不可恢复。」/「将从当前助手的话题栏移除，其他助手不受影响。」（e42c139 文案重做）。

### 6. `src/renderer/src/demo-api.ts`

- `demoSettings` 加 `agentWorkspaces`（default → chat-anytime-demo；黑鱼河 → PiDesktop）与 `defaultWorkspace: "D:\\Projects\\chat-anytime-demo"`。
- `agent.select`：`workspace = agentWorkspaces?.[agentId] ?? defaultWorkspace`。
- `workspace.open` / `session.new` / `session.open`：记录 map。
- `workspace.remove`：forget + 移除当前工作区时快照回落（workspace=defaultWorkspace、sessionId/messages 清空）。

### 7. 测试（settings.test.ts 增补约 12 例）

- resolveDefaultWorkspace：custom 优先 / 内置路径 / mkdir 幂等（tmp 目录）。

## 行为核对表

| 场景 | 行为 |
|---|---|
| 新建助手 → 切话题栏 | 落默认工作区：一个分组（该助手在默认工作区的既有会话或空）、对话区「今天想开发什么？」、**直接可发消息** |
| 新助手打开工作区 X | map[A]=X，X 成为 A 的分组 |
| 助手 A 移除工作区 X | 只删 A 的会话 + A 的 map 键；A 回落默认工作区（不回 landing）；**B 的键、B 的会话、全局 recents 不动** |
| A、B 都用过 X，A 移除 | B 完全不受影响 |
| 移除默认工作区分组 | 清当前助手在默认工作区的会话；工作区保持默认（它永远兜底） |
| 重启 | initialize 按 currentAgentId 读 map；无条目 → legacy（仅迁移期）→ 默认工作区；不再回潮 |
| 老配置升级 | 活跃助手继承旧 settings.workspace（体验不变）；其他助手落默认工作区 |
| 切 A→B→A | 各自恢复各自的最后工作区；从未用过的助手落默认 |
| 更换默认工作区（设置页） | 当前正用旧默认工作区时即时切换；否则下次落位生效 |

## 验证方式

1. `npm test`（新增 settings 测试）+ `npm run build` 全绿。
2. demo 模式浏览器冒烟：切助手恢复各自工作区、移除工作区仅影响当前助手、无工作区助手落默认。
3. 真机多助手 + 重启 + 老配置升级场景由用户冒烟（重启应用生效；无打包行为变化）。

## 风险与假设

- **agent.select 失败回滚**：previousWorkspace 快照，防切角色失败后 workspace 残留目标目录。
- **activate() 写 map**：分屏聚焦其他工作区格子会记为该助手最后工作区——语义合理，文档写明。
- **默认工作区目录**：`<agentDir>/workspace-default` 与 Pi 会话数据同级，mkdir 幂等不覆盖已有内容；resolve/mkdir 失败时 workspace=undefined 走 landing 极端兜底（保留现有 landing 代码路径）。
- **协议兼容**：两个新字段均可选，旧 settings.json 缺省即 undefined，无版本号变更；RuntimeCommand 仅 settings.save 的 Pick 扩一个字段（向后兼容）。
- **假设**：用户认可「移除默认工作区分组 = 清当前助手在该目录的会话、分组保留（永远兜底）」这一语义；若希望默认工作区分组完全不可移除，改 App.tsx 右键菜单一行即可。
