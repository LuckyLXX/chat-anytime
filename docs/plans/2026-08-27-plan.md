## 背景与目标

分屏（尤其三分屏）下，非焦点格子偶尔会永久停留在「正在载入会话……」，直到点击它（激活）才恢复正常。经排查，这是渲染端 `parkedSeed`（单槽兜底）承载不了多格分屏导致的。

**数据流（一个 parked 格子的数据来源优先级）**：
```
snapshot（自身是焦点格）→ paneStates（主进程 session.state 推送）
                       → parkedSeed（单槽：只记「上一次被切走的格子」）
                       → emptyPaneData（无 workspace → 永远渲染「正在载入会话」）
```

**根因**：
1. `parkedSeed` 是单槽——只在激活切换时写入「刚被切走的那一格」。三分屏里，非「上一任」的格子永远不会被它覆盖，只能依赖 `paneStates[该格]`。
2. `paneStates` 靠主进程 `session.watch` 推送；但 `store.ts` 的 `session.state` 通道会丢弃「当前激活会话的迟到帧」（`sessionId === snapshot.sessionId` 守卫）。激活切换瞬间主进程对旧焦点格推的那一帧，若在渲染端快照尚未更新的窗口内到达，会被误判为激活会话而丢弃。
3. 渲染端 `watchedPaneIdsRef` 只增不减（格子仍在集合内就不补发 watch），一旦水合帧丢失且该格不满足 parkedSeed 单槽条件，就永久卡在 `emptyPaneData` ⇒ 无限转圈。点击激活后走主快照 ⇒ 恢复正常。

**目标**：让任何「曾激活过、有完整数据」的格子失焦后都不会再被误渲染成「正在载入」，真实 `session.state` 到达后无缝接管。

## 实施方案

**只改渲染端，不动主进程**。主进程 `activate()` 里对 `previous` 的补帧条件（`renderedSessions.has(previous)`）若去掉会破坏单窗口切会话语义——单窗口下 previous 不在 renderedSessions，本就不该补帧，故主进程保持原样，避免副作用。

### 步骤 1：`src/renderer/src/store.ts` — 单槽 `parkedSeed` 升级为多槽数据缓存

- 类型：把 `parkedSeed?: { sessionId: string; data: SessionPaneSnapshot }` 改为
  `parkedPanels: Record<string, SessionPaneSnapshot>`（key = sessionId，值 = 该格最近一次完整快照）。
- `handleRuntimeMessage` 的 `state` 分支：把原来「写入单槽 parkedSeed」的逻辑改为把旧激活会话（`previous.sessionId !== incoming.sessionId` 时）**写入 parkedPanels**（覆盖式写入该 id），保留其余逻辑不变。
- 新增/复用清理：`dropPaneStates(sessionIds)` 在删除 `paneStates` 条目时**一并删除 `parkedPanels` 对应 id**（格子被关闭/修剪/切换助手时回收，避免残留）。格子数上限 4（`MAX_SPLIT_PANES`），加上焦点格不在其中，内存恒定有界。
- 导出 helper（供 `usePaneData` 使用）：新增纯函数或直接暴露 `parkedPanels` 供 selector 读取。

### 步骤 2：`src/renderer/src/ConversationPane.tsx` — `usePaneData` 读取多槽兜底

把 `usePaneData` 的 selector 优先级改为：
```
snapshot（焦点格）→ paneStates[sessionId] → parkedPanels[sessionId] → emptyPaneData
```
（原 `parkedSeed?.sessionId === sessionId` 分支替换为 `state.parkedPanels[sessionId]` 读取。）

### 步骤 3：`src/renderer/src/App.tsx` — 无需改逻辑（适配确认）

`dropPaneStates(removed)` 已覆盖所有格子移除路径（close / prune / 切换助手时 watch effect 重跑把全部格子移出 removed 列表），`parkedPanels` 随之清理，无需新增调用点。仅确认该路径即可。

## 验证方式

1. **新增单测**（`src/renderer/src/store.test.ts`，沿用现有 `handleRuntimeMessage` + `useDesktopStore.setState` 模式）：
   - 激活会话从 A 切到 B 时，`state` 通道把 A 的数据写入 `parkedPanels[A]`（不再是单槽覆盖）。
   - 三分屏模拟：焦点依次 A→B→C 切换后，`parkedPanels` 同时保留 A 与 B 两条数据（旧单槽会丢 A）。
   - `dropPaneStates(["A"])` 后 `parkedPanels` 与 `paneStates` 一起清掉 A，B/C 不受影响。
2. **运行** `npm test` 全绿（含既有 store 用例不回归）。
3. **运行** `npm run build` 通过（tsc 严格类型检查）。

## 风险与假设

- **风险：多槽缓存只保住「曾激活过、有完整数据」的格子**。若某个格子从始至终未被激活过（仅从 localStorage 恢复且从未打开），`parkedPanels` 无数据、`paneStates` 也可能未水合，仍可能短暂转圈——但主进程启动恢复会逐格 `open` 激活，实际路径下不触发；该边缘场景不影响本 bug 的复现与消除。
- **假设：单窗口模式不受影响**。单窗口时焦点格恒为激活会话，`parkedPanels` 无实际作用；`state` 通道写入逻辑与原来单槽等价（仅存储位置不同），单窗口下 `previous.sessionId !== incoming.sessionId` 的切换依然会被记录在 `parkedPanels` 中，但不影响任何渲染（单窗口没有 parked 格子）。
- **范围**：本次仅修复「非焦点格子无限转圈」，不做分屏 UI 美化/紧凑化等其他改动，避免范围扩张。
