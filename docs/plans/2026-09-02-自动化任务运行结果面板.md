# 自动化任务运行结果面板

## 背景与目标

自动化任务每次触发会在后台新建会话跑一遍提示词，但目前：

- **无历史记录**：store 只有覆盖式的 `lastRun`（单条），`recordAutomationRun`（automation-store.ts L117）每次直接替换；
- **通知信息不足**：`automation-run` 推送 payload 只有 `{id, status, message?}`（pi-runtime.ts L562/566），渲染端 toast 只能显示通用文案「定时任务已运行」，拿不到任务名、结果预览、sessionId；
- **无处集中查看**：运行产生的会话混在普通话题列表里，标题是 prompt 全文，难辨认；想看某任务「最近跑得怎么样」没有入口。

目标：新增**运行记录持久化 + 集中展示面板 + 快速查看结果**的完整链路。

## 已做取舍（如有异议请在批准时指出）

1. **面板位置**：设置页「自动化任务」tab 内加「任务 / 运行记录」双子页。理由：入口复用侧边栏 Zap 按钮（用户已习惯）；运行记录与任务管理同域；设置页空间充足可做筛选+展开详情。不选 PanelDock（定位是会话级辅助工具，空间小）也不选独立弹窗（多一套容器与状态管理，收益低）。
2. **toast 升级**：运行完成通知带任务名 + 「查看结果」按钮，点击直达运行记录子页并高亮该条。
3. **跨角色回看**：运行记录里的会话归属任务的角色。同角色任务「查看会话」直接打开；跨角色任务按钮明示为「切换角色查看」，点击后切换到该角色再打开（用户点击前已知晓会发生切换，不做隐式切换）。
4. **历史容量**：全局保留最近 200 条，超限自动裁剪（append 时顺带重写），不做手动清空按钮（低频需求，先聚焦）。

## 数据模型

**新文件** `<agentDir>/pidesktop-automation/runs.jsonl`——全角色共用一份 append-only 事件流（与任务文件同目录；`readAllAutomations` 只读 `*.json`，不受影响）。运行历史是全局事件流，不按角色分文件，与「跨角色调度、全角色聚合展示」的既有口径一致。

```ts
// protocol.ts 新增
export interface AutomationRunRecord {
  id: string;          // runId（randomUUID）
  taskId: string;
  taskName: string;    // 快照：任务被删后记录仍可读
  agentId: string;
  agentName: string;   // 快照
  sessionId: string;   // 回看入口（AutomationRunInfo.sessionId 同源）
  startedAt: number;
  durationMs: number;
  status: "ok" | "error";
  trigger: "cron" | "manual";
  modelId?: string;    // 实际使用的模型 id（回退链解析后的结果）
  preview?: string;    // 最后一段助手文本截断 200 字（复用 truncatePreview）
  error?: string;
}
```

不快照 prompt（避免记录膨胀）：详情展开时按 taskId 从 store.automation 现查，任务已删则不显示该行。

## 实施步骤

### 1. 新增运行历史 store：`src/main/automation-runs.ts`（+ 同目录测试）

与 automation-store.ts 同风格（原子写、normalize 净化、容错）：

- `automationRunsPath(agentDir)` → `<agentDir>/pidesktop-automation/runs.jsonl`
- `appendAutomationRun(agentDir, record)`：追加一行 JSON；追加后若超 **200 条**则重写文件保留最新 200（tmp+rename，低频事件可接受读-过滤-写）；返回全量最新列表
- `readAutomationRuns(agentDir)`：逐行解析，坏行跳过，按 startedAt 倒序
- `normalizeAutomationRun`：校验必填字段（id/taskId/taskName/agentId/agentName/sessionId/startedAt/durationMs/status/trigger），非法即丢弃

测试 `src/main/automation-runs.test.ts`：追加/读取/超 200 裁剪/坏行容错/normalize 非法字段丢弃。

### 2. 协议变更：`src/shared/protocol.ts`

- 新增 `AutomationRunRecord` 类型
- `RuntimeMessage`：
  - `automation-run` payload 扩展：`status` 增加 `"running"`（开始时推送），新增 `taskName`、`runId` 字段（终态推送携带）
  - 新增 `{ type: "automation-runs", runs: AutomationRunRecord[] }` 全量推送
- `RuntimeCommand`：新增 `{ type: "automation.run.open", runId: string }`——渲染端只发 runId，主进程负责查记录、跨角色切换、定位会话、激活/恢复
- `ResourceCatalog` 增加 `automationRuns: AutomationRunRecord[]`（bootstrap 初始注入，与 `automation` 同模式）

### 3. 主进程：`src/main/pi-runtime.ts`

`runAutomationTask(task, trigger: "cron" | "manual")`：

- 创建会话成功后 `manager.appendSessionInfo(\`自动化 · ${task.name}\`)`（复用 L613 已验证用法，失败仅记日志不阻塞）——运行会话在话题列表中可辨认，是「查看会话」后的体验闭环
- 开始执行时推 `automation-run { status: "running", id: task.id, taskName: task.name }`（渲染端据此在记录列表顶部显示运行中条目）
- 结束（成功/失败）时：现有 `afterAutomationRun`（lastRun 回写，保留不动）之外，追加 `appendAutomationRun` 完整记录（含 durationMs、trigger、modelId=实际解析的 modelRef.id、preview/error），随后推 `automation-runs` 全量 + 终态 `automation-run`（带 taskName/runId）
- 调度器 drain 处传 `trigger: "cron"`；GUI `automation.run` 分支与工具侧 `runTaskNow` 路径传 `"manual"`

新命令 `automation.run.open { runId }`：

1. 读 runs.jsonl 找记录，找不到 → 推 error log（「运行记录不存在」）
2. `run.agentId !== currentAgentId` → 先执行 agent.select 等价逻辑切换角色（复用现有切换管线，含会话列表刷新）
3. 定位会话：`liveSessions.get(sessionId)` 命中 → activate；未命中 → 在 `agentWorkspaceSessionDir(agentDir, run.agentId, ...)` 下按 sessionId 扫描 JSONL 文件 → 走 session.open 相同的恢复逻辑；文件不存在（失败运行未落盘且应用重启过）→ error log 提示「该运行的会话不存在（可能未持久化或已删除）」

初始化：`refreshAutomation` 同时读 `automationRuns`（模块级变量）并入 ResourceCatalog；新增 `emitAutomationRuns()`。

### 4. 渲染端 store：`src/renderer/src/store.ts`

- state 新增 `automationRuns: AutomationRunRecord[]`、`automationRun` 扩展为 `{ id, taskName?, runId?, status: "ok"|"error"|"running", at }`
- case `"automation-runs"` → 全量替换；case `"automation-run"` → 更新 automationRun（running/终态统一处理）

## 风险与假设

- **存量无历史**：升级前只有 lastRun，面板首启为空（空态文案已覆盖）；不回填（无 taskId→历史会话映射，成本高收益低）
- **跨角色切换时序**：agent.select 后需等会话列表刷新再打开目标会话，主进程内串行处理可控；实现时重点验证
- **失败运行无会话文件**：JSONL 落盘门槛（首条 assistant 消息）导致部分失败会话不可恢复——automation.run.open 已设计容错提示，liveSessions 命中时仍可打开
- **推送体积**：200 条全量约 100KB，每次运行结束推一次，IPC 可接受
