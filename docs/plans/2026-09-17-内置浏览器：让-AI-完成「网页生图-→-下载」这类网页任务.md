# 内置浏览器：让 AI 完成「网页生图 → 下载」这类网页任务

## 一、背景与目标

**用户需求**：有很多网页功能（如网页生图：登录后输入提示词 → 生成图片 → 下载），希望 AI 用内置浏览器自动完成，而不是用户手动去 Chrome 操作。

**经 ask_question 对齐的三项决策**（本计划据此展开）：
1. 验证站点：`https://l0veyou.com/chat`（**需登录**——登录由用户在内置浏览器手动完成一次，Cookie 持久保存；本计划不用自动化碰登录流程）。
2. 范围：**C = 修 browser_click + 补输入链路 + 端到端探针 + 模型操作指引 + 「页面图片直存工作区」能力**。
3. `browser_click` 根因的处置：**删除 `Input.setIgnoreInputEvents` 守卫**（实测它拦不住真人输入，却拦死了 CDP 合成输入）；保护改由自动化横幅 + 逐操作串行 + 点击前重定位核验承担。

**为什么现在做**：链路已有八成基础设施（登录态持久、下载落盘、工具面齐全），卡在一处已登记 P0（待办 T2：`browser_click` 实际点不动）。真实审计数据佐证这是主因：`browser_click` 累计 44 次调用 / 11 次错误，而 `browser_eval` 高达 412 次——模型在绕行点击；下载回执在所有真实会话中出现 **0 次**（点击触发的下载够不到）。

## 二、已核实的现状（供实施直接引用，不必重新调研）

### 1. browser_click 失效（T2，根因已由历史探针 8/9/10 钉死）
- 守卫 `withAutomationGuard`（`src/main/browser-automation.ts` 约 1096–1119 行）在操作前后发 `Input.setIgnoreInputEvents {ignore:true/false}`，**唯一调用点 `:762`**（包住全部 op：attach/navigate/snapshot/click/type/press/scroll/select/upload/eval/screenshot/wait/get/tabs）。
- 实测：开守卫时 CDP 鼠标事件在渲染器侧完全不派发（`browser_click` 回执成功、页面 `onclick` 不动、不产生下载）；`Input.insertText` 与页面脚本 `click()` 不受影响。
- 守卫在 `withOpTimeout` 覆盖范围之外，且历史上是「假死标签页拖死 110s」的两处 arming 之一（另一处 `Page.enable` 已改 fire-and-forget）。

### 2. 登录态（已核实，无需改动）
- 唯一 partition `"persist:pidesktop-browser"`（`src/main/browser-preview.ts:281`），用户标签 `browser-<uuid>` 与 AI 自动化标签 `pi-browser-<uuid>` **共用同一 session**，Cookie 跨重启持久（实测磁盘 `%APPDATA%/chat-anytime/Partitions/pidesktop-browser/Network/Cookies`）。
- 全仓库无 `clearStorageData`/`clearCache`/`cookies.remove` 类清理 → 登录态不会被任何代码路径打断。

### 3. 下载通道（已就绪，无需改动）
- `will-download` → `BrowserPreviewController.handleDownload`（`browser-preview.ts:407`）→ 按标签策略：用户预览页 `cancel`；自动化标签且 `browser_navigate` 带过 workspace → 落 `<workspace>/.pidesktop/downloads/`。
- 上限 `MAX_TAB_DOWNLOADS = 20`/导航；命名经 `sanitizeDownloadName`；回执走 `pendingDownloads` → `notices` → `formatDownloadNotices`（含「尚未落盘完成，请用 ls/read 确认」的中性态）。
- 操作尾统一 `awaitDownloadsSettled`（预算 3000ms）。

### 4. 输入链路现状
- `type`：`Input.insertText`（实测有 `input` 事件、受控组件状态同步；无 keydown/keyup）。
- `press`：`PRESS_KEYS`（`browser-automation.ts:571`）映射后只发 `keyDown`/`keyUp`，**不带 `text` 字段**；未命中的单字符走 `insertText`。
- **待验证**：`<input>` 内 Enter 能否触发默认提交行为、`contenteditable`（React 富文本编辑器）能否被 insertText 正确写入——两者都影响「输提示词 → 回车发送」。

### 5. 能力缺口：页面图片直存
- 现有路径：`browser_screenshot`（截「屏幕上看到的」，非原图）；`browser_eval` 只能拿 base64 文本再自行解码（无字节通道）。
- **缺口**：没有「把页面里的图片原图存成工作区文件」的工具 —— 应对无下载按钮、`blob:`/`data:`/canvas 图片的站点。

### 6. 其他约束
- 工具清单：14 个 `browser_*`（`src/main/runtime-browser.ts`），测试硬编码于 `src/main/runtime-browser.test.ts:31`；`locale.ts` 需同步 label（渲染端状态栏/工具卡用）。
- 权限（`permissions.ts`）：`browser_navigate` / write-eval / tabs-close 走 `browse` 风险；其余页面内操作免门。
- 教学纪律：tools 数组是**每请求前缀成本**，教学文案一律落对话尾部或 skill（按需读取），禁止堆进 description。
- 当前测试规模：**1459 例 / 122 文件**；`npm test` + `npm run build` 全绿为准。

### Step 3：新增 `browser_save_image`（页面图片直存）
**协议**（`src/shared/protocol.ts`）：
- 请求：`{ op: "saveImage"; ref?: string; selector?: string; url?: string }`（三选一）
- 响应：`{ kind: "saveImage"; mode: "inline" | "download"; relativePath?: string; bytes?: number; width?: number; height?: number; mime?: string; filename?: string; source?: "data" | "blob" | "canvas" | "http" }`

**主进程实现**（`src/main/browser-automation.ts` + 新纯模块 `src/main/browser-save-image.ts`）：
1. 定位：`ref`/`selector` 复用现有 `locate`/`queryDeep` 路径（穿 shadow DOM / 同源 iframe），页面脚本返回元素类型与候选来源：
   - `<canvas>` → `toDataURL("image/png")`（catch 跨域污染 SecurityError，给出可行动错误）
   - `<img>` → `currentSrc || src`；CSS `background-image` → 解析 `url()`
2. 按来源分派（**按探针 P3 结论定主/降级路径**）：
   - `data:` → 主进程解 base64
   - `blob:` → 页面内 `fetch(blobUrl)` → ArrayBuffer → base64 回传（页面内天然带 cookie/referer）
   - `http(s)` → 主通道 `session.fetch(url, { credentials: "include", headers: { Referer: 页面 URL } })` 取字节；失败（非 2xx/抛错）→ 降级 `webContents.downloadURL(url, { headers: { Referer } })` 走既有下载通道（回执 mode=`download`，落盘结果由现有 notices 报）
3. 落盘（inline 模式）：存到该标签的下载目录（`downloadDirs.get(tabId)`，与下载同目录 `.pidesktop/downloads/`）；文件名 = URL basename（经 `sanitizeDownloadName` 清洗）+ 冲突递增；无 basename → `image-<时间戳>`；扩展名由**字节 sniff**（magic bytes: png/jpeg/webp/gif/bmp/avif/svg）决定，不信任 URL 后缀。
4. 尺寸：`nativeImage.createFromBuffer(buffer).getSize()`（对 svg/未知格式优雅降级为不给尺寸）。
5. 上限：单图 20MB（与 upload 上限对齐），超限明确报错；`ref`/`selector` 与 `url` 必须三选一，多给报错。
6. 无工作区 / 标签未 navigate 过工作区 → 明确报错并提示「先 browser_navigate 打开页面（自动化标签会自动把下载保存到 `.pidesktop/downloads/`）」。

**工具层**（`src/main/runtime-browser.ts`）：
7. `browser_save_image` 定义：描述说明「把页面中的图片原图保存到工作区（应对没有下载按钮、或图片是 blob/data/canvas 的站点）」，参数 `ref`/`selector`/`url` 三选一；回执给相对路径 + 尺寸 + 大小（inline）或「已发起下载，见下方下载提示」（download）。
8. `src/shared/locale.ts` 加 `browser_save_image: "浏览器保存图片"`。
9. 权限（`src/main/permissions.ts`）：**免门**（与 `browser_screenshot` 同口径——都是「AI 把看到的内容落到 `.pidesktop/` 下的观察产物」，不写用户工作区文件）。此取舍写进代码注释与迭代记录。
10. 单测：来源分类、sniff、命名清洗、工具参数校验与回执渲染；并加一条**描述 token 上限断言**（≤200 tokens，防未来把教程堆进 description）。

## 五、风险与假设

1. **删守卫的副作用**：AI 操作期间真人输入不再被忽略（用户已确认接受）。缓解：横幅提示 + 可取消、逐操作串行、点击前重定位核验。**假设**：单操作时间窗短（<1s），人机抢输入概率低。
2. **Enter 发法的最终选择以探针实测为准**：三种发法若都无效（极小概率），则如实记录并保留最接近真实键盘的一组，不强行宣称已修好。
3. **`session.fetch` 的 Cookie 行为不确定**（Electron 已知 issue）：以探针 P3 实测决定主通道；若带不上 Cookie 则主线直接走 `downloadURL`（走浏览器下载栈，Cookie/referer 天然正确）。
4. **跨域图片 canvas 污染**：`toDataURL` 对跨域绘制的 canvas 会抛错，属预期行为，会给出明确报错与替代建议（用 http 通道存原图 URL）。
5. **新增工具的前缀成本**：`browser_*` 是常驻激活策略，新工具会增加每请求前缀；用描述精简 + token 断言控制。
6. **范围克制（明确不做）**：不做点击后 DOM 变化检测、不改 `browser_wait` 上限、不动浏览器 UI/主题、不动登录流程（用户手动登录）、不做多窗口。
