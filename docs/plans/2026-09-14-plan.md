# 内置 Skill 目录化实施计划（2026-09-14）

## 背景与目标

**问题起因（用户澄清）**：我们是在 PiDesktop 自己的工作区里开发 PiDesktop（自举），所以才会出现「这两个 skill 显示成当前项目」的现象——因为它们在仓库项目级目录 `.pidesktop-skills/` 里，而项目级是最高优先、且只在打开这个工作区时才可见。

**用户定的口径**：**用户安装后，安装目录里的 skill 目录就是内置 skill 的目录**；项目级 skill 应该是单独的目录（`.pidesktop-skills/`，不变）。因此——

- 内置 skill = 随安装包分发、装在 `<安装目录>/resources/skills/`，**运行时直接扫描该目录**（不复制、不 seed 到用户目录）；
- 开发者（dev 模式）读仓库里的 `resources/skills/`，所以自举开发时也能看到它们，且在工作区里它们显示为「内置」而不是「当前项目」。

## 现状（已核实）

1. 扫描优先级（`src/main/skill-catalog.ts` `discoverSkills`）：`~/.agents/skills`（共享）< `<agentDir>/pidesktop-skills`（用户全局，agentDir = `~/.pi/agent`）< `<workspace>/.pidesktop-skills`（项目，最高）。
2. 这两个 skill 只在仓库 `.pidesktop-skills/` ⇒ 只有打开本仓库工作区才可见。
3. `computer_*` 工具的 Python 资产定位（`runtime-computer.ts:69-79` `locateLjqCtrlDir`）只看项目/全局两处，所以换个工作区就找不到 `ljqCtrl.py`——工具与 skill 必须同源。
4. `package.json` 的 `build.files` 只含 `out/**/*` 与 `package.json`，`.pidesktop-skills` **没进包**，打包版里电脑控制/对话式建自动化任务实际不可用。
5. 无 workspace 时 `runtime-skills.ts:23` 把 projectDir 顶成 globalDir，全局 skill 被标成「当前项目」（顺手修的既有瑕疵）。

## 参考：Proma 内置 skill 的两个可借鉴点（已通读其源码）

Proma 的默认技能走「`apps/electron/default-skills/` → `extraResources: {from: default-skills, to: default-skills}` → 启动期 `seedDefaultSkills()` 复制到 `~/.proma/default-skills/` 并按 `SKILL.md` 的 `version` 做版本门升级」（`electron-builder.yml:66-69`、`config-paths.ts:501-563`）。**我们按用户口径不采用 seed 复制**（安装目录即内置目录、直接读），但借两点：

1. **打包方式照抄**：`extraResources` 把 `resources/skills` 原样发到 `<安装目录>/resources/skills`（不进 asar、随版本升级）；
2. **UI 区分内置**：Proma 用「PROMA 内置」徽标区分，我们用既有的 `ResourceScope` 枚举 `"bundled"`（渲染端已有标签「内置」，零协议结构改动）。

> 为什么不像 Proma 那样复制到用户目录：Proma 的工作区是它自管的（`~/.proma/agent-workspaces/<slug>/skills`），复制才有意义；PiDesktop 的全局技能目录是 `~/.pi/agent/pidesktop-skills/`、项目目录是用户任意工作区里的 `.pidesktop-skills/`，一旦复制就会出现「副本被用户改坏 / 升级覆盖用户改动 / 两份漂移」三类问题，而直接读完全没有这些问题——安装目录是只读的、随安装包升级。

## 决策（已定，实施照此执行）

| 决策点 | 结论 |
| --- | --- |
| 内置资产仓库落点 | 目录**改名** `.pidesktop-skills/` → `resources/skills/`（`git mv`，保留历史）；与安装包内布局同名，`extraResources` 零路径翻译 |
| 分发 | `package.json` → `build.extraResources: [{ "from": "resources/skills", "to": "skills", "filter": ["**/*"] }]` |
| 运行时定位 | 主进程算出绝对路径，随 `initialize` 下发新可选字段 `bundledSkillsDir`；utility 进程无 Electron API，故不由它自己推导 |
| 路径推导 | 打包 → `join(dirname(app.getAppPath()), "skills")`（`app.asar` 的父目录即 `resources/`）；dev → `join(app.getAppPath(), "resources", "skills")`；两侧都 `existsSync` 校验，不通过则不下发（dev 缺目录 = 退回三档） |
| 扫描优先级（低→高） | `~/.agents/skills`（共享）< **内置（安装目录）** < `<agentDir>/pidesktop-skills`（用户全局）< `<workspace>/.pidesktop-skills`（项目）——同名 slug 后者覆盖前者，因此用户放一份同名副本到全局目录即可覆盖内置 |
| 展示 | 内置条目 `scope: "bundled"`（枚举已存在、渲染端标签「内置」）、`source: "随应用分发"`；其余仍按来源显示「全局 / 共享目录 / 当前项目」 |
| computer_* 资产 | `locateLjqCtrlDir` 与 skill 扫描同序：项目 → 用户全局 → 内置 → `~/.agents/skills` |
| 项目级约定 | 不变：`<workspace>/.pidesktop-skills/`（用户自己的项目技能，最高优先）；内置**不写进**任何项目目录 |

## 实施步骤

### 步骤 1：资产搬家 + 打包配置
- `git mv .pidesktop-skills resources/skills`（含 `automation/SKILL.md`、`computer-use/{SKILL.md,ljqCtrl.py,uia.py,ui_detect.py}`；`__pycache__` 未跟踪且已 gitignore）。
- `package.json` 的 `build` 段加 `extraResources`（见上表）。
- `resources/skills/computer-use/SKILL.md`：示例路径 `.pidesktop-skills\computer-use` 改为安装目录形态（`<安装目录>\resources\skills\computer-use`），并加一句「这是随应用分发的内置资产；要自定义请把整个目录复制到全局技能目录 `~/.pi/agent/pidesktop-skills/`（同名会覆盖内置）」。

### 步骤 2：skill 扫描支持「内置」来源（`src/main/skill-catalog.ts`）
- `discoverSkills` 改为接受**有序扫描源数组**（数组顺序 = 优先级低→高，同名后者覆盖前者）：
  ```ts
  export interface SkillSourceDir { dir: string; scope: "global" | "project"; source: string }
  export function discoverSkills(sources: readonly SkillSourceDir[]): DiscoveredSkill[]
  ```
  `DiscoveredSkill` 增 `source: string`（展示名）；`scope` 类型放宽到 `"global" | "project" | "bundled"`。
- 各源的 scope/source：共享 `~/.agents/skills` → global「共享目录」；内置 → **bundled「随应用分发」**；`<agentDir>/pidesktop-skills` → global「用户资源」；项目 → project「当前项目」。
- `toSkillSummaries` 直接用 `skill.source`（不再按 scope 猜）。

### 步骤 3：路径装配（`src/main/runtime-skills.ts`）
```ts
export interface SkillPaths { dirs: SkillSourceDir[]; statePath: string }
export function skillPathsFor(workspace: string | undefined, agentDir: string, bundledDir?: string): SkillPaths
```
按上表顺序拼装；`bundledDir` 存在才加该档；**workspace 为空时不再顶替 projectDir**（修掉「全局 skill 被标成当前项目」）；`scanSkills` 适配新签名。

### 步骤 4：computer_* 资产定位（`src/main/runtime-computer.ts`）
- `locateLjqCtrlDir(agentDir, workspace, bundledDir?)`：候选顺序 = 项目 → 用户全局 → 内置 → `~/.agents/skills`，每处查 `<dir>/computer-use/ljqCtrl.py`。
- 顶部注释与缺资产文案（`runtime-computer.ts:261`）改为如实描述四档来源（「内置资产缺失请重装应用，或把 computer-use 目录放到全局/项目技能目录」）。

### 步骤 5：主进程下发内置目录（`src/shared/protocol.ts` + `src/main/index.ts` + `src/main/pi-runtime.ts`）
- 协议：`{ type: "initialize"; settings; apiKeys; bundledSkillsDir?: string }`（新增可选字段，向后兼容）。
- `src/main/index.ts` 新增**导出**纯函数（便于单测）：
  ```ts
  export function resolveBundledSkillsDir(appPath: string, isPackaged: boolean): string | undefined
  ```
  在 `startRuntime()` 构造 `initialize` 时带上；不存在则 undefined（dev 下没这个目录也不报错）。
- `src/main/pi-runtime.ts`：模块级 `bundledSkillsDir`，`initialize` 赋值；`skillPaths()` 透传；`buildComputerTools({ ..., locateScriptDir: () => locateLjqCtrlDir(getAgentDir(), recordWorkspace, bundledSkillsDir) })`。

### 步骤 6：渲染端与文档
- `src/renderer/src/App.tsx:579` Skill 区帮助文案改为四档来源说明（内置随应用分发、只读；全局 `pidesktop-skills/`；共享 `~/.agents/skills/`；当前项目 `.pidesktop-skills/`）+「要改内置请复制到全局目录」。
- `src/renderer/src/demo-api.ts` 的 `demoResources.skills` 补一条 `scope: "bundled"`、`source: "随应用分发"` 的样例（demo 冒烟能看到「内置」标签）。
- `README.md:108`、`AGENTS.md:16`（Skill 段落：四档来源 + 内置目录来源 + extraResources）与 `AGENTS.md:29` 里 `.pidesktop-skills/automation/SKILL.md` 的路径改为 `resources/skills/automation/SKILL.md`。
- `docs/迭代记录/2026-09.md` 追加条目 + `docs/迭代记录.md` 最新进展一行（两文件已 gitignore；改前先看 mtime 防并发覆盖）。

   - `skill-catalog.test.ts` 改用新签名，覆盖：四源优先级与同名覆盖（内置 vs 共享、用户全局 vs 内置、项目 vs 用户全局）、`scope`/`source` 标签正确、无工作区时**不出现** project 源。
   - 新 `runtime-skills.test.ts`：`skillPathsFor` 在「有/无 workspace × 有/无 bundledDir」四种组合下的顺序与内容。
   - `runtime-computer.test.ts`：`locateLjqCtrlDir` 四档顺序（项目优先、内置兜底、`~/.agents/skills` 最后、全缺返回 undefined）。
   - 新 `src/main/index.test.ts`（或并入既有 main 侧测试文件）：`resolveBundledSkillsDir` 在打包布局（`…/resources/app.asar` → `…/resources/skills`）、dev 布局（`<repo>/resources/skills`）、目录不存在（→ undefined）三种情形。
   - **资产契约测试**（新增，防未来改名/搬家）：仓库内 `resources/skills/computer-use/{ljqCtrl.py,uia.py,ui_detect.py}` 与两个 `SKILL.md` 存在，且 frontmatter 能被 `parseSkillFrontmatter` 解析出 name/description。
2. `npm test` 全绿 + `npm run build` 全绿（硬门槛）。
3. **真实路径冒烟（只读，不写用户目录）**：`npx tsx` 临时脚本（放仓库内 `.tmpchk/`，用完 `rmSync` 删除）用真实 `resources/skills` 与临时目录跑一次 `discoverSkills` + `locateLjqCtrlDir`：断言两个 skill 被识别为 `scope: "bundled"`、name/description 正常，且 computer-use 目录下的 `ljqCtrl.py` 能被定位。
4. **打包产物校验**：`npx electron-builder --win dir` → 断言 `dist/win-unpacked/resources/skills/computer-use/ljqCtrl.py` 与 `dist/win-unpacked/resources/app.asar` 同时存在（证明路径推导 `dirname(app.asar)/skills` 成立）。不启动应用、不结束用户正在运行的实例。
5. 完成后提醒用户重启应用生效（源码改动不影响运行中的实例）。

## 风险与假设

- **`app.getAppPath()` 布局**：打包下应为 `<resources>/app.asar`；若实测不同，断言 4 立刻暴露，回退方案是主进程改用 `process.resourcesPath`（该 API 仅主进程可用，恰好我们是主进程推导）。
- **extraResources 漏文件**：filter 配错会悄悄少文件 ⇒ 断言 4 是必经项，不通过不提交。
- **用户既有的 `~/.pi/agent/pidesktop-skills/` 副本**：若用户以前手动复制过这两个 skill，同名 slug 下**用户全局优先于内置**（升级不覆盖它）——这是刻意的：用户可以覆盖内置行为；本机是否已存在该副本会在实施时 `ls` 确认，存在则在迭代记录里提示用户可自行删除以回到内置版本。
- **dev 与打包的可见性差异**：dev 读仓库 `resources/skills`（改完热重启即生效），打包读安装目录副本（升级随安装包）——预期且与用户口径一致。
- **不改**权限口径、工具 schema/描述字节（无前缀缓存影响）；**不动** `.pidesktop-skills/` 项目级约定；skill 开关状态文件 `pidesktop-skill-state.json` 以 `SKILL.md` 绝对路径哈希为 key，路径变化会让这两个 skill 的开关回到默认（启用），无历史数据损失。
