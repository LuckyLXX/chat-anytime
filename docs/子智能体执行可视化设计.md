# 子智能体执行可视化 + 流式进度设计（A+B）

现状：`delegate_agent` 是同步阻塞工具，子会话事件在 `runChildToCompletion`（`src/main/subagent.ts:71-99`）里只取最终文本，其余全部丢弃；渲染端把它当通用工具节点渲染（原始 JSON 参数 + "运行中…"），状态栏显示英文原名，子代理 30 分钟执行期完全黑盒。另外 `sessionDirectories()`（`src/main/pi-runtime.ts:791-800`）会扫 `delegations/` 子目录，子会话以 goal 文本为标题混进侧边栏话题列表。

本设计两部分：**A 流式进度上报**（复用 Pi 现成的 `onUpdate` → `tool_execution_update` → 节流快照管道）、**B 结构化委派节点 + 完整记录查看 + 侧边栏去污染**。两者共享同一块地基：子代理事件 → `DelegationProgress` 结构。

## 非目标

- 不改 `delegate_agent` 工具 schema 与同步语义（真异步委派是独立立项的 C 方案）。
- 不改子代理的权限审批、30 分钟超时、abort、单层嵌套限制逻辑。
- 不改工具最终 `content`（模型可见的最终文本不变，前缀缓存友好）。
- 不给子会话补 tool-audit/checkpoint/hooks 扩展（现状维持，是否补齐单独决策）。

## 数据模型（`src/shared/protocol.ts`）

```ts
/** 子代理执行中的一步（对应子会话的一次工具调用）。 */
export interface DelegationStep {
  /** 子会话内的 toolCallId，用于完整记录查看时对齐。 */
  toolCallId: string;
  tool: string;
  /** 人类可读摘要（summarizeArgs 生成，如命令行、文件路径），≤120 字符。 */
  label: string;
  status: "running" | "completed" | "error";
  startedAt: number;
  completedAt?: number;
}

/** delegate_agent 工具执行的实时/最终进度，挂 ToolExecution.delegation。 */
export interface DelegationProgress {
  childSessionId: string;
  /** 子会话 JSONL 绝对路径（完整记录查看的入口凭据）。 */
  childSessionFile: string;
  /** 命中的自定义子智能体名（未命中时无此字段，走 role 渲染）。 */
  subagentName?: string;
  subagentColor?: string;
  role: DelegationRole;
  model: { provider: string; id: string };
  steps: DelegationStep[];
}

// ToolExecution 增加可选字段：
export interface ToolExecution {
  // ...现有字段不变
  delegation?: DelegationProgress;
}
```

`steps` 只存 label 不存 args/output（体积纪律）；上限 200 步，超出丢最老并在头部合成一条 `（已省略 N 个早期步骤）` 的占位步骤。

## A：进度上报链路

### 1. `subagent.ts` — DelegationTracker + onUpdate 转发

`runChildToCompletion` 重写为携带 tracker 的版本，`runDelegation` 把 `execute` 的第 4 参 `onUpdate`（`AgentToolUpdateCallback`，`pi-agent-core/dist/types.d.ts:349`，现被 `subagent.ts:214` 忽略）传进去：

- **事件白名单**（其余事件忽略，控制推送频率）：
  - `tool_execution_start` → 追加 step `{status:"running"}`，label 用 `summarizeArgs`（从 `runtime-permissions.ts` 导入，无 broker 依赖）；
  - `tool_execution_end` → 对应 step 置 `completed/error` + `completedAt`；
  - `message_end`（assistant）→ 现有 lastText 逻辑不变；
  - `agent_end`/`agent_settled` → 结束逻辑不变，另把所有 running 步骤封口为 error。
- **每次 tracker 变更后调用 `onUpdate`**，partialResult 同时带：
  - `content: [{type:"text", text: 累计日志行}]` — 每步一行（`✓ 执行命令 npm test · 3.2s` / `● 读取文件 src/...`）。这是 UI 兜底文本：不识别 delegation 的消费方（输出区、demo-api）也能看到活日志；结束时被最终文本替换。
  - `details: { delegation: tracker.snapshot() }` — 结构化数据。
- **最终结果**（`runDelegation` 返回值）：`content` 不变（最终助手文本）；`details` 在现有 `{goal, role, childSessionId, model}` 基础上补全为 `DelegationProgress`（含 subagentName/color/steps/childSessionFile，childSessionFile 取 `child.sessionManager.getSessionFile()`）——即结束时 details 从"元信息"升级为完整进度快照。
- **abort/timeout**：现有 reject 路径不变；tracker 已随最后事件封口，模型看到的是错误 toolResult，无 details（Pi 对抛错的工具不发我们的 details）——渲染端自动落回通用渲染，可接受。

### 2. `pi-runtime.ts` — 事件处理器扩展

- `tool_execution_update`（`pi-runtime.ts:1112`）：在现有 `current.output = textFromToolResult(...)` 之外，提取 `partialResult.details.delegation` 存入 `current.delegation`；若存在且是 delegate_agent，同步 `record.status = 子代理·${最后一步 label}`（该事件本就走 50ms 节流推送）。
- `tool_execution_end`（`pi-runtime.ts:1119`）：仿照 `patchFromToolResult` 加 `delegationFromToolResult`，把 `result.details.delegation` 盖进 execution（覆盖 partial 的最后一次快照，保证终态一致）。

协议层零新增消息类型：`ToolExecution` 挂新字段后，`RuntimeSnapshot.executions` 与分屏 `SessionPaneSnapshot.executions`（同类型，`protocol.ts:882/908`）自动携带，分屏免费受益；store 的 uuid-identity merge 是整对象替换，不受影响。

### 3. 缓存与体积纪律

- 进度只走工具结果通道（partial/最终 toolResult），**不碰系统提示词、不注入用户消息**——符合项目缓存优先原则。
- 传输截断复用现状：`truncateTransferredOutput` 只管 output；steps 的体积靠源头约束（200 步 × 短 label）。

## B：结构化委派节点

### 1. 基础标签（`src/shared/locale.ts`）

`toolLabels` 加 `delegate_agent: "委派子代理"`——状态栏「正在委派子代理」、时间线节点标题同时受益。

### 2. 参数摘要（`src/renderer/src/lib/tool-call-preview.ts`）

新增 `parseDelegateCallArgs(args)`：`{ goal首行（≤80字符）, role, subagent, modelId }`，供节点 summary 与"调用指令"区使用，替代裸 JSON。

### 3. 专属节点渲染（`src/renderer/src/ConversationPane.tsx`）

`ToolCallDetails` 内对 `call.name === "delegate_agent"` 分支（或抽 `DelegationCallSection` 组件）：

- **summary 行**：`委派子代理 · {subagentName 徽标（带 color 圆点）或 role 标签} · {goal 首行}`。
- **展开区新增「执行步骤」段**（在"调用指令"之前）：steps 列表逐行渲染，running=转圈、completed=✓、error=✗，行尾时长；数据源 `execution.delegation?.steps`。
- **输出区**：运行中显示累计日志（execution.output 即 partial 日志），结束显示最终文本——现有逻辑无需改。
- **「查看完整记录」按钮**：完成或运行中均可点（见下）；无 delegation 数据时整段不渲染（恢复中断的老会话落回通用视图）。
- 主题钩子：步骤列表容器沿用 `action-timeline-call-section` 结构；如需新钩子按 theme-guide 惯例补 `data-*`（预计不需要新公开钩子）。

### 4. 完整记录查看（只读弹窗）

- **命令**：`subagent.transcript { sessionId?, childSessionId, path }`。main 进程校验 `resolve(path)` 落在 `chatanytime-sessions/<agentId>/delegations/` 内（防目录逃逸，pathIsWithin 现成），逐行 parse JSONL 的 `message` entries（与 `session-history.ts` 的 `PersistedSessionEntry` 同构），经 `normalizeMessages`（`message-normalize.ts:105`）转 `ChatMessage[]` 返回。文件不存在（子代理尚无 assistant 输出，Pi `_persist` 的 hasAssistant 门槛）→ 友好错误「子代理尚未产生输出」。
- **渲染**：新组件 `DelegationTranscript`（放 `components/`），模态弹窗复用 settings-dialog 的 modal 样式模式；只读时间线（goal 气泡 + assistant 文本/思考 + 工具调用行，markdown 走 RichContent），无 composer/无再生成。
- **明确不做**：分屏打开转正（把子会话变成可交互主会话）语义重，留作后续可选项。

### 5. 侧边栏去污染（`src/main/pi-runtime.ts`）

`sessionDirectories()` 排除名为 `delegations` 的子目录（`checkpoints/*.jsonl` 已被 Pi 的 `buildSessionInfo` 首行校验自然过滤，无需处理）。`session.open` 的 `pathIsWithin` 校验保持不变（主动打开 delegation 文件仍允许，作为兜底入口）。

## 持久化与恢复

- Pi 会把 toolResult 的 `details` 原样写入父会话 JSONL（edit 的 patch 字段已依赖同一机制），`DelegationProgress` 随之持久化。
- `restoreToolExecutions`（`session-history.ts:91`）仿 `resultPatch` 加 `delegationFromDetails` 提取；被中断的执行（running→error 兜底分支）无 details，落回通用渲染。
