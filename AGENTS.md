# Project Conventions

- Keep Pi runtime objects behind `src/shared/protocol.ts`; the renderer consumes only the desktop protocol.
- Keep Electron main focused on native lifecycle, dialogs, persistence, and process supervision.
- Run Pi sessions and tools in the utility process, not in the renderer or main process.
- Pi is used only as the Agent runtime core. Its third-party extension access (loading, approval, binding, `pi-mcp-adapter`, subagent CLI shim) has been removed; do not reintroduce it. The only retained extension hooks are app-owned inline extensions: the permission gate and the tool-audit logger.
- Tool pipeline (`src/main/tool-audit.ts`, `src/main/tool-delta.ts`): every tool execution is appended to `chatanytime-sessions/<agentId>/tool-audit.jsonl` (best-effort), and MCP `callTool` is bounded by a 120s `AbortSignal` timeout. MCP tool additions/replacements hot-apply to the live session via `pi.registerTool()` on the captured `ExtensionAPI` (no session rebuild); removals still rebuild the session because Pi has no tool-removal API.
- Capability clusters extracted from `pi-runtime.ts` live in `src/main/runtime-*.ts` (todo-tools / skills / vision / permissions / mcp) as pure builders over explicit inputs; session lifecycle and command dispatch stay in `pi-runtime.ts`.
- Multi-session runtime: `pi-runtime.ts` keeps several sessions alive concurrently as `SessionRuntimeRecord`s (session/busy/status/executions/todos/permission-gate/customTools are per-record) in `liveSessions`, with `activeRuntime` selecting the record that feeds `RuntimeSnapshot`. Switching or creating a session parks the previous one (it keeps executing in the background and can be reactivated as the same live record); only same-session rebuilds, workspace removal, or idle-LRU eviction (`MAX_PARKED_SESSIONS`) dispose records. Sidebar status dots (`SessionSummary.runStatus`): running=yellow is live state; completed=green / failed=red are unseen-outcome notifications that clear on activation (`setTerminalRunStatus`/`activate`) and are never set for the session the user is already viewing. The sidebar session list is agent-scoped: `refreshSessions` lists only `chatanytime-sessions/<agentId>/` and stamps `currentSessionsAgentId`; `createSession`'s "list already loaded" shortcut (`sessionListReadyFor`) requires the cached list to belong to the current agent, so an agent switch always re-lists instead of showing the previous agent's topics.
- Self-built capabilities (MCP / Skill / Subagent / Todo) live in the utility process and are exposed to Pi as `customTools` (`ToolDefinition[]`) on `createAgentSession`, plus system-prompt injection for Skills. Do not run them in the renderer or main.
  - MCP: `src/main/mcp-client.ts` (`McpClientManager`) connects via `@modelcontextprotocol/sdk`; each tool becomes `mcp__<server>__<tool>`. Config in `.mcp.json` (project) / `mcp.json` (global).
  - Skill: `src/main/skill-catalog.ts` scans `pidesktop-skills/` (global) and `.pidesktop-skills/` (project) for `SKILL.md`; enable state in `pidesktop-skill-state.json`.
  - Subagent: `src/main/subagent.ts` `delegate_agent` creates a single-level child `AgentSession` under `chatanytime-sessions/<agentId>/delegations/`.
  - Question: `src/main/runtime-question-tool.ts` exposes `ask_question` as a customTool; its execution blocks on `QuestionBroker` until the user answers in the renderer's question panel (`question`/`question.dismiss` pushes, `question.resolve` command — mirrors the permission round trip). The panel is paged (one question at a time) and auto-marks the first option of a choice question as（推荐）— the tool description tells models to put their recommended option first; no protocol change carries the recommendation. Pending questions cancel on session dispose; the tool is never permission-gated.
  - Todo: dsh-style single-owner semantics (`src/main/runtime-todo-tools.ts`): the single `todo_write` customTool whole-list-replaces the store (`src/main/todo-store.ts` atomic JSON, session-scoped at `chatanytime-sessions/<agentId>/todos/<sessionId>.json`, rebuilt in `createSession` so the task panel follows the active session; reads normalize the legacy `{id,title,notes}` shape). Todo state reaches the model only through tool-call args appended at the conversation tail — never via per-turn system-prompt or user-message injection (either would break the provider prefix cache); the renderer's task panel is read-only and there are no `todo.*` user commands.
  - Memory: long-term memory per assistant, cross-session (`src/main/memory-store.ts` markdown topics + derived `MEMORY.md` index under `pidesktop-memory/<agentId>/`; store rebuilt in `createSession`). Same cache discipline as todo: the governance block + a byte-frozen index snapshot join `systemPromptOverride` once per session (global topics + topics bound to the record's workspace), and all later changes flow through `memory_*` tool calls at the conversation tail (`src/main/runtime-memory-tools.ts`: write/read/list/search/delete; never permission-gated; live `settings.memory.enabled` check, no session rebuild). Panel edits go over `memory.*` commands directly to the store (never through the model's context) and take effect in the next session's snapshot; the memory panel (`data-pane="memory-panel"`) is the user's governance view with the master toggle.
- Vision (`src/main/vision.ts` + `src/main/runtime-vision.ts`) is exposed as the `recognize_images` customTool injected per session. Attached images always stay in the session transcript (the user's bubble renders them and the JSONL persists them) regardless of model type; what changes for text-only conversation models is the transport: the shared `ModelRuntime` is wrapped once in `initialize` (`wrapModelRuntimeForVision`, `streamSimple` choke point — main sessions and subagents all pass through) so image parts are stripped from every LLM request whose model lacks image input, and the prompt text gets a trailing hint telling the model to call the tool (`visionHintText`; stripped again for display and regenerate matching via `stripVisionHint`). The tool recognizes the current turn's user images by scanning the live transcript at call time (`currentTurnUserImages` — everything since the last assistant message that concluded a previous run: Pi appends the tool-calling assistant message before executing the call, so mid-run `toolUse` steps do not end the scan; no inbox to stage or leak) through a user-selected multimodal model from the configured provider catalog (`settings.vision` `{ enabled, provider, model }`, resolved via the shared `ModelRuntime`); the model may also pass workspace image file paths (e.g. its own screenshots) via the `files` argument — workspace-bounded, size/MIME whitelisted — or a `prompt` argument carrying per-call recognition guidance that overrides the settings-level custom prompt (blank/absent falls back to it, then the built-in default). The tool is registered for every session but activated only when the conversation model lacks image input (recomputed at session creation or model switch via `reconcileVisionTool`/`switchSessionModel`, never mid-turn). Cache discipline: the tool schema is byte-stable (no dynamic state) and image counts/prompt hints live only in the trailing user text.
- Preserve the permission boundary for bash, writes, and paths outside the selected workspace. One deliberate carve-out: directory links (Windows junctions / symlinks to directories) placed inside a workspace are user-created entry points (git checkouts on Windows produce no links by default), so `workspace-preview.ts` follows them for tree browsing, preview, and for renaming/deleting the link node itself; writes/creates through them stay blocked, and file symlinks escaping the workspace are still rejected everywhere.
- Keep provider secrets process-local unless a dedicated secure-storage design is added.
- Render complete HTML/SVG documents only inside the sandboxed Artifact preview.
- Theme system: custom theme CSS is applied verbatim (only legacy alias mapping and mode-selector rescoping, `src/renderer/src/lib/theme-presets.ts`). The stable theme-hook contract for structural themes is: `data-pane` on major regions (sidebar / topbar / work-area / conversation / timeline / composer / task-panel / memory-panel / preview / terminal / question-panel / settings-dialog / permission-dialog), `data-role` on message articles (user / assistant / extension), `data-control` on key controls (new-session / settings / workspace-open / preview-toggle / task-panel-toggle / memory-toggle / send / stop / attach / access-mode / model-select / thinking-select / copy / edit / regenerate / share), boolean `data-ui-*` state attributes on `<html>` (settings-open / workspace-open / chat-empty / generating / preview-open / permission-pending / question-pending), and viewport decoration layers declared as `--pi-layer-<name>` (above wallpaper, below UI) / `--pi-overlay-<name>` (above UI, below dialogs) background-shorthand variables that the shell renders as `pointer-events:none` divs (`collectThemeLayers`). These attributes and variables are public theme API — do not rename or remove them without a migration note. Themes own every color token; the only renderer-side override is the wallpaper-opacity slider (`appearance.wallpaperOpacity`, light/dark). Theme assets may be image or font data URLs. Authoring guide: `docs/theme-guide.md`; the `pidesktop-theme-creator` skill's checker validates hook names.
- User terminal (`src/main/terminal-pty.ts`): preview-tab terminals are real PTYs (node-pty) hosted in the main process and rendered with xterm.js in the sandboxed renderer, mirroring the BrowserPreview IPC shape (`terminal:command` invoke + per-terminal `terminal:data:<id>` push). The PTY outlives tab switches (main-process scrollback replay on `create` reconnect); closing the tab, changing the workspace, or quitting kills it. It is user-typed input and bypasses the agent permission gate — keep it separate from the Pi `bash` tool pipeline in the utility process.
- Prefer focused changes. Do not copy ChatAnyTime plugin runtime code into this project.
- Before handoff, run `npm test`, `npm run build`, and a packaged Windows smoke test when packaging behavior changes.
